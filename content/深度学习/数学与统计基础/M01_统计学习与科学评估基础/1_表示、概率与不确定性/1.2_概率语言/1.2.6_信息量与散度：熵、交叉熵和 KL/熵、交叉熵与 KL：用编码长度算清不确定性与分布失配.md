# 熵、交叉熵与 KL：用编码长度算清不确定性与分布失配

> 视频来源：[A Short Introduction to Entropy, Cross-Entropy and KL-Divergence](https://www.youtube.com/watch?v=ErfnhcEV1O8)（YouTube · Aurélien Géron）｜时长约 11 分钟
> 导读：一支把三个概念串成一条链的短片——先由"不确定性减半"定义信息量，再由平均信息量定义熵，把交叉熵解释成"用错码表的平均码长"，最后用"交叉熵减熵"得到 KL。全片只用天气与分类器两个例子，数字都可手算。

## 本讲要解决的核心问题（SCQA）

**背景**：训练分类器时，损失函数几乎默认写成交叉熵；论文里还常出现 KL 散度，说它"衡量两个分布差多远"。

**冲突**：这两个量都写成 $-\sum p \log q$ 的样子，长得几乎一样；而"差多远"听起来像距离，距离应当对称，可 KL 偏偏不是。若只记住公式，就分不清哪一部分在量"这件事本身有多难猜"，哪一部分在量"我们的模型猜偏了多少"。

**疑问**：熵、交叉熵、KL 三者到底是什么关系？为什么交叉熵能当损失函数？KL 为什么不能当对称距离？

**回答（中心思想）**：把概率分布想成"编码方案"，三个量就有了统一的读法——**熵是这套分布自身的不确定性，也就是最优编码的平均码长；交叉熵是用另一套分布设计的码去编码真实数据时的平均码长；KL 是两者之差，即因为用错码表而白白浪费的比特数**。所以交叉熵 $=$ 熵 $+$ KL，KL 只可能非负，且方向不同结果不同。

## 一、信息量：把不确定性砍掉一半，就是 1 bit

这套语言来自香农 1948 年的《通信的数学理论》：目标是把消息从发送方可靠、高效地传到接收方 [【跳转到 00:17】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=17)。数字时代消息由比特组成，但**比特数不等于信息量**：有些比特是冗余的，有些是纠错用的。

![香农与 1948 年《通信的数学理论》：信息论要解决的是"高效可靠地传输消息"，而不是"消息里有多少个比特"](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00042.webp)

在香农的框架里，**传输 1 bit 信息的含义是：把接收方的不确定性缩小为原来的二分之一** [【跳转到 01:07】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=67)。

- 天气完全随机，晴/雨各 50%。气象站告诉你"明天雨"，两个等可能选项变成一个，不确定性除以 2，所以你收到 **1 bit** 有用信息。
- 就算它用 5 个字符、每字符 1 字节来编码这句话，实际发了 40 bit，**有用信息仍然只有 1 bit** [【跳转到 01:12】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=72)。
- 若天气有 8 种等可能状态，告诉你结果就把不确定性除以 8 $=2^3$，于是你收到 **3 bit** [【跳转到 01:37】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=97)。

![8 种等可能的天气状态：不确定性除以 8 等于除以 2 的三次方，所以是 3 bit 信息](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00122.webp)

一般地，若事件概率为 $p$，不确定性缩小的倍数就是 $1/p$，取以 2 为底的对数即得信息量：

$$
I(x) = \log_2 \frac{1}{p(x)} = -\log_2 p(x)
$$

### 1.1 概率不等时，信息量按事件分别算

设晴 75%、雨 25% [【跳转到 02:02】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=122)：

- 若明天是雨，不确定性除以 $1/0.25=4=2^2$，得到 **2 bit**；
- 若明天是晴，不确定性只除以 $1/0.75\approx1.33$，只有约 **0.41 bit** [【跳转到 02:27】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=147)。

注意这里的"比特"可以是小数：0.41 bit 不是说发了半个比特，而是说这条消息带来的不确定性削减量不到一次"减半"。

## 二、熵：平均每天能收到多少信息

既然不同结果带来的信息量不同，自然的问法是"**平均**能收到多少"。按概率加权：

$$
0.75 \times 0.41 + 0.25 \times 2 = 0.81 \text{ bit}
$$

![把两种天气的信息量按概率加权：0.75×0.41 + 0.25×2 = 0.81 bit，这就是熵](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00197.webp)

这个加权平均就是**熵（entropy）** [【跳转到 03:17】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=197)：

$$
H(p) = -\sum_i p_i \log_2 p_i
$$

它衡量的是"从分布 $p$ 里抽一个样本、得知结果时平均获得多少信息"，也就是**这个分布本身有多难猜** [【跳转到 03:42】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=222)：

- 沙漠里天天晴，气象站说什么你早就知道，熵接近 0；
- 天气变化越大，熵越大。

到这里要记住一条边界：**熵只由真实分布 $p$ 决定，和你怎么编码、模型怎么预测都无关**。它是"这件事的下限"。

---

## 三、交叉熵：用错码表时，平均要发多长

现在换个角度：熵是"平均信息量"，而实际通信中你真正付出的是**平均消息长度**。这两者什么时候相等？

先看一个"码表刚好配得上分布"的例子：8 种天气各用 3 bit 编码，每条消息固定 3 bit，平均长度就是 3 bit——这也就是**交叉熵** [【跳转到 04:32】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=272)。

![8 种天气各分配一个 3 bit 码字：每条消息都是 3 bit，平均消息长度（交叉熵）就是 3 bit](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00297.webp)

但真实分布并不均匀。假设某地 8 种天气的概率是 35%、35%、10%、10%、4%、4%、1%、1%，算出的熵只有 **2.23 bit** [【跳转到 04:57】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=297)。

![这个偏晴的分布熵只有 2.23 bit：35%×log₂(1/0.35) 一路加到 1% 的项，加权和为 2.23](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00322.webp)

也就是说：**平均发 3 bit，收件人只得到 2.23 bit 有用信息**。浪费来自码表——给常见天气和罕见天气分配了同样长的码。

### 3.1 换一套更贴合的码

于是改成：最晴的两种天气用 2 bit，多云两种用 3 bit，小雨中雨用 4 bit，大雨雷暴用 5 bit。这套码仍然无歧义（例如 `011100` 只能读成"partly sunny + light rain"），平均长度降到 **2.42 bit** [【跳转到 05:22】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=322)。

![按概率长短分配码字后的码表：常见天气 2 bit、罕见天气 5 bit，平均码长降到 2.42 bit，但仍高于熵 2.23](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00347.webp)

比 3 bit 好，但仍高于 2.23 bit 的熵——因为整数比特的码字无法完全贴合真实概率。

### 3.2 把同一套码搬到别处：交叉熵飙升

现在把**同一套码表**用在天气相反的地方（多雨）。重算平均码长，得到 **4.58 bit** [【跳转到 06:12】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=372)：

$$
1\%\times2 + 1\%\times2 + 4\%\times3 + 4\%\times3 + 10\%\times4 + 10\%\times4 + 35\%\times5 + 35\%\times5 = 4.58
$$

![同一套"偏晴"码表用在多雨地区：35% 的天气要发 5 bit，加权平均涨到 4.58 bit，约为熵的两倍](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00422.webp)

平均发 4.58 bit，真正有用的仍只有 2.23 bit，浪费了一倍多。原因很直白：**码表隐含地假设了一个分布**。给某种天气分配 2 bit 码，等于宣称它平均每 4 天出现一次（$2^2=4$），即预测概率 25% [【跳转到 06:37】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=397)。所以这套码对应的预测分布 $q$ 与真实分布 $p$ 差得很远。

![把码表翻译成概率：2 bit 码字等于预测 1/2² = 25%，3 bit 等于 12.5%，5 bit 等于 3.125%；蓝色是真实分布 p，绿色是码表隐含的预测分布 q](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00447.webp)

### 3.3 交叉熵的公式

于是交叉熵可以写成同时含 $p$ 与 $q$ 的形式 [【跳转到 07:02】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=422)：

$$
H(p, q) = -\sum_i p_i \log_2 q_i
$$

![交叉熵的公式：权重是真实概率 p，取对数的却是预测概率 q（等价于码长）](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00472.webp)

和熵的公式只差一处：**熵对真实概率取对数，交叉熵对预测概率取对数**。这个差别正是全部信息的来源：

- 权重永远是 $p$——因为现实按真实频率发生；
- 取对数的是 $q$——因为码长由你设计的码表决定。

## 四、KL：交叉熵比熵多出来的那部分

如果预测完美（$q=p$），交叉熵就等于熵；如果两个分布不同，交叉熵就会比熵大出若干比特 [【跳转到 07:27】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=447)。这个差值有专门的名字：**相对熵**，更常见的叫法是 **KL 散度（Kullback-Leibler divergence）**：

$$
D_{\mathrm{KL}}(p \,\|\, q) = H(p, q) - H(p)
$$

![KL 散度的定义式：D_KL(p‖q) = H(p,q) − H(p)，即"交叉熵减熵"](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00497.webp)

在上面的例子里：交叉熵 4.58 bit，熵 2.23 bit，所以 KL 为 **2.35 bit** [【跳转到 08:17】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=497)。

三个量由此各就各位：

| 量 | 回答的问题 | 由谁决定 |
| --- | --- | --- |
| 熵 $H(p)$ | 这件事本身平均有多难猜？最优编码要多少比特？ | 只有真实分布 $p$ |
| 交叉熵 $H(p,q)$ | 用我设计的码（模型 $q$）去编码真实数据，平均要多少比特？ | $p$ 与 $q$ 共同决定 |
| KL $D_{\mathrm{KL}}(p\|q)$ | 因为码表不对，平均白扔了多少比特？ | $p$ 与 $q$ 的失配程度 |

### 4.1 为什么不能把 KL 当对称距离

公式里 $p$ 在权重位置、$q$ 在对数位置，两者角色完全不同，交换之后结果一般会变。这一点在另一篇《交叉熵为什么以熵为下限》里有专门的二值分布反例（$H(p,q)=1$ bit 而 $H(q,p)\approx1.74$ bit）。

所以正确的读法是：**KL 有方向**。$D_{\mathrm{KL}}(p\|q)$ 问的是"用 $q$ 去近似 $p$ 代价多大"，反过来问的是另一个问题。它满足非负性（$D_{\mathrm{KL}}\ge 0$，当且仅当 $p=q$ 时取 0），但不满足对称性与三角不等式，因此不是距离。

## 五、落到机器学习：交叉熵为什么能当损失

把上面的角色对调一下就是分类任务 [【跳转到 08:47】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=527)：

- **真实分布 $p$**：有监督学习里我们已知标签。一张小熊猫图片，7 个类别中"小熊猫"概率 100%，其余 0%；
- **预测分布 $q$**：分类器对 7 个类别各输出一个概率，例如猫 2%、狗 30%、狐狸 45%、牛 0%、小熊猫 25%、熊 5%、海豚 0%。

![分类器输出 7 类概率，真实标签是小熊猫（100%）：交叉熵就是拿真实分布 p 当权重、对预测概率 q 取负对数](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00527.webp)

用两者的交叉熵当损失，就是**交叉熵损失**，也叫对数损失（log loss）。实践中通常换成自然对数，与以 2 为底只差一个常数因子 $\ln 2$，不影响最优点的位置 [【跳转到 09:12】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=552)。

当标签是 one-hot 时，求和里只剩真实类别那一项 [【跳转到 09:37】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=577)：

$$
H(p,q) = -\log q_{\text{真实类别}}
$$

![one-hot 标签下交叉熵坍缩成 −log q(真实类)：此例中 q(小熊猫)=25%，损失为 −log 0.25](assets/熵、交叉熵与%20KL：用编码长度算清不确定性与分布失配/00577.webp)

这个式子的两个端点值得记住：

- 预测概率接近 0 时，$-\log q$ 急剧增大——**自信地答错，罚得极重**；
- 预测概率接近 1 时，损失趋近真实分布的熵；one-hot 的熵为 0，所以损失趋近 0 [【跳转到 10:02】](https://www.youtube.com/watch?v=ErfnhcEV1O8&t=602)。

这也解释了为什么交叉熵比均方误差更适合概率输出：它衡量的不是"数值差多少"，而是"把概率质量放错位置要付多少比特"。

## 六、边界与常见误读

- **比特与 nat**：以 2 为底得到 bit，以 $e$ 为底得到 nat，两者只差常数倍。讨论"信息量"时用 bit 更直观，写损失函数时用自然对数更好求导。
- **熵不是模型指标**：熵只描述真实分布 $p$，模型好坏体现在交叉熵与 KL 上。把"熵高"当成"模型差"是偷换了对象。
- **KL 不对称**：$D_{\mathrm{KL}}(p\|q)\neq D_{\mathrm{KL}}(q\|p)$，它衡量的是"用 $q$ 编码 $p$"的额外代价，有明确方向。
- **交叉熵损失不是唯一的概率损失**：这里只说明它在编码意义下的合理性；与最大似然的关系、以及 softmax 如何把 logits 变成 $q$，分别见 1.2.5 与 2.1.3。
- **本讲的数字都是玩具例子**：真实模型的词表有十万量级，逐 token 的交叉熵与困惑度的换算见 M02 序列建模相关小节。

## 小结

- **信息量** $-\log_2 p$：概率越小，得知结果时不确定性削减越多，信息量越大；1 bit 对应"不确定性减半"。
- **熵** $H(p)=-\sum p_i\log_2 p_i$：平均信息量，也是最优编码的平均码长，只由真实分布决定。
- **交叉熵** $H(p,q)=-\sum p_i\log_2 q_i$：用 $q$ 设计的码去编码服从 $p$ 的数据时的平均码长；$q=p$ 时退化为熵。
- **KL** $D_{\mathrm{KL}}(p\|q)=H(p,q)-H(p)$：因为码表不对而浪费的比特数，非负、有方向、不对称。
- **三个量的关系**：交叉熵 $=$ 熵 $+$ KL；熵是下限，KL 是超出下限的部分。
- **分类损失**：one-hot 标签下交叉熵坍缩为 $-\log q_{\text{真实类}}$，把真实类别的概率压低会被重罚。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 比特（bit） | 信息量单位；收到 1 bit 意味着不确定性缩小为原来的一半 |
| 信息量（information content） | $-\log_2 p(x)$，单个事件发生时所提供的信息 |
| 熵（entropy） | 分布的平均信息量，也是该分布下最优编码的平均码长 |
| 交叉熵（cross-entropy） | 用预测分布 $q$ 的码长去编码真实分布 $p$ 的数据时的平均码长 |
| KL 散度（相对熵） | 交叉熵减熵，衡量用 $q$ 近似 $p$ 时多付出的比特数；非负但不对称 |
| one-hot 编码 | 只有一个类别为 1、其余为 0 的标签分布 |
| 交叉熵损失 / 对数损失 | 以交叉熵为目标的分类损失；one-hot 下等于 $-\log q_{\text{真实类}}$ |
| nat | 以自然对数为底的信息量单位，与 bit 相差 $\ln 2$ 倍 |
