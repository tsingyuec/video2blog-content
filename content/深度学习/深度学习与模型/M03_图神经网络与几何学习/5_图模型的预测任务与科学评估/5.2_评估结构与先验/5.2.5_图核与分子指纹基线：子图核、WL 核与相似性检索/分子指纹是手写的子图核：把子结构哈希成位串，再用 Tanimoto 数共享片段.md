# 分子指纹是手写的子图核：把子结构哈希成位串，再用 Tanimoto 数共享片段

> 视频来源：[rdkit 化合物编码方式与化学相似性计算](https://www.bilibili.com/video/BV1DW4y1o7bQ/)（B 站 · 曹博AIDD）｜时长约 40 分钟
> 简要导读：这支课把"分子怎么变成计算机能算的东西"讲成一条流水线：SMILES/InChI 等字符串 → 分子指纹 → 相似系数。本文按这条流水线展开，第 5 章把它翻译成图核的语言（子图核、WL 核），第 8 章给出适用条件与局限。视频全程没有使用"核"这个词，凡属本文的对应说明都会明确标出。

## 本讲要解决的核心问题（SCQA）

**背景**：做分子性质预测，今天默认的做法是建一张分子图、跑消息传递 GNN。但在 GNN 之前，化学信息学已经用"分子指纹 + 相似系数"做了几十年：把分子压成一条 0/1 位串，再数两条位串有多少位相同。

**冲突**：这条老流水线看起来粗糙——它把整个分子压成几百到几千个比特，丢掉了大量结构。可它在虚拟筛选、相似性检索、性质预测里一直有人用，而且常常是论文里必须交代的基线。粗糙的表示为什么还能用？它到底丢掉了什么、保留了什么？

**疑问**：一张分子图怎样变成一条位串？两条位串怎样变成一个相似度？这套做法与图核是什么关系？在什么条件下它还够用，什么条件下必须换成 GNN 或三维模型？

**回答（中心思想）**：**分子指纹是一条"枚举子结构 → 哈希成位 → 数共享位"的流水线；把它写成核，就是子图核或 WL 核的一个定长哈希版本，而 Tanimoto 系数是它的归一化。** 因此它继承了图核的全部优点（无需训练、可解释到子结构、检索极快），也继承了全部盲区（只看得见二维子结构、看不见构象与长程耦合、位冲突与覆盖不足会静默丢信息）。它适用的条件可以归结为三条：相似分子确实有相似性质、性质由二维子结构决定、目标子结构落在指纹的覆盖范围内。

## 一、先有"分子 → 位串 → 相似度"这条流水线

**结论：指纹不是凭空的表示技巧，它是"分子比较"这个任务的工程解——因为直接比分子很难，比位串很容易。**

视频开场先按维度把分子表示分成三层。[【跳转到 00:20】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=20)

- **一维**：SMILES 这类字符串，或者分子指纹；
- **二维**：分子图、路径、片段、原子环境，以及二维分子描述符；
- **三维**：在图的基础上加上立体信息，用构象表示。

同一页幻灯片还给了两条对建模很关键的判断：一维的**全局描述符**（溶解度、logP、分子量、熔点）只有一个值代表整个分子，"通常不包含足够的信息来应用于机器学习"，但"可以添加到二维指纹中以改进 ML 的分子编码"；而三维描述符"由于分子的灵活性（分子的'正确'构象是什么？），不如 2D 表示稳健"。[【跳转到 00:20】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=20) 这两句话提前划定了指纹的位置：它是二维层面的、分子各部分的详细表示，而不是一个全局标量。

![一维、二维、三维分子描述符的对照：全局描述符信息不足，三维描述符受构象灵活性拖累，二维指纹是相似性搜索与机器学习的主力](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/00020.webp)

那为什么不直接用 SMILES 比较？视频给的理由很直接：**比较分子是很难的，比较比特串却很容易，分子之间的比较必须以可量化的方式进行。** 指纹把分子结构转化成计算机可处理的二进制或数字串，每个位对应一个预先定义的分子特征或环境，"1"表示存在、"0"表示不存在。[【跳转到 13:47】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=827)

![分子指纹的定义：以位串、位向量或数组编码化学与分子特征，把分子结构转成可比较、可搜索的二进制串](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/00827.webp)

这一步之后，"两个分子有多像"就变成了"两条位串有多少位对得上"。视频的说法是：字符串形式（比如 SMILES）比较起来其实很难，但表示成位串之后，"只要一一对应地看哪个位相同、哪个位不同"，就很容易拿到它们的相同与不同点。[【跳转到 15:02】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=902)

## 二、结构指纹：每个比特位问一个"有没有这个子结构"的问题

**结论：结构指纹把"哪些子结构算特征"这件事提前写死；生成指纹就是逐条回答"这个分子有没有这个子结构"，答案填 0 或 1。**

结构指纹（substructure key-based fingerprint）的规则只有两步：先给定一张结构列表，里面是若干已经定义好的子结构或分子特征；再判断某个分子有没有这些子结构，有就置 1，没有就置 0。[【跳转到 16:54】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1014) 位宽由子结构数量决定，每个比特位与"某个给定特征存在或不存在"一一对应。

最常用的代表是 **MACCS**（Molecular Access System fingerprints）。它采用 SMARTS 编码的子结构（SMARTS 是一种描述子结构模式的字符串语言，可以理解为带通配符的 SMILES），按子结构种类数量有两个变种：166 位和 960 位；960 位太大、处理不易，常用的是 166 位，它"长度相对较小，但涵盖了药物发现和虚拟筛选时的大多数感兴趣的化学特征"。[【跳转到 18:09】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1089)

![结构指纹与 MACCS：位宽由子结构列表决定，每个比特位对应一个给定子结构的存在与否，166 位是最常用的版本](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01014.webp)

视频用一张 10 位的示意图把这个过程走了一遍：每个位置编码一个子结构，分子里出现了 3 个位置所代表的子结构（图中用红圈圈出的苯环、羧基、氨基），这 3 位标 1，其余标 0。[【跳转到 19:54】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1194) 幻灯片右侧同时给出了 RDKit 的实现入口 `MACCSkeys.GenMACCSKeys(mol)`，说明这不是概念演示，而是可以直接调用的编码器。

![10 位结构指纹的生成示例：分子中出现的三个子结构把对应位置置 1，其余置 0，右侧是 RDKit 的 MACCS 调用](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01194.webp)

结构指纹的局限也写在同一页上：**如果分子主要由指纹的子结构组成，它最有用；当分子包含指纹的子结构不多时，它就不那么有用，因为"它们的特征将不被分子指纹所表示"。**[【跳转到 18:09】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1089) 这句话是后面"覆盖范围"这条适用条件的来源：结构指纹只认识自己字典里的东西，字典之外的结构一律记为 0，看起来像"没有特征"，而不是"未知特征"。

## 三、哈希指纹：不预定义片段库，枚举后压进固定长度

**结论：哈希指纹把"哪些片段算特征"从人工字典换成枚举——把分子里所有不超过特定大小的片段都找出来，用哈希函数映射到固定范围的位位置上。**

结构指纹的替代方法是哈希指纹，它与结构键相反，"不需要预定义的片段库"。做法是枚举分子中所有不大于特定大小的可能片段，再用哈希函数把这些片段转换为数值，这些数值指示哈希指纹中的位位置。[【跳转到 20:37】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1237)

![哈希指纹的定义：不需要预定义片段库，枚举不大于特定大小的片段后哈希成数值，数值指示位位置；固定范围必然带来位冲突](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01237.webp)

哈希函数的作用是"将任意大小的数据映射到固定大小的值"。代价立刻出现：一个分子枚举出的片段可能非常多，把它们散列到固定范围里，"不可避免地会导致位冲突（bit collision）"——不同的片段被转换成相同的数值、落到相同的位位置。因此**片段和指纹位之间没有一一对应的关系**，这一点与结构指纹相反。[【跳转到 20:37】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1237)

按枚举片段的方式，哈希指纹再分两支：

- **基于拓扑或路径的指纹**：从一个原子出发，沿"指定数量键"的路径收集所有分子片段，再对每条路径做哈希。它适用于任意分子，长度可调，可用于快速的子结构搜索与分子过滤；代表是 **Daylight 指纹**，由多达 2048 个比特位组成，编码分子达到给定长度的所有可能连接路径。[【跳转到 21:27】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1287)
- **圆形指纹**：不在分子中找路径，而是记录每个原子出发、指定半径内的环境（下一章展开）。

![基于拓扑或路径的哈希指纹：逐条路径哈希成位，Daylight 用 2048 位编码给定长度内的所有连接路径；哈希意味着从位出发无法反推结构](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01287.webp)

视频用一张 10 位的路径指纹图演示了位冲突：从被圈出的起始原子出发，键长为 5 的路径生成两个片段，对应两位；键长为 4 时又有一位；图中出现两处"多个片段指向同一个比特位并引发比特位减少"的冲突。幻灯片还强调，图中只画了从单个起始原子出发的片段，完整指纹要对分子中的每个原子重复这个过程。[【跳转到 23:27】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1407)

![路径指纹的 10 位示例：不同长度的路径映射到不同位，箭头标出两处位冲突；完整指纹要对每个原子重复](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01407.webp)

这里有一个对"可解释性"很关键的句子：**哈希指纹意味着从比特位出发无法追踪到结构特征。** 同样的比特位可以对应不同的结构特征，这就是位冲突。[【跳转到 21:27】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1287) 结构指纹的每一位还能翻译回一条 SMARTS 子结构，哈希指纹的某一位却不能——它只告诉你"这类片段出现过"，不告诉你是哪一个。

## 四、圆形指纹与 Morgan：把"半径内的环境"迭代地哈希

**结论：圆形指纹以每个原子为中心，把半径 1、2……内的原子环境逐层记录下来再哈希；Morgan 是这一类里最常用的实现，它更适合"整体结构相似性搜索"，不适合子结构查询。**

圆形指纹（circular fingerprint）也是一种哈希的拓扑指纹，区别在于：**不是在分子中寻找路径，而是记录每个从原子出发直到指定半径内的环境。**[【跳转到 25:07】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1507) 幻灯片用一张苯环衍生物的图展示了"层"的概念：以某个重原子为中心，Layer 0 是它自身的原子类型（芳香碳，sp²），Layer 1 是半径 1 内看到的邻居类型，Layer 2 再往外扩一圈，把氮、氧及其轨道类型都纳入进来。

![圆形指纹的半径分层：以重原子为中心，Layer 0/1/2 依次记录半径内的原子类型与官能团环境](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01507.webp)

正因为记录的是"环境"而不是"片段本身"，视频明确说这类指纹**不适用于子结构查询**（相同的片段可能处在不同环境里），但**广泛用于完整结构的相似性搜索**。[【跳转到 25:32】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1532) 这是一个容易混淆的分工：路径指纹适合"找含有某个子结构的分子"，圆形指纹适合"找整体长得像的分子"。

最常用的圆形指纹是**摩根分子指纹**（Morgan fingerprints）。它是对标准摩根算法改造后得到的拓扑型指纹，视频列出的优点是：计算速度快、没有经过预定义（可以表示无穷多种不同的分子特征）、可以包含手性信息（手性指镜像不能重合的立体差异，比如 L 型和 D 型氨基酸）、指纹中的每个元素代表一种特定子结构、可以方便地进行分析和解释、可以根据需要修改。[【跳转到 26:18】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1578)

它的设计初衷是"用于搜索与活性相关的分子特征，而非子结构搜索"，此外也用于相似性搜索、聚类、虚拟筛选。生成方式是"设定一个从特定原子出发的半径，统计这个半径以内的部分分子结构的数量"；设定 radius 和 bit 的数量，就得到不同长度、不同粗细的指纹。幻灯片上的代码是 `AllChem.GetMorganFingerprintAsBitVect(mol, 2, 2048)`——半径 2、2048 位。[【跳转到 26:18】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1578)

![Morgan 指纹：半径内环境计数后哈希成位，代码里用 radius=2、2048 位；优点是快、无需预定义、可含手性](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01578.webp)

> 术语对照：RDKit 的 Morgan 指纹就是通常所说的 **ECFP**（Extended-Connectivity Fingerprint）系列；视频只用了"摩根指纹/圆形指纹"这两个名字，没有出现 ECFP 这个缩写。

## 五、把这条流水线翻译成图核：子图核与 WL 核

**结论：视频讲的两条流水线，正好对应图核里的两个经典构造——结构指纹对应子图核（数共享子结构），圆形指纹对应 WL 核（数共享邻域标签）；Tanimoto 则是这个核的归一化形式。**

先说清"核"是什么。**核（kernel）是一个相似度函数 $K(G,G')$，它不必显式写出特征，只要能在两张图之间给出一个数。** 图核的通用做法是选一组子结构模式，把每张图映射成"每种模式出现了几次"的向量，再取内积（对应分量相乘后求和）：

$$
K_{\text{sub}}(G,G') = \langle \phi(G), \phi(G') \rangle = \sum_{H \in \mathcal{H}} \phi_G(H)\,\phi_{G'}(H)
$$

其中 $\mathcal{H}$ 是模式集合，$\phi_G(H)$ 是模式 $H$ 在图 $G$ 中出现的次数。这就是**子图核**：两张图共享的子结构越多，核值越大。

把视频的结构指纹代进这个式子：$\mathcal{H}$ 就是 MACCS 那 166 条 SMARTS 子结构，$\phi_G(H)$ 退化成 0/1（出现或不出现），内积就是"两条位串共同为 1 的位数"。视频说的"判断分子有没有这些子结构、用 0/1 表示、最后形成位串"，与子图核的特征映射是同一件事，只是把计数换成了存在性。[【跳转到 17:19】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1039)

**WL 核**换一组模式：它不预先指定子结构，而是让模式随迭代长出来。做法是给每个节点一个初始标签，然后反复用"自身标签 + 邻居标签的多重集"生成新标签（这一步就是颜色细化），每一轮统计一次标签直方图，最后把各轮的直方图相似度加起来：

$$
K_{\text{WL}}(G,G') = \sum_{h=0}^{H} \langle \phi_h(G), \phi_h(G') \rangle
$$

其中 $\phi_h(G)$ 是第 $h$ 轮迭代后图 $G$ 的标签直方图。第 0 轮看原子本身，第 1 轮看直接邻居，第 2 轮看两跳环境——**这正是视频里圆形指纹的 Layer 0、Layer 1、Layer 2。** 区别只在实现：WL 核保留每一轮的完整标签直方图，圆形指纹把每一层的环境哈希进固定长度的位串，并用位冲突换空间。[【跳转到 25:07】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1507)

把三者放在一张表里，关系就清楚了：

| 构造 | 模式从哪来 | 特征长什么样 | 视频里的对应物 |
| --- | --- | --- | --- |
| 子图核 | 人工指定一组子结构 | 每种子结构的出现次数 | 结构指纹（MACCS，0/1 版） |
| WL 核 | 迭代生成邻域标签 | 每轮标签的直方图 | 圆形指纹（Morgan，哈希定长版） |
| 指纹 | 上面两者之一 | 固定长度 0/1 位串 | 视频讲的整条编码流水线 |

需要说明的是：**视频没有使用"核"这个说法，也没有给出上面两个公式**；这是本文把它的两条流水线放回图核语言后的对应。做这个对应的用处是：一旦认出"指纹 = 哈希过的图核"，就能直接借用图核的适用条件与失效模式，而不必把指纹当成一套独立的经验技巧。

与 [2.3.1 图表达能力](../../../2_图上的学习机制/2.3_图表示能力、位置编码与异质图/2.3.1_图表达能力：同构判别、WL%20视角与消息传递边界/两个五边形与两个六边形分不开：1-WL%20颜色迭代与消息传递的分辨力上限.md) 的分工在这里：那一节用 WL 的**分辨力上限**去界定消息传递 GNN 能区分多细的结构；本节用 WL 的**特征映射**去构造一个不需要训练的非神经基线。同一个颜色细化过程，一边当"尺子"，一边当"特征提取器"，不重复表达力证明。

## 六、两个分子怎么变成一个数：列联表与三个系数

**结论：所有基于指纹的相似系数都只用到四个计数——A 独有、B 独有、共有、都没有；Tanimoto 和 Dice 只用前三个，cosine 换一种归一化。**

视频把两个分子的位串逐位比对，统计成一张列联表：$a$ 是只有 A 为 1 的位数，$b$ 是只有 B 为 1 的位数，$c$ 是两者都为 1 的位数，$d$ 是两者都为 0 的位数。[【跳转到 31:11】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1871)

![两个指纹的列联表与各种相似系数：a、b、c、d 四个计数决定了 Tanimoto、Dice、cosine 等度量的取值](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01871.webp)

最常用的是 **Tanimoto 系数**（也叫 Jaccard 系数）：

$$
T(A,B) = \frac{c}{a+b-c} = \frac{\lvert A \cap B \rvert}{\lvert A \rvert + \lvert B \rvert - \lvert A \cap B \rvert}
$$

**Dice 系数**只差一个分母：

$$
D(A,B) = \frac{2c}{a+b}
$$

**cosine 系数**则把分母换成两个向量的模长之积，$c / \sqrt{(a+c)(b+c)}$。视频还提到欧几里得距离作为可选项，但"最常用的就是 Tanimoto 这个系数"。[【跳转到 30:07】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1807)

![Tanimoto 与 Dice 的公式对照：两者分子相同、分母不同，因此 Dice 的取值通常不低于 Tanimoto](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01958.webp)

两者的大小关系可以算出来。因为 $a \ge c$、$b \ge c$，所以 $a+b-2c = (a-c)+(b-c) \ge 0$；两边同乘 $c$ 并整理，就得到

$$
\frac{c}{a+b-c} \le \frac{2c}{a+b}
$$

即 Dice 通常比 Tanimoto 给出更高的值。视频的提醒是：相似性度量"通常考虑任一指纹中存在的正位的数量，以及两者间共有的比特位的数量"，分母不同就会导致数值不可直接比较。[【跳转到 32:38】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1958)

这里还有一个容易被忽略的性质：$d$（两者都为 0 的位数）**不出现在 Tanimoto 和 Dice 的公式里**。指纹是定长的，而一个分子命中的子结构只占其中少数位（第二章的 10 位示例里只有 3 位为 1）；如果让 $d$ 进分母，任意两个分子都会显得很像。Tanimoto 把 $d$ 排除在外，等于只比较"出现了什么"，这正是它能成为化学信息学默认度量的原因。用核的语言说，$T(A,B)$ 就是两个 0/1 特征向量的**最小-最大核**（min-max kernel），是内积的一种归一化。

## 七、相似性检索与性质预测：基线怎么落地

**结论：有了位串和系数，检索就是"编码查询分子 → 与库中每个分子算系数 → 排序取前 k 或设阈值"；性质预测则直接取最近邻的标签，全程不需要训练。**

视频把分子相似性的用途列成一串：相似性搜索、性质预测、合成设计、虚拟筛选、聚类分析、分子多样性分析。[【跳转到 28:02】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1682)

![分子相似性的应用清单：相似性搜索、性质预测、合成设计、虚拟筛选、聚类与多样性分析；相似性没有权威标准，取决于上下文](assets/分子指纹是手写的子图核：把子结构哈希成位串，再用%20Tanimoto%20数共享片段/01682.webp)

把这条清单拆成可执行的步骤，就是本节要的"非神经基线"：

1. **编码**：给查询分子和库里每个分子算同一种指纹（同一种指纹类型、同一组参数，比如 Morgan radius=2、2048 位）。
2. **打分**：逐对计算 Tanimoto 系数。这一步只是位运算，复杂度与分子数成线性，不需要 GPU。
3. **检索/筛选**：按分数排序取前 $k$ 个，或设一个阈值留下"足够像"的分子；也可以把分数矩阵拿去做层次聚类、多样性挑选；虚拟筛选就是先按相似度从大化合物库里挑出候选子集，再交给对接或实验。
4. **预测**：如果要预测性质，取最近邻的性质值（或前 $k$ 个的加权平均）作为预测。这就是指纹空间里的 kNN（k 近邻：取最像的 k 个样本的标签做投票或平均）基线，没有参数需要训练。

视频对"相似性"本身给了一个很重要的限定：**分子相似性是一个概念，而不是物理可观察到的量，所以"测量"分子相似性本质上是主观的，并且依赖于上下文；分子相似性没有正确或权威的衡量标准。** 因此才提出了各种相似性度量来量化结构相似程度。[【跳转到 28:02】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1682)

这也解释了为什么同一批分子换个指纹、换个系数，检索结果就会变：相似度的定义里有两个可替换部件——**代表分子结构的描述符**，以及**根据描述符计算分数的相似系数**；视频还提到第三个可选的加权方案，用来给描述符的各个组成部分分配不同的重要性。[【跳转到 29:12】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1752) 所以"指纹基线"不是一个基线，而是一族基线；报告结果时必须写清用的是哪一种指纹、哪一种系数。

## 八、适用条件与局限：什么时候指纹基线够用，什么时候必须换

**结论：指纹基线在"相似分子有相似性质、性质由二维子结构决定、目标子结构在覆盖范围内"这三条同时成立时很强；一旦性质依赖构象、依赖长程耦合，或者分子落在指纹字典之外，它会静默失效。**

**条件一：相似分子确实有相似性质。** 这是整个相似性范式的前提。检索和 kNN 预测都默认"离得近 → 性质接近"；如果性质在结构空间里剧烈跳变（比如一个甲基的差别就让活性反转），最近邻的标签就不能代表查询分子。视频没有讨论这条假设的检验方法，但它把相似性定义为"依赖上下文"的概念，本身就在提示：相似度的"近"是结构定义的近，不是性质定义的近。

**条件二：性质由二维子结构决定。** 指纹是二维的：结构指纹看子结构，路径指纹看键路径，圆形指纹看半径内的原子环境。它们都不含坐标。视频在讲文件格式时给了一个具体证据：mol 文件里的 Z 坐标"有的时候全是零，全是零就说明它这里只包括二维信息，而不包括三维信息"。[【跳转到 34:10】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=2050) 而三维描述符虽然能表达构象，却"由于分子的灵活性，不如 2D 表示稳健"。[【跳转到 00:20】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=20) 两头一夹，指纹的盲区就明确了：**对构象敏感的性质（结合构象、口袋形状互补、构象熵）在指纹空间里没有对应维度**：同一个分子的两种构象会得到完全相同的指纹，Tanimoto 相似度为 1。手性信息在 Morgan 里可以编码，但那是原子级的立体标记，不是构象。

**条件三：目标子结构落在覆盖范围内。** 结构指纹的覆盖问题视频讲得很直白：分子包含指纹的子结构不多时，"它们的特征将不被分子指纹所表示"。[【跳转到 18:09】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1089) 哈希指纹换了一种失效方式：位冲突让多个片段共享一个位，"从比特位出发无法追踪到结构特征"。[【跳转到 21:27】](https://www.bilibili.com/video/BV1DW4y1o7bQ/?t=1287) 两者合起来是同一个问题的两面——**指纹的维度是固定的，而化学空间是开放的**；超出字典或撞位的结构不会被报错，只会被压成 0 或别人的 1。

由此可以列出四条实践上的局限：

- **可解释性分层**：结构指纹的每一位能翻译回一条 SMARTS 子结构，可解释性最好；Morgan 的每一位理论上对应一种子结构，但经过哈希后，"这一位到底是什么片段"不再唯一，可解释性弱于结构指纹；路径哈希指纹最弱，视频直接说无法从位反推结构。
- **稀疏与信息压缩**：位宽固定，而分子命中的特征只占少数位，大量结构信息被压进固定长度；位宽越小冲突越多，位宽越大检索与存储成本越高。MACCS 只有 166 位，处理起来更容易，但也只能覆盖"药物发现和虚拟筛选中大多数感兴趣的化学特征"，不是全部。
- **对三维与构象的盲区**：如上，指纹只看见连接性；构象、口袋形状、长程静电这些三维量不在表示里。
- **度量本身不唯一**：没有权威的相似性标准，指纹、系数、加权方案三者都可换，换一组就可能换一个结论；因此基线必须写清配置，且不能把"相似度高"当成"性质一定接近"。

反过来说，指纹基线在下面这些场景仍然是首选：库很大而算力有限时的**粗筛**（位运算比 GNN 前向便宜得多）；需要**可解释到子结构**的命中解释；需要**无标签、无训练**就能给出排序的冷启动场景；以及作为 GNN 论文里的**下界对照**——如果 GNN 连 Morgan + Tanimoto 的 kNN 都赢不了，那它没有证明自己学到了更多结构信息。

## 小结

- 分子表示按维度分三层：一维字符串/指纹、二维图与片段、三维构象；全局描述符信息不足，三维描述符受构象灵活性拖累，二维指纹是相似性搜索与机器学习的主力。
- 指纹把分子变成定长 0/1 位串，每个位对应一个分子特征或环境；这样"比较分子"就变成"比较位串"。
- 结构指纹（MACCS，166/960 位）用预定义子结构字典，逐条判断存在与否；覆盖不到的结构一律记为 0。
- 哈希指纹（路径型 Daylight，最多 2048 位）枚举片段后哈希成位，必然出现位冲突，片段与位不再一一对应，也无法从位反推结构。
- 圆形指纹（Morgan，常用 radius=2、2048 位）记录每个原子半径内的环境，适合整体结构相似性搜索，不适合子结构查询。
- 用核的语言看：结构指纹是 0/1 版的子图核，圆形指纹是哈希定长版的 WL 核，Tanimoto 是这个核的归一化；视频没有用"核"这个词，这是本文的对应说明。
- 相似系数只用四个计数：Tanimoto 为 $c/(a+b-c)$，Dice 为 $2c/(a+b)$，因此 Dice 通常不低于 Tanimoto；两者都不使用"都为 0"的位数。
- 检索流程是编码、打分、排序取前 k 或设阈值；性质预测用最近邻标签，无需训练。
- 适用条件三条：相似分子有相似性质、性质由二维子结构决定、目标子结构在覆盖范围内。局限四条：可解释性分层、稀疏与压缩、三维/构象盲区、度量不唯一。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 分子指纹（molecular fingerprint） | 把分子编码成定长 0/1 位串的表示，每一位对应一个分子特征或环境。 |
| 结构指纹（substructure key-based fingerprint） | 用预定义子结构字典逐条判断存在与否的指纹，位宽等于字典大小。 |
| MACCS | 基于 SMARTS 子结构的结构指纹，有 166 位和 960 位两个版本，166 位最常用。 |

| 位冲突（bit collision） | 多个不同片段被哈希到同一位，导致片段与位失去一一对应、信息减少。 |
| 路径指纹（path-based fingerprint） | 沿指定数量键的路径收集片段再哈希的指纹，Daylight 是代表，最多 2048 位。 |
| 圆形指纹（circular fingerprint） | 记录每个原子指定半径内环境再哈希的指纹，适合整体结构相似性搜索。 |
| Morgan 指纹 | 最常用的圆形指纹实现，可设 radius 与位数；RDKit 的 Morgan 即通常说的 ECFP。 |
| ECFP | Extended-Connectivity Fingerprint，圆形指纹的一类；视频未使用该缩写。 |
| 子图核（subgraph kernel） | 以"共享子结构计数"定义两图相似度的核，$K=\langle\phi(G),\phi(G')\rangle$。 |
| WL 核（Weisfeiler-Lehman kernel） | 反复用邻域标签多重集细化节点标签，再累加各轮标签直方图内积的图核。 |
| Tanimoto 系数 | $c/(a+b-c)$，两个 0/1 向量的归一化重叠度，化学信息学默认相似度量。 |
| Dice 系数 | $2c/(a+b)$，分母不含共有项，取值通常不低于 Tanimoto。 |
| 相似性检索 | 把查询分子编码后与库中分子逐一打分、排序取前 k 或设阈值的过程。 |
