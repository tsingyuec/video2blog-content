# Protein-Complexa：测试时算力扩展与湿实验成功率

> 视频来源：[Scaling Atomistic Protein Binder Design with Generative Pretraining and Test-time Compute](https://www.youtube.com/watch?v=bt_1-VtjPSE)（YouTube · Boston Protein Design and Modeling Club，讲者 Carsten 与 Kian，NVIDIA）｜时长约 99 分钟
> 本文覆盖报告主体与现场问答：为什么「纯生成」和「纯推理时优化」是个伪二分法、测试时算力怎么花、以及当所有方法被放进同一个算力预算和同一套湿实验筛选时，成功率到底差多少。字幕为自动生成，本文订正了明显的识别错误（Protein-Complexa、Lab-Proteina、BindCraft、BoltzGen、RFdiffusion、ipAE 等）。

## 本讲要解决的核心问题（SCQA）

**背景**：蛋白质 binder 设计要生成一段能结合到指定靶点界面上的蛋白。现有方法大致分两派：一派是**纯生成模型**（如 RFdiffusion），在大量靶点—binder 配对数据上训练，推理时以靶点为条件采样，再用 AlphaFold2 的置信度分数做筛选；另一派是**纯推理时优化**（如 BindCraft），不训练生成模型，而是把折叠模型当奖励函数，直接优化一条序列。

**冲突**：这两派各自都有明显短板。纯生成模型在推理时不显式引导生成，遇到难靶点只能靠多采样；纯推理时优化则完全依赖折叠模型的分数，容易掉进「分数好看但实验不work」的坑。更麻烦的是，**评测本身不可比**：有人报 in silico 成功率，有人报湿实验命中率；有人用 32 GPU 小时，有人跑几天；有人只报最好的几个设计，有人报整个批次。

**疑问**：如果把「生成」和「推理时搜索」组合起来，能不能在难靶点上做得更好？更重要的是——**当所有方法被放进同一个算力预算、同一套筛选标准、同一批湿实验里时，谁真的能产出能结合的蛋白？**

**回答（中心思想）**：讲者认为「纯生成 vs 纯优化」是个**伪二分法**——现代生成式 AI 系统（大语言模型、推理智能体）都是「先预训练一个大生成模型，再在推理时花算力做搜索」。Protein-Complexa 就是把这个范式搬到蛋白 binder 设计上：用部分潜变量流匹配做生成式预训练，用并行去噪轨迹 + 共折叠打分做测试时算力扩展，然后用**一次约 100 万个 binder、127 个靶点、超过 14 万 GPU 小时的湿实验**来验收。结论是：在统一算力预算下，不做事后序列重设计的自生成序列，湿实验命中率最高（2.45%），而 in silico 上看起来更好的逆折叠重设计，在湿实验里反而更差。

## 一、两种现有方法，以及为什么这是个伪二分法

### 1.1 训练时优化 vs 推理时优化

讲者把现有方法分成两派：

| 派别 | 代表 | 做法 | 弱点 |
| --- | --- | --- | --- |
| 训练时优化（纯生成） | RFdiffusion 及其后续版本 | 在多聚体数据上训练，固定靶点输入、生成 binder；生成过程**没有显式引导**，只在事后用 AF2 筛选 | 难靶点上只能靠多采样；生成时不看分数 |
| 推理时优化（幻觉） | BindCraft | 没有生成模型；从随机初始猜测出发，把 AF2 当奖励函数做梯度更新，再对非界面区域做序列优化 | 完全依赖折叠模型分数；序列统计性质差 |

![两派方法的流程图对比：上面是 RFdiffusion 的训练时优化（生成后再用 AF2 筛选），下面是 BindCraft 的推理时优化（以 AF2 为奖励做梯度更新）](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/00911.webp)

[【跳转到 15:11】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=911)

讲者强调：这两种情况在最后通常都会做一次 ProteinMPNN 重设计，而 **Protein-Complexa 不做这一步**——这是后面湿实验结论的关键之一。

### 1.2 「伪二分法」：现代生成式 AI 都是预训练 + 推理时算力

讲者认为这个二分法是假的：看其他领域的现代生成式 AI 系统，比如大语言模型、推理智能体，总是**先训练一个大生成模型，再在这个模型之上做优化、搜索、某种测试时算力扩展**，在推理时解决难题。而 binder 生成，尤其是难靶点，可以算很难的问题。

![「False Dichotomy!」：现代生成式 AI 系统把生成式预训练与推理时算力扩展结合起来，例如 LLM 推理与智能体](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/01036.webp)

[【跳转到 17:16】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=1036)

问答里有人提出一个尖锐的反驳：现有的生成模型其实已经采样很多了，事后还做 best-of-N 的推理时搜索，而论文里也显示这是最高效的推理时搜索方法之一——那这不已经是「预训练 + 推理时算力」了吗？

讲者的回答很诚实：**对于容易的靶点，随机多采样、多测试可能确实就是最好的方法**；但对于难靶点，他们用 best-of-N 并没有得到那么多成功，而更高级的搜索算法效果更好。这正是后面「算力—成功率曲线」要展示的东西。

## 二、模型从哪来：Lab-Proteina 的部分潜变量流匹配

要理解 Protein-Complexa，得先理解它的前作。讲者用相当篇幅讲了模型家族的三级台阶：**Proteina**（2025 年 3 月，只做骨架生成）→ **Lab-Proteina**（2025 年 7 月，全原子生成）→ **Protein-Complexa**（binder 生成）。

### 2.1 全原子生成是个「离散 + 连续、维度可变」的问题

要生成全原子蛋白质，你必须知道序列（离散的序列 token），然后从侧链生成连续的原子坐标；而侧链长度取决于你生成的是哪种氨基酸。这是一个离散与连续混合、维度可变的问题。

Lab-Proteina 的解法是**潜变量**：把氨基酸身份（离散）连同侧链的原子细节，一起编码到一个**每个残基固定大小**的潜空间里；同时**显式保留骨架**（alpha 碳坐标），其余部分只用潜变量建模。于是这就变成了一个纯粹的连续生成建模问题，可以直接套用大规模扩散/流匹配框架。

具体地，$n$ 个残基有 $3n$ 个 alpha 碳坐标，再编码成额外的 8 个潜变量通道。生成时用流匹配在「alpha 碳骨架 + 每残基潜变量」的联合空间上做，所以叫**部分潜变量**（partially latent）——骨架是显式的，其余是潜的。

### 2.2 一个被低估的细节：采样日程

讲者特别强调 **sampling schedule（采样日程）**：跑 400 步模拟时，模型先主要生成 alpha 碳坐标，而潜变量一开始只缓慢地去噪。所以这是两套生成日程，有点像「先生成骨架、再生成侧链与序列」的经典流程，但没那么二元，更介于两者之间，后面两者会互相影响。

讲者的原话是：**这也许是我们模型最重要的隐藏超参数**，怎么调影响很大。Lab-Proteina 和 Protein-Complexa 都是这样。这一点对「评测」的意义在于：**采样步数与日程本身就是预算的一部分**，换一套日程，同样的步数得到的结果不可比。

### 2.3 自编码器只处理单体，条件模型才看靶点

Protein-Complexa 的架构是 Lab-Proteina 的直接扩展：编码器和解码器原样沿用（只在 PDB 蛋白上额外微调），只有那个**以靶点为条件的部分潜流模型**是新的。序列 token 扩展成靶点的额外原子级特征，再加上 hotspot token，构造覆盖整体的联合 pair 表示，最后只提取 binder 的向量场。

一个容易被忽略但很重要的设计：**自编码器仍然只处理单体**，不生成复合物。讲者用图像潜扩散模型类比——你通常只让潜模型以文本为条件，自编码器还是标准的图像自编码器。

### 2.4 全局平移噪声：让模型在整个生成过程中推理「放在哪」

训练目标里有一个看似突兀的项：一个**全局平移扰动**。它不是每个残基上的 alpha 碳噪声，而是一个噪声值广播到所有维度，让整个 binder 在生成过程中带着一个全局扰动，模型必须把它去掉。

动机来自流模型的性质：这类模型**先生成低频信息、再生成高频信息，而初始生成之后几乎不再细化低频信息**；而全局平移恰恰是最低频的信息。如果不管它，模型一开始挑一个位置（可能挑得很差），然后再也不改，就朝那个位置去噪，哪怕有碰撞。

问答里有人追问这个扰动的标准差是多少，现场确认是 **2 埃**（讲者一度记成 0.2，最后被纠正）。也有人指出论文方程里把它写成了标量，讲者承认那是笔误，应该是三维平移向量。

讲者还提到：RFdiffusion2 里用了非常类似的技术，底层动机相同。

## 三、测试时算力怎么花：并行去噪 + 共折叠打分 + 剪枝重启

### 3.1 机制

Protein-Complexa 的推理时扩展机制可以拆成四步：

1. **并行**跑多条去噪轨迹（在部分潜空间里）；
2. 把轨迹展开到若干步后，**解码**成结构；
3. 与靶点**共折叠**（co-fold），用 ipAE 之类的分数**打分**；
4. 根据分数好坏**截断**某些轨迹，从更有希望的轨迹上**发起新轨迹**。

![测试时算力扩展的示意：并行去噪轨迹 → 解码 → 与靶点共折叠 → 计算奖励（ipAE、氢键数等）→ 保留或剪枝](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/02170.webp)

[【跳转到 36:10】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=2170)

讲者指出这套东西和几个熟悉的搜索算法是同一件事：

- **Best-of-N**：只采样不剪枝，最后挑最好的 N 个；
- **Beam search**：按分数保留前若干条轨迹，从它们继续分支；
- **FK steering**：同一件事，只是带概率重加权；
- **蒙特卡洛树搜索**：把去噪轨迹看成树。

**扩展算力的旋钮是粒子数（并行轨迹数）与分支因子**。这就把「算力预算」变成了一个可以直接调节、也可以直接报告的量——这一点对评测至关重要：**不报粒子数和分支因子，就无法比较两个方法的成功率**。

### 3.2 算力—成功率曲线：容易靶点用 best-of-N，难靶点要搜索

讲者给了两张曲线：横轴是 GPU 小时，纵轴是唯一成功数（unique successes）。

- **容易靶点**：best-of-N 的曲线在最上方，随算力线性增长最快；
- **难靶点**：beam search 与 FK steering 明显优于 best-of-N，BindCraft 与 AlphaDesign 的曲线低得多。

![推理时算力扩展曲线：左图容易靶点上 best-of-N 最强，右图难靶点上 beam search 与 FK steering 更强，BindCraft/AlphaDesign 明显更低](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/02493.webp)

[【跳转到 41:33】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=2493)

这张图是整场报告在方法论上最有价值的一张：**它把「方法好坏」变成了「在给定算力下的成功率曲线」**。同一张图里，你既能看到不同方法的效率差异，也能看到「多给算力能不能救回来」。讲者还提到，有些非常难的多链接口靶点，在 32 GPU 小时内他们和所有基线都做不出来，但只要算力给够，就能得到 binder。

### 3.3 把奖励换成物理量：界面氢键优化

讲者展示了一个很有意思的扩展：除了 ipAE，还可以在推理时优化**其他奖励**，比如用 GPU 加速的力场去优化**界面氢键数**。

![界面氢键优化：不做奖励时界面氢键少，加上氢键奖励后能得到漂亮的 beta 链配对（左 15 个氢键 vs 右 1 个氢键）](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/02523.webp)

[【跳转到 42:03】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=2523)

有意思的是，这不仅提高了氢键数量，**也提高了成功率**；而且加上氢键奖励后，ipAE 分数本身也比只有 ipAE 奖励时更好——讲者认为这是一个**正交信号**。这提示：折叠模型的置信度分数是有限的，**用基于物理的方法补充筛选与生成，是改进评测与生成流程的一个方向**。

## 四、in silico 基准：先定清楚「成功」是什么

### 4.1 靶点集与成功判据

讲者的 in silico 基准借用了 BindCraft 的靶点集（很多人也这么做），另外加了一个小分子生成基准。靶点表里列出了靶点名、PDB ID 或 AF2 预测、靶点链与残基范围、hotspot 残基、binder 长度范围与来源。

![in silico 基准的靶点表：每个靶点给出 PDB ID / AF2 预测、链与残基范围、hotspot 残基、binder 长度与来源](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/02322.webp)

[【跳转到 38:42】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=2322)

**成功判据**直接采用了 AlphaProteo 的做法：一个基于 AF2 的过滤器，看 ipAE、binder 的 RMSD、pLDDT 等指标；他们做过消融，说明这个过滤器还不错。讲者还说明，他们通常看的是**唯一成功数**——先对生成的 binder 做聚类，再数成功簇的个数，避免「同一个设计重复计数」这种典型的筛选偏差。

### 4.2 消融：Tetramer 数据与平移噪声都重要

讲者提到两个关键消融：**Tetramer 数据集**（从 AlphaFold 数据库切分结构域构造的合成 binder—靶点配对）很重要，**平移噪声**通常也很重要。训练数据方面：过滤后的 PDB 多聚体只有 45,000 个，而通过把 AFDB 蛋白切成结构域、把不同结构域当作合成 binder—靶点配对，他们多了约 50 万个训练配对——这是一次巨大的数据增广。

### 4.3 一个提前出现的信号：in silico 上逆折叠更好

问答里，Panos 指出：计算结果显示**逆折叠（ProteinMPNN）生成的序列似乎还是更好**。讲者承认这一点，并说这正是他要在湿实验部分回头讲的：**通常逆折叠在 in silico 上更好，但湿实验结果恰恰相反，而且不止一次**。

这句话是理解整场报告的关键：**in silico 指标是有偏的，而且偏差方向是可预测的**——它系统性地偏好「折叠模型自己喜欢」的序列，而不是「实验里真的能结合」的序列。

## 五、湿实验：把预算、筛选和判据全部对齐

### 5.1 为什么要做湿实验

讲者的动机很直接：**我们的指标并不完美，我们对这些东西都持怀疑态度，那就看看它到底在实验室里行不行**。

### 5.2 第一步：先验证单体

他们先和 LMU 的一个合作实验室（讲者称 Iona 组）验证单体：测试从 100 个残基到 800 个残基的各种长度，比较「同一个骨架下用我们生成的序列」与「用 ProteinMPNN 重设计的序列」。结论是总体持平：表达量好、可溶、能折叠、有些耐热、产量也不错；有些情况下 MPNN 产量更高，有些情况下 Complexa 更好。

这里有一个**温度参数**的发现值得单独说。讲者展示了一张氨基酸频率对比图：

![氨基酸频率与 CD 谱：低温采样（绿）几乎复现 MPNN 的分布（谷氨酸、赖氨酸富集），高温采样（粉）更接近 UniProt 天然分布；CD 谱显示低温样本升温几乎不变、高温样本会部分解折叠](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/04331.webp)

[【跳转到 72:11】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=4331)

- **低温采样**基本复现了 MPNN 的分布（谷氨酸、赖氨酸很多，「折叠模型和 MPNN 喜欢的」），CD 谱在 20 度与 95 度之间几乎没有变化——「像 MPNN 通常给出的那样，是超级稳定的石头」。
- **高温采样**更接近 UniProt 天然分布（更多苯丙氨酸、酪氨酸、色氨酸这类庞大氨基酸），升温时谱变化明显，说明会部分解折叠，行为更像天然蛋白；表达量也不像 MPNN 那么夸张。

讲者把这个温度参数称为模型里一个很好的**旋钮**：可以在「MPNN 式超稳定」和「更接近天然」之间调节。对评测而言，这意味着**同一个模型在不同温度下是不同的方法**，不报温度就无法比较。

### 5.3 大规模筛选：约 100 万个 binder、127 个靶点、14 万 GPU 小时

与 Manifold Bio 合作，他们做了一次**多重噬菌体展示（multiplexed phage display）**的全对全结合筛选：

- 约 **100 万个 binder**，针对 **127 个靶点**；
- 全对全结合矩阵，约 **1000 个任务**（不同 hotspot）；
- 超过 **140,000 GPU 小时**；
- 结果：在 **87 个靶点**上拿到 on-design 命中，其中 **74 个是特异性的**（只结合设计靶点，不结合其他靶点）。

![大规模验证活动：约 100 万 binder × 127 靶点的全对全结合矩阵，on-design 命中 87 个靶点，其中 74 个特异](assets/Protein-Complexa%EF%BC%9A%E6%B5%8B%E8%AF%95%E6%97%B6%E7%AE%97%E5%8A%9B%E6%89%A9%E5%B1%95%E4%B8%8E%E6%B9%BF%E5%AE%9E%E9%AA%8C%E6%88%90%E5%8A%9F%E7%8E%87/03005.webp)

[【跳转到 50:05】](https://www.youtube.com/watch?v=bt_1-VtjPSE&t=3005)

这里有几个**定义必须先说清楚**，否则「成功率」没有意义：

| 术语 | 定义 |
| --- | --- |
| on-design | 你针对某个靶点设计，并且在这个靶点上拿到命中 |
| off-design | 你没针对某个靶点设计，却在这个靶点上拿到命中 |
| on-design specific | 只命中设计靶点，不命中其他靶点 |
| polyspecific | 除设计靶点外，还命中 1–3 个其他靶点；命中更多就不算 on-design 了 |

讲者还提到一个有意思的现象：**有些靶点不管你对它设计什么，总能找到能结合的 binder**；而有些 hotspot 基本是「不可能的」（Manifold 给的 hotspot 里有些更像是随机选的）。

### 5.4 头对头比较：预算怎么对齐

这是整场报告在评测方法学上最值得学习的一段。为了让比较公平，讲者做了这些对齐：

1. **同样的算力预算**：每个方法每个靶点 **32 GPU 小时**，而且**包括生成、逆折叠、重折叠的全部开销**——否则对幻觉方法不公平。
2. **同样的样本数**：每一列都基于 **400 个送进实验室的样本**；各方法在这段时间里生成的候选池大小不同，但都按 in silico 分数挑最好的 400 个。
3. **保证不被预算饿死**：选 400 这个数字，是为了让每个方法得到的成功数都超过实验预算，避免某个方法因为「这段时间只做出 200 个样本」而吃亏。
4. **同一个 hotspot**：先在 in silico 上针对每个 hotspot 设计、按 ipAE 阈值数成功数，挑表现最好的那个 hotspot，然后把这个 hotspot 给所有方法。讲者补充说，通常最好的 hotspot 对所有方法都是同一个。
5. **同一个过滤器**：所有方法统一用 AlphaFold2 那套重折叠和筛选（min ipSAE），因为「评估的是生成方法，不是过滤器」。
6. **同样的温度**：基准里每个方法只给一个温度（Complexa 用 0.1 和 1，一开始就定死），温度对比是另一组实验。
7. **不重复计数**：生成 8 条 MPNN 序列时，每个骨架只取一条，凑不满 400 再取第二条。

讲者还澄清了几个容易误解的细节：BoltzGen MPNN、BoltzGen IF、BoltzGen self 被当作**三个独立的方法**，各自有自己的 32 GPU 小时预算和 400 个样本；重折叠步骤不算进 BoltzGen 的流水线计时，只是为了最后出数字。

### 5.5 结果：统一预算下的湿实验命中率

这张图的读法很重要。它按「事后是否做序列重设计」分成三组：

| 分组 | 方法 | on-design 特异命中率 |
| --- | --- | --- |
| 不重设计 | Complexa self | **2.45%** |
| 不重设计 | BoltzGen self | 0.76% |
| 不重设计 | RFD3 self | 0.04% |
| 部分重设计（固定界面） | Complexa fixed | 1.72% |
| 部分重设计（固定界面） | BindCraft fixed | 1.25% |
| 完全重设计 | BoltzGen mpnn | 1.81% |
| 完全重设计 | Complexa mpnn | 1.61% |
| 完全重设计 | BoltzGen IF | 1.30% |
| 完全重设计 | RFD3 mpnn | 0.41% |
| 完全重设计 | RFD mpnn | 0.32% |

两个结论：

1. **Complexa 的自生成序列在湿实验里最好**（2.45%），而且**不需要事后序列重设计**；
2. **对 Complexa 来说，逆折叠重设计反而降低了命中率**（2.45% → 1.61%），而其他方法（BoltzGen、RFD3）做重设计通常是提升。

第 2 点在现场引发了很长的讨论。有听众指出：如果 Complexa 擅长生成命中，那么对它生成的命中做逆折叠，那条序列很可能也应该命中——「只要起点是 binder 骨架，重设计应该总是改进」。讲者的解释是：**这取决于基础方法本身的序列生成能力**。他们看过序列分布：Complexa 低温匹配 MPNN、高温匹配 UniProt，而 BoltzGen 和 RFD3 都严重过度表达某些氨基酸；BindCraft 这类纯幻觉方法如果不做 MPNN，序列统计性质也不好。所以「MPNN 有没有用」不只取决于 MPNN，还取决于**基础方法的序列质量**。

另一个解释是**特异性的定义**：这里的成功是「on-design specific」，即只命中设计靶点。讲者说，如果只看「有没有命中」这个靶点，差异不一定显著；但看「这个命中对该靶点有多特异」，self 似乎更好。

### 5.6 显著性：2.45% 算高还是低

现场最有价值的一段讨论来自 Martin 的提问：**这些差异在实验上显著吗？**

讲者的回答分两层：

- **绝对数字不高**：2%、2.5% 看起来不算高。但这是因为他们给了很紧的算力预算，而且这次是**纯粹的贪心筛选**——只按 ipAE 挑，没有做形状互补、疏水性等更高级的过滤，靶点裁剪也是自动算法生成的。后面幻灯片显示，只要多采样，成功率可以显著提高。
- **Martin 的反驳**：他认为这些数字「非常出色」——在 75 个多样靶点上、用这么高通量的方法拿到 2.5% 的特异命中率是惊人的。但他同时提醒：**通量越高，误差越大**；同样的实验在周一做和周三做，结果可能差 10 倍。所以在这种高 throughput 方法里，**两倍的差异基本是噪声，只有 10 倍差异才算显著**——按这个标准，唯一显著的差异是 RFdiffusion3 与其他方法之间的差异。

讲者补充说，这些测试其实是同一天做的，不是分几天做的。这段对话本身就是「任务成功率」这一类指标最好的教学材料：**分子（命中率）和分母（预算、筛选强度、实验通量、批次效应）必须一起报，否则数字不可解释**。

## 七、局限与开放问题

问答部分暴露了几个诚实的局限：

- **数据决定上限**。Tetramer 数据集是从 AlphaFold 数据库切结构域构造的，界面通常比真实 PDB 界面小，平均氢键更少、亲和力更低。讲者承认：如果换成真实的 50 万个蛋白—蛋白复合物，效果可能更好；这更像是一种**高级数据增广**，而不是「真实相互作用数据」。
- **合成数据继承结构预测模型的缺陷**。有听众问：AlphaFold2 不是全原子的，它无法处理金属离子、翻译后修饰，那用它构造的训练数据会不会带来问题？讲者回答：结构预测模型每天都在进步，所以合成数据也会随之进步；而且他们主要用这些数据学 **PPI 界面**，界面通常和配体口袋很不一样，所以这个影响不是最关键的。
- **潜变量 vs 显式原子**。有人问：全原子建模的意义不就是在真实空间里直接刻画原子间相互作用吗？讲者认为这个区分没想象中大——一旦嵌入模型，原子身份本来就是「潜在地」被推理的；他们看到侧链 rotamer、分子内氢键的质量与 PDB 相当，重建 RMSD 约 0.05 埃，「基本是完美的」。
- **温度与序列分布**还没有最优用法。讲者说这是一个很好的旋钮，但「怎么在不同应用里用得最好」还需要研究。
- **绝对成功率仍然偏低**。讲者自己说 2%、2.5% 不算高，并归因于紧预算 + 纯贪心筛选；Martin 则认为在 75 个多样靶点上这已经很好。这个分歧本身说明：**「成功率多高算好」没有绝对标准，取决于预算、筛选强度与靶点难度**。

## 小结

- **评测要报预算**：成功率必须和 GPU 小时、粒子数/分支因子、送检样本数一起报；同一方法在不同算力下的成功率可以差好几倍。
- **「成功」必须先定义**：on-design、on-design specific、polyspecific 是三个不同的量；不定义清楚，「命中率」没有意义。
- **筛选标准要对齐**：所有方法用同一个过滤器（这里是 AF2 + min ipSAE），否则你评估的是过滤器而不是生成方法。
- **in silico 指标有方向性偏差**：逆折叠在 in silico 上更好，在湿实验里却可能更差；偏差方向与「折叠模型喜欢什么」有关。
- **筛选偏差会高估能力**：只报最好的几个设计、只报 in silico 分数、只报单一 hotspot，都会高估；聚类后数「唯一成功数」是一种纠偏手段。
- **实验噪声决定什么叫「显著」**：高 throughput 筛选里两倍差异可能只是噪声，十倍差异才值得讨论。
- **约束满足要单独看**：合成可及性、特异性、极性靶点（糖类）的可设计性，都不能由折叠分数替代。
- **算力可以换成功率，但不是免费的**：难靶点上更聪明的搜索（beam search、FK steering）比单纯多采样更有效；容易靶点上 best-of-N 就够了。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| binder | 结合蛋白：被设计出来去结合某个靶点界面的小蛋白 |
| 测试时算力扩展（test-time compute scaling） | 在推理阶段多花算力（并行采样、搜索、剪枝重启）来提高成功率 |
| best-of-N | 只采样 N 个候选，按分数挑最好的，不做中间剪枝 |
| beam search | 按分数保留前若干条去噪轨迹，从它们继续分支 |
| FK steering | 与 beam search 同源，但对轨迹做概率重加权 |
| ipAE / ipSAE | 折叠模型给出的界面预测质量分数，常用作 binder 设计的筛选指标 |
| on-design specific | 只命中设计靶点、不命中其他靶点的命中 |
| 多重噬菌体展示 | 一次实验里并行筛选大量 binder 与大量靶点结合情况的高通量方法 |
| 唯一成功数（unique successes） | 对生成的 binder 聚类后数成功簇的个数，避免同一设计重复计数 |
| 部分潜变量流匹配 | 骨架（alpha 碳）显式保留、侧链与序列用每残基潜变量建模的流匹配生成框架 |
| 逆折叠 / ProteinMPNN | 给定骨架反推序列的模型；湿实验显示它不一定能提升 binder 命中率 |
| 筛选偏差 | 只报告通过筛选的样本或只报最优结果，从而系统性高估能力 |
