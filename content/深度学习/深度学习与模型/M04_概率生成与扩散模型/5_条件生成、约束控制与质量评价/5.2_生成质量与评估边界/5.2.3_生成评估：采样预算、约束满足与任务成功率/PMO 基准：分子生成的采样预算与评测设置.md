# PMO 基准：分子生成的采样预算与评测设置

## 本讲要解决的核心问题（SCQA）

**背景**：在分子发现里，我们想找到「新的功能性分子」——能与靶蛋白紧密结合的药物分子，或具有指定能带结构的材料分子。深度生成模型被寄望于加速这个过程：在巨大的化学空间里直接「生成」候选，而不是靠高通量筛选去试错。

**冲突**：可是当一批论文都说自己「更好」时，这些比较往往不可比。讲者指出三个具体障碍：**不报 oracle 调用次数**、**oracle 选得太容易**、**实验设置各不相同**。一个方法可以只调用 500 次 oracle 就达到某个分数，另一个调用 20 万次达到同样分数——如果只报「最好的那个分子」的分数，两者看起来一样好，但代价差了三个数量级。

**疑问**：那么，怎样才算是「公平地比较两个分子生成方法」？采样预算、oracle 选择、随机种子、超参调优，这些实验设置应该如何统一，才能让排名有意义？

**回答（中心思想）**：**把采样预算写进指标本身**。PMO（Practical Molecular Optimization）基准把 oracle 调用上限固定为 10000 次，用「AUC top-K」而不是「top-K」作为主指标，统一 23 个 oracle、25 个方法、5 次独立重复与同一套数据库，并把超参调优也计入预算。结论是反直觉的：**没有哪个方法足够采样高效**，而且很多「强基线」的排名在换成预算敏感指标后会掉下来。

## 一、三个让比较失效的问题

### 1.1 问题一：不报 oracle 调用次数，比较就不公平

讲者把分子优化形式化为一个带约束的多目标优化问题：在整个分子空间上优化，去最大化或最小化 oracle 打分。最朴素的做法是高通量筛选，但它需要大量试错、既耗时又昂贵；生成式方法本应加速它，但评测环节没跟上。

第一个障碍是**采样效率没有被报告**。讲者展示了一张汇总表：不同方法在同一个任务（JNK3、GSK3β）上报告的 top-1、top-10、top-100 分数看起来差别不大，但最右一列「#oracle」从「100K+0」到「10K+10K」不等，甚至有些方法根本没有报告这个数字。

![这张表把「分数」和「oracle 调用次数」并列，说明只看分数会让不同预算的方法看起来一样好](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/00192.webp)

[【跳转到 03:12】](https://www.youtube.com/watch?v=OfdWayFibBU&t=192)

这里的「oracle」是一个可以被打分、但调用有代价的黑箱函数：给定一个分子，它返回一个数值（类药性、与靶点的结合亲和力预测等）。调用一次 oracle 就相当于做一次虚拟筛选或一次实验测量，所以**oracle 调用次数就是采样预算**。预算不同的两个结果放在一起排名，等于让一个跑 100 米的人和一个跑 400 米的人比成绩。

### 1.2 问题二：oracle 选得太容易，方法之间就分不出高下

第二个障碍是 oracle 的选择。讲者举了两个典型例子：

- **QED（类药性）**：它是一个人工规则，很容易优化。很多方法都能达到 0.948，而这个值被认为是 QED 的全局最优——**连随机搜索都能达到**。既然天花板人人都能碰到，它就失去了区分能力。
- **logP（脂水分配系数）**：它偏好大的苯环或碳原子。如果你不断往分子上加苯环或碳原子，分数就会一直涨。这也不是一个「有意义的」优化目标。

![同一张幻灯片用表格说明：在 QED、penalized logP 这类 oracle 上，不同方法的最大值几乎相同](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/00242.webp)

[【跳转到 04:02】](https://www.youtube.com/watch?v=OfdWayFibBU&t=242)

换句话说，**oracle 的「地形」（landscape）决定了这个任务有多难**。如果地形是一片单调上升的缓坡，任何会爬坡的方法都能到顶；只有地形有陷阱、有多峰、有平台时，方法之间的差异才会显现出来。

### 1.3 问题三：实验设置各异，报告的指标也各异

第三个障碍是实验报告本身。不同方法的设置不同：训练数据不同、起始分子不同、随机种子不同、超参数调优策略不同。它们还会各自挑选「顺手的」基线方法，并报告各种不同的指标——「最好的那一个」、top-K、recall 等等。

讲者由此提出「理想算法」的四条标准：

| 标准 | 含义 | 对应的评测要求 |
| --- | --- | --- |
| Powerful（强大） | 有很强的优化能力 | 最终分数要高 |
| Efficient（高效） | 在有限 oracle 调用内把性质优化上去，越快越好 | 必须报告预算 |
| Generalizable（可泛化） | 在多种任务上都有不错表现 | 多 oracle、多任务 |
| Robust（鲁棒） | 对随机种子有合理鲁棒性 | 多次独立重复 + 标准差 |

## 二、PMO 的解法：把预算写进指标

### 2.1 指标设计：上限 10000 次调用，主指标是 AUC top-10

PMO 的第一个设计决定是**给 oracle 调用次数设上限：10000 次**。第二个决定是**用 AUC top-10 作为主指标**，而不是 top-10。

「top-K」只问：在我跑完整个预算之后，我手里最好的 K 个分子有多好？「AUC top-K」问的是：在预算的每一步，我手里最好的 K 个分子有多好，然后对整条曲线求面积。用公式写出来，若 $\mathrm{top}K(t)$ 表示用到第 $t$ 次 oracle 调用时当前最优 K 个分子的平均分数，$T$ 为预算上限，则

$$
\mathrm{AUC\text{-}top}K = \frac{1}{T}\int_{0}^{T} \mathrm{top}K(t)\,dt
$$

这个量把「最终能到多高」和「多快能到」压成了一个数：**早拿到好分子，面积就大**。讲者在问答里也澄清了这一点——这个曲线不是 ROC 或 PR 曲线，横轴是 oracle 调用次数，纵轴是当前的 top-K 分数，面积就是这条曲线下的累积表现。

![横轴是 oracle 调用次数、纵轴是 top-10 分数的曲线族，面积越大表示在同样预算下越早拿到好分子](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/00392.webp)

[【跳转到 06:32】](https://www.youtube.com/watch?v=OfdWayFibBU&t=392)

### 2.2 oracle 覆盖：23 个任务，刻意避开对接打分

PMO 覆盖了最常用的一批 oracle：QED 衡量类药性；DRD2、JNK3、GSK3B、GSK3β 衡量与特定靶点受体的结合亲和力；此外还有 19 个来自 GuacaMol 的 oracle（基于相似性、基于异构体等）。

值得注意的是**没有纳入对接打分（docking score）**。讲者的理由是：对接打分评估起来通常很耗时，而且仍然不准确。这是一个诚实但重要的取舍——**评测集的选择本身也是评测设置的一部分**，纳入一个又慢又噪声大的 oracle，会让「预算」的含义变得模糊。

![PMO 的设计要点：预算上限 10000 次、主指标 AUC top-10、覆盖最常用的 oracle，并明确排除昂贵且不准确的对接打分](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/00417.webp)

[【跳转到 06:57】](https://www.youtube.com/watch?v=OfdWayFibBU&t=417)

问答里有人追问 DRD2、JNK3、GSK3β 这些 oracle 到底是什么。讲者回答：它们**不是直接的对接打分**，而是用机器学习模型训练的，训练数据来自真实的湿实验结合数据。这一点很关键——它意味着 oracle 本身是一个「代理模型」，代理模型和真实实验之间的差距，正是后面所有讨论的根源。

### 2.3 统一实验设置：调参、重复次数、数据库

PMO 的第三组设计决定是统一实验设置：

1. **为每个方法调超参数**（而不是用作者原版默认值），因为默认值往往没有为这个基准调过；
2. **每个方法在每个任务上跑 5 轮独立实验**，报告平均值和标准差；
3. **所有方法使用同一个数据库**（ZINC 250,000）。

![统一设置的三件事：调超参、5 次独立重复报均值与标准差、共用同一数据库](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/00467.webp)

[【跳转到 07:47】](https://www.youtube.com/watch?v=OfdWayFibBU&t=467)

第 2 点常被忽略，但讲者后面专门用一页幻灯片说明它的重要性（见 §5.2）。第 1 点则引出一个更微妙的问题：**调超参数本身要消耗 oracle 调用**。如果调参花了 5000 次调用、正式跑又花 10000 次，那这个方法的真实预算就是 15000 次。讲者在问答里给出的做法是：调参与正式运行各用 10000 次预算，并且建议调参至少需要 2000–3000 次 oracle 调用，否则「很难看出趋势」。

## 三、规模：25 个方法 × 23 个 oracle

### 3.1 之前的基准太小

讲者回顾了此前的基准，指出它们的共同问题是**规模有限**：

- **GuacaMol**：只包含四种机器学习方法（基于爬山法的 SMILES LSTM、SMILES 层面遗传算法、图层面遗传算法、图层面蒙特卡洛树搜索）；
- **Therapeutics Data Commons 的分子优化基准**（2021）：专注优化对接打分，包含六种方法——两种领域特定方法（高通量筛选、图层面遗传算法）与四种机器学习方法（LSTM 爬山、GCPN、MolDQN、MARS）；
- **Austin Tripp 的从头分子设计基准**（2021）：三种方法（图层面遗传算法、SELFIES 层面遗传算法、混合遗传算法与贝叶斯优化）。

PMO 覆盖了 **25 种有代表性的算法**。讲者用两个维度给它们分类：

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 分子组装策略 | 字符串 / 图 / 合成 | 字符串分 SMILES 与 SELFIES；图分以原子为构建单元与以片段为构建单元；合成用化学反应构造分子 |
| 方法论 | GA、MCTS、BO、VAE、GAN、SBM、HC、RL、梯度上升 | 遗传算法、蒙特卡洛树搜索、贝叶斯优化、变分自编码器、生成对抗网络、基于得分的建模、爬山法、强化学习、梯度上升 |

[【跳转到 11:19】](https://www.youtube.com/watch?v=OfdWayFibBU&t=679)

一些太早期或学习过程太慢的算法（如 BOSS、JAMBO、基于博弈的方法）没有纳入。这又是一个评测设置的取舍：**纳入哪些方法，本身会改变「谁最强」的结论**。

## 四、结论一：没有方法足够采样高效

### 4.1 大多数方法要上千次调用才拿到理想分子

讲者的第一个结论是：**没有哪个方法足够采样高效**。他展示了两张典型任务的曲线（thiothixene 与 troglitazone 的 rediscovery），可以看到绝大多数曲线在前 2000 次调用里上升缓慢，要上千次 oracle 调用才能得到性质理想的分子。

### 4.2 top-K 排名高不等于采样高效：爬山法的例子

第二个结论最能说明「指标选择决定结论」。讲者标出了三个爬山法（SMILES-LSTM-HC、SELFIES-LSTM-HC 等）：它们在 **top-K 指标上排名靠前**，但在 **AUC top-K 指标上排名明显下滑**。

![同一张排名表，红框圈出的爬山法在 top-1/top-10/top-100 列排名靠前，在 AUC top-K 列排名靠后](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/00929.webp)

[【跳转到 15:29】](https://www.youtube.com/watch?v=OfdWayFibBU&t=929)

这背后的机制不难理解：爬山法每步只做局部微调，最终确实能爬到一个高分分子，但它需要大量 oracle 调用来一步步爬；而 AUC 衡量的是「多快拿到好分子」，于是它掉下来了。**如果你只看 top-K，你会误以为它很强；一旦把预算写进指标，这个优势就消失了。**

### 4.3 老算法依然很强

第三个结论有些反直觉：**较老的方法依然很强**。REINVENT（2017 年提出，用 SMILES 字符串作表示、循环神经网络作生成器、策略梯度训练）在全部六个指标上都排第一；只把 SMILES 换成 SELFIES 的 SELFIES-REINVENT 排第三。前十名里还有四个是基于遗传算法的方法。

讲者自己也说这「非常令人意外」。这提示我们：**新方法并不自动优于老方法**，而排行榜的差异往往来自评测设置而不是模型本身。

### 4.4 SMILES 与 SELFIES：一个被实验推翻的刻板印象

讲者专门比较了 SMILES 与 SELFIES 两种字符串表示。做法是以每个「SMILES 变体 vs SELFIES 变体」为一个点，横轴是 SMILES 变体的表现，纵轴是 SELFIES 变体的表现。结果：**大多数点在虚线下方，即 SMILES 变体更好**（遗传算法是例外，但那不是严格的一对一对比）。

![SMILES 与 SELFIES 的逐点对比：多数点落在对角虚线下方，说明直接替换成 SELFIES 并没有带来提升](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/01314.webp)

[【跳转到 21:54】](https://www.youtube.com/watch?v=OfdWayFibBU&t=1314)

讲者特别强调：人们通常认为 SMILES 字符串容易出现语法错误、有效率低，但**这个刻板印象在实验里并不成立**。他确实在 SELFIES 字符串里发现了语法问题——有些 SELFIES 字符串非常长，却塌缩成一个非常简单的分子，因为它在化学上并不真的合法——但就整体优化性能而言，SMILES 并不吃亏。

问答里有人追问：这张图展示的是有效率还是准确率？讲者澄清：**没有报告有效率**，因为 SMILES 的有效率非常高，而且对基于图的方法，生成的分子总是合法的，所以只衡量 AUC top-K 分数。这又是一个评测设置的取舍：**当某个指标对所有方法都饱和时，它就不再是区分度来源，报告它只是增加噪声**。

## 五、结论二：约束满足、调参与方差

### 5.1 合成可及性：约束满足率是一个独立维度

分子优化的输出必须能真的被合成出来，否则再高的 oracle 分数也没有意义。PMO 报告了所有任务、所有方法的 **SA（synthetic accessibility，合成可及性）分数**。讲者指出，有些方法的 SA 分数明显更低（更好合成），尤其是基于合成的方法——DoG-Gen、SynNet、DoG-AE 等用化学反应来增长分子的方法。

把 SA 放进评测的意义在于：**「约束满足率」和「优化能力」是两个正交的维度**。一个方法可以分数很高但生成一堆无法合成的分子；如果评测只报分数，这种失败模式就被隐藏了。

### 5.2 方差：单次实验的排名不可信

讲者用一页幻灯片说明**重复多次实验的重要性**：大多数方法在多次独立实验之间的方差很大。所以他建议，如果想得到可靠的表现评估，应该独立地多跑几次。

![多次独立重复之间的方差示意：单次运行的结果波动足以改变排名](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/01727.webp)

[【跳转到 28:47】](https://www.youtube.com/watch?v=OfdWayFibBU&t=1727)

这与 §2.3 的「5 次重复 + 标准差」是同一件事的两面：**报告均值而不报告方差，等于隐藏了不确定性**；而在方差很大的情况下，两个方法之间 1–2 个名次的差距可能完全落在噪声里。

### 5.3 超参数调优是隐藏的预算项

讲者以 REINVENT 为例说明调参的重要性。它有四个超参数：经验回放、学习率、批大小和 **sigma**。把 sigma 从 100 提高到 500，最终性能显著提升，而其他超参数影响不大。有意思的是，原始实现里的 sigma 值低于 100——也就是说，**仅仅调一个超参数，就能在原始实现基础上获得很大提升**。

![REINVENT 的超参数平行坐标图：sigma 一条线对最终分数的影响最大](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/01602.webp)

[【跳转到 26:42】](https://www.youtube.com/watch?v=OfdWayFibBU&t=1602)

sigma 是学习目标里 oracle 分数的权重，增大 sigma 意味着提高 oracle 分数的权重、增强优化能力。讲者用公式说明了 REINVENT 的目标：

$$
J(\Theta) = \left[ \sum_{t=0}^{T} \left( \log \pi_{\text{Prior}}(a_t, s_t) - \log \pi_{\Theta}(a_t, s_t) \right) + \sigma\, S(A) \right]^2
$$

其中 $\pi_{\text{Prior}}$ 是先验策略、$\pi_\Theta$ 是当前策略、$S(A)$ 是 oracle 分数。$\sigma$ 越大，模型越偏向「把分数刷高」。

问答里有人立刻指出这个权衡：**增大 sigma 会不会牺牲多样性？** 如果 top-100 全是同一个分子，那提高分数就是显然的。讲者承认：优化 top-K 分数通常意味着牺牲多样性分数，这一点他后面用热力图证实了（见 §5.4）。

### 5.4 多样性与优化能力的取舍

讲者报告了多样性分数（定义为所有分子对之间 1 减去 Tanimoto 相似度的平均值，相似度用 Morgan 指纹计算，范围 0 到 1）。结论是一个普遍趋势：**优化能力强的方法，多样性分数通常较差**。

![多样性热力图：优化能力强的列（左侧）颜色更暗，即多样性更低](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/01825.webp)

[【跳转到 30:25】](https://www.youtube.com/watch?v=OfdWayFibBU&t=1825)

讲者的判断是：优化能力可能是以牺牲多样性为代价的，而在真实的分子设计中需要在两者之间做权衡。问答里作者之一补充了一个更实用的理由（见 §6.3）：**因为 oracle 不完美，所以需要多样性来降低下游实验的失败率**。

## 六、从 oracle 分数到实验成功率

### 6.1 oracle 地形：不同任务适合不同方法

讲者对结果热力图做了层次聚类，发现相似的 oracle 会聚在一起（例如基于异构体的 oracle、基于相似性的 oracle 各自成群），而**不同地形更适合不同类型的方法**。

![oracle 地形热力图：行是 oracle、列是方法，聚类显示相似 oracle 成群，且不同群偏好不同方法](assets/PMO%20%E5%9F%BA%E5%87%86%EF%BC%9A%E5%88%86%E5%AD%90%E7%94%9F%E6%88%90%E7%9A%84%E9%87%87%E6%A0%B7%E9%A2%84%E7%AE%97%E4%B8%8E%E8%AF%84%E6%B5%8B%E8%AE%BE%E7%BD%AE/01544.webp)

[【跳转到 25:44】](https://www.youtube.com/watch?v=OfdWayFibBU&t=1544)

由此得出一个实践结论：**当你要优化某个任务时，首先要知道它属于哪一类 oracle 地形**。但讲者也坦白：如何用非常有限的实验数据判断地形，仍然是一个开放问题。这句话其实点出了整个评测体系的核心困难——**你手上的实验数据永远太少，不足以确定地形，于是「选对方法」本身就带有运气成分**。

### 6.2 基于模型 vs 无模型：增益依赖场景

讲者还比较了基于模型的方法（用代理模型引导搜索）与无模型方法。每个点是一个任务，横轴是无模型方法的表现，纵轴是基于模型方法的表现。结论是：**在高通量筛选这类场景中，基于模型的方法能提升表现**（几乎所有点都在虚线上方）；而在图层面遗传算法、GFlowNet 等场景中，有些点在虚线下方、有些非常贴近虚线，说明**基于模型的方法并不能带来性能增益**。

讲者的结论是：基于模型的方法有潜力更采样高效，但需要在内部循环、外部循环和预测模型上仔细设计。换句话说，**「加了代理模型就一定更好」是一个需要被评测检验的假设，而不是默认成立的事实**。

### 6.3 关键问答：oracle 不完美，所以要多样性

报告后段的问答里，一位作者给出了整场最实用的一段解释。有听众问：既然可以生成几千个分子，为什么还要关心多样性？直接用 top-100 分数不就行了吗？

作者的回答分两层：

1. **规模上要分清两类任务**。设计小分子时，现实中没人会去合成几千个分子，人们通常只挑少数几个去合成和测试，他见过的小分子发现里最多的也就几百个；上千个的通常是生物大分子，可以用并行肽合成之类的方案。所以「提出几千个分子」这个使用场景本身要打问号。
2. **多样性存在的真正理由是 oracle 不完美**。把一批分子送去下游实验验证，最重要的原因是当前使用的 oracle 有噪声，需要**降低失败率、降低提案中的假阳性率**。但最终我们其实只想要一个分子。所以分子设计算法的第一要求是优化能力，第二要求——只要 oracle 不完美——就是多样性；oracle 噪声越大，越应该把多样性纳入考虑。

这段问答把「评测」和「实验验证」连起来了：**oracle 分数是代理，代理有噪声，所以「只报 top-1」会系统性高估能力；而多样性是抵抗代理噪声的一种手段**。这也解释了为什么 PMO 一方面以优化能力为主指标，另一方面仍然报告 SA 与多样性。

### 6.4 关于筛选偏差的一个具体例子

讲者提到有些论文会综合衡量多样性与 top-K 分子，例如把多样性分数与 top-K 分数相乘作为最终指标。这实际上是在指标层面显式地惩罚「只报最优」的筛选偏差——因为一个方法如果靠反复筛选出同一个分子的近亲来刷分，它的多样性会很低，乘积就会惩罚它。

## 八、讲者的四条主要结论

讲者在结尾总结了 PMO 的主要观察：

1. 一些被认为很强的基线方法（例如基于 LSTM 的爬山法）**在数据使用上可能很低效**——它们在 top-K 上好看，在 AUC top-K 上掉队。
2. 一些较老的方法（REINVENT、图层面遗传算法）**超过了近期的方法**。
3. 除遗传算法外，**SELFIES 相比 SMILES 在优化性能上似乎并没有直接的好处**。
4. 基于模型的方法有潜力更采样高效，但需要在内部循环、外部循环和预测模型上仔细设计；**不同算法在不同任务上各有所长，这由 oracle 地形决定**，选哪个算法仍取决于具体用例和任务类型。

问答里，有听众把这一点类比为机器学习里的「没有免费午餐」定理：采样高效的分子优化，是否只有在你为分子选对了表示、并且选对了优化算法时才可能实现？讲者的回答是肯定的，但强调「具体问题具体分析」，他们没有找到能处理所有情况的方法。

另一个问答细节值得一提：有人问爬山法每一步大概加入多少新化合物，讲者的回答是「取决于经验法则，实践中每次迭代通常用几百个新成员」——这是一个**预算如何在方法内部被切分**的具体例子。

## 小结

- **采样预算必须进指标**：只报「最好的那个分子」，等于把 500 次调用和 20 万次调用混为一谈；AUC top-K 把「多高」和「多快」压成一个数。
- **oracle 的选择决定任务难度**：QED 这类人人能到顶的 oracle 没有区分度，logP 这类单调可刷的 oracle 会奖励「堆苯环」而不是「设计分子」。
- **统一实验设置才有横向比较**：同一数据库、每方法调超参、5 次独立重复并报标准差、同一套 oracle 集合、同一预算上限。
- **调参也是预算**：调超参数要消耗 oracle 调用；讲者的经验是调参至少需要 2000–3000 次调用才能看出趋势。
- **约束满足是独立维度**：合成可及性（SA）和多样性不能由分数替代；优化能力强的方往往牺牲多样性。
- **代理与实验之间有鸿沟**：oracle 是带噪声的代理模型，只报 top-1 会系统性高估能力；多样性是抵抗代理噪声、降低下游失败率的手段。
- **没有免费午餐**：不同 oracle 地形适合不同方法，如何用有限实验数据判断地形仍是开放问题。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| oracle | 可以给分子打分的黑箱函数（类药性、结合亲和力预测等），调用一次算一次预算 |
| oracle 调用次数 | 采样预算的计量单位，等价于「做了多少次虚拟筛选或测量」 |
| AUC top-K | 预算内每一步当前最优 K 个分子的平均分数对调用次数的曲线下面积，同时衡量「多高」和「多快」 |
| top-K | 跑完整个预算后最好的 K 个分子的平均分数，不反映到达速度 |
| QED | 类药性的经验规则打分，容易优化，很多方法都能到 0.948 的估计全局最优 |
| SA score | 合成可及性分数，越低表示越容易合成，属于「约束满足」类指标 |

| 爬山法（HC） | 每步只做局部微调的方法，top-K 好看但 AUC top-K 差，说明采样效率低 |
| oracle 地形 | oracle 函数在分子空间上的形状（多峰、平台、单调等），决定任务难度与适配方法 |
| 筛选偏差 | 只报告通过筛选的样本或只报最优结果，从而高估模型能力 |
