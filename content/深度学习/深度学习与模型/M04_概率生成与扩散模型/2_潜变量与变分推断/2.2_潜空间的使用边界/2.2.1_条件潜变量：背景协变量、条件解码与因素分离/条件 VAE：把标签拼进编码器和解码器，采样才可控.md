# 条件 VAE：把标签拼进编码器和解码器，采样才可控

> 视频来源：[VAE和CVAE原理简介以及代码实现](https://www.bilibili.com/video/BV1LgDzYME7c/)（Bilibili · 比奇堡最聪明的海星 · 约 18 分钟，PyTorch 代码实拍）
> 导读：这支视频用一个 MNIST 手写数字的 VAE 代码，演示了条件 VAE（cVAE）最朴素也最常见的实现：把 one-hot 标签 `c` 拼到编码器输入和**解码器输入**两处，于是同一个 `z` 在不同 `c` 下解码出不同的数字。本文只讲「条件怎么进去、进去后职责怎么分」，ELBO 与重参数化的推导见 2.1.9 与 2.1.10，本文只在必要处回指。

## 本讲要解决的核心问题（SCQA）

**背景**：VAE 训练好之后，从标准正态里采一个 $z$ 丢进解码器，就能生成一张像样的手写数字图。这是「无条件生成」——生成什么由采样运气决定。

**冲突**：可是我们经常想要「生成一批数字 1」，而不是「生成一批随便什么的数字」。无条件的 VAE 做不到这件事：它把「这是几」这一信息混在 $z$ 里，而 $z$ 是随机采的，我们没法指定。

**疑问**：如果「这是几」本来就是一个**已知**的量，为什么还要让它占用 $z$ 的容量、由采样去碰运气？能不能把这个已知量单独拿出来，作为条件直接喂给网络？

**回答（中心思想）**：能，而且改动极小——把条件 $c$ 做 one-hot 编码后**同时拼到编码器输入和解码器输入**上：编码器吃 $x \oplus c$，解码器吃 $z \oplus c$。这样一来，$c$ 负责回答「生成哪一类」，$z$ 负责回答「这一类里的哪一个」，采样时手动指定 $c$ 就得到可控的生成结果。视频里改的代码只有两行 `torch.cat`，以及编码器输入维度从 784 变成 784+10。

## 一、普通自编码器为什么「只会压缩，不会生成」

### 1.1 压缩包类比：编码器与解码器

视频开篇先退回到自编码器[【跳转到 00:17】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=17)。它的定义很朴素：拿一批数据，**不用打标签**，也能从数据本身学到东西。

作者用了一个很贴切的类比[【跳转到 01:10】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=70)：你有一个文件夹 A，把它打成一个很小的压缩包，再把压缩包发给我，我还能还原回原来的文件夹。这个「压缩—还原」的流程就是自编码器，中间那个压缩包就是**隐空间**（latent space）里的表示。

具体到手写数字[【跳转到 01:35】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=95)：一张图是 28×28、只有一个通道、只有黑白，没有 RGB，所以一共 $28 \times 28 = 784$ 个数。把它拉平成一行，就是 $1 \times 784$ 的向量。编码器用若干线性层把它压到更小的维度，解码器再把它恢复成 784 维。

![自编码器与 VAE 的对照：上半部分是「压缩—恢复」的一对一自编码器，下半部分是先从隐空间随机取样、再解码的 VAE](assets/条件%20VAE：把标签拼进编码器和解码器，采样才可控/00070.webp)

### 1.2 一对一的问题：反不了三

这个流程有一个大问题[【跳转到 02:25】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=145)：它只能做**一对一**的映射。丢进去什么，压缩出来什么，拿出来以后还是什么。

用作者的话说：我们学到知识其实是可以举一反三的，但它不行，它「反不了三」。隐空间里只有训练样本对应的那几个点是有意义的，点与点之间的区域解码出来是什么，没人保证。

### 1.3 VAE 的破局点：先采一个随机数，再解码

于是有人从概率的角度改造了它，这就是 VAE（Variational AutoEncoder，变分自编码器）[【跳转到 02:50】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=170)。核心思想是：**用计算机随机生成一组数据，丢进解码器，让它生成图片**。

要让这件事成立，做法是：编码器不再输出一个点，而是输出**均值**和**方差**，从这个高斯分布里采样一个 $z$，再送进解码器。这样隐空间里一大片区域都能解码出有意义的结果，生成才有可能。

### 1.4 采样不可导，于是有了重参数化

但直接「从学出来的分布里采样」在训练时行不通[【跳转到 04:08】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=248)：均值和方差是网络学出来的，你从中间再随机采一下，梯度就没法往回传了。

解决办法就是**重参数化技巧**（reparameterization trick）[【跳转到 04:33】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=273)：先从固定的标准正态里采一个噪声 $\varepsilon$，用方差算出标准差 $\sigma$，然后

$$
z = \mu + \sigma \odot \varepsilon
$$

分布上完全一样，但随机性被挪到了 $\varepsilon$ 上，$z$ 变成了 $\mu$ 和 $\sigma$ 的普通函数，梯度可以一路传回编码器。生成时则是反过来：直接随机采一个 $z$ 丢进解码器。

![重参数化的计算图：均值与协方差（标准差）分别与随机噪声相加、相乘，得到 z 再送入解码器](assets/条件%20VAE：把标签拼进编码器和解码器，采样才可控/00273.webp)

代码里这一段非常短[【跳转到 11:01】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=661)：

```python
def reparameterize(self, mu, log_var):
    std = torch.exp(0.5 * log_var)   # 由对数方差算标准差
    eps = torch.randn_like(std)      # 从标准正态采噪声
    return mu + eps * std            # z = mu + sigma * eps
```

```python
def decode(self, z):
    z = F.relu(self.fc4(z))
    return torch.sigmoid(self.fc5(z))  # 像素值在 0~1，用 sigmoid
```

![VAE 的 reparameterize 与 decode：解码器输出经过 sigmoid，因为 MNIST 像素值就是 0 到 1](assets/条件%20VAE：把标签拼进编码器和解码器，采样才可控/00681.webp)

损失函数是重建项加 KL 项[【跳转到 07:18】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=438)：重建项用 MSE 比较 `predict` 和原始 `data`（因为数据无标签，就是「它和它自己算」），KL 项用 `mu` 和 `log_var` 算。这两项的来历见 2.1.9，这里不重复推导。

## 二、无条件生成的局限：采样是随机的

训练完跑一遍生成[【跳转到 14:06】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=846)：随机采 10 个 $z$ 丢进解码器。第一波的生成结果还比较糊，随着训练慢慢清楚起来。但作者强调了一句关键的话——**「其实它是随机的，因为你没有设置条件」**。

这就是问题的起点。我们手里有一个能生成手写数字的模型，却没法说「给我来一批 1」。要想控制，就得把「这是几」这个**已知**信息显式地交给网络。

## 三、条件 VAE：两行 `torch.cat` 的改动

### 3.1 编码器吃 $x \oplus c$

作者的改法非常直接[【跳转到 15:06】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=906)：原来的输入是 784 维，现在往后**拼接**一个 label。手写数字是十分类，就加 10 维，也就是 one-hot 编码——比如数字 1 就是 `0100000000` 这种形式。

于是输入从 784 维变成 $784 + 10 = 794$ 维。相应地，编码器第一层的 `input_size` 要从 784 改成 784+10[【跳转到 16:43】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=1003)：

```python
# 编码器输入维度：784 + 10
self.fc1 = nn.Linear(input_size + 10, 512)
```

这正是视频里说的「相当于我给你拼接一点特征信息，就是**我告诉你我是谁**」。

### 3.2 解码器吃 $z \oplus c$

更关键的是解码器这一端[【跳转到 16:28】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=988)：**解码之前也要把标签拼一次**。也就是说，无论编码还是解码，网络都会拿到这个「你是谁」的限制条件。

完整的 `forward` 只有五行，是理解 cVAE 最省事的入口[【跳转到 15:31】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=931)：

```python
def forward(self, x, y):
    x = torch.cat([x, y], dim=1)          # 784 + label
    mu, log_var = self.encode(x)
    z = self.reparameterize(mu, log_var)
    z = torch.cat([z, y], dim=1)          # 隐变量 + label
    out = self.decode(z)
    return out, mu, log_var
```

![条件 VAE 的 forward：输入 x 与标签 y 先拼接再编码，采样出的 z 再与同一个 y 拼接后解码](assets/条件%20VAE：把标签拼进编码器和解码器，采样才可控/01003.webp)

对照 2.1.2 里的普通 VAE，差别只有两处 `torch.cat`。用概率的语言写出来就是：

$$
\text{普通 VAE：}\ p_\theta(x \mid z),\qquad \text{条件 VAE：}\ p_\theta(x \mid z, c)
$$

编码器一侧则从 $q_\phi(z \mid x)$ 变成 $q_\phi(z \mid x, c)$。注意后者的必要性没有前者那么强——条件 $c$ 完全可以只给解码器，编码器不给也行；视频里两边都给，是因为这样最省事、代码最对称。

### 3.3 采样时手动指定 $c$

生成阶段的改动同样只有一行[【跳转到 16:21】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=981)：随机采 $z$ 之后，**自己造一个标签**拼上去，再解码。

```python
sample_data = torch.randn(pic_num, latent_size).to(device)
sample_labels = torch.arange(10).long().to(device)      # 0-9 的标签
sample_labels_onehot = F.one_hot(sample_labels, num_classes=10).float()
sample_end = torch.cat([sample_data, sample_labels_onehot], dim=1)  # 连接图片和标签
sample_img = model.decode(sample_end)
```

注意这里把标签设成 `arange(10)`，也就是 0 到 9 各一个。所以生成出来就是整齐的 0 到 9，而不是随机的一堆数字[【跳转到 17:33】](https://www.bilibili.com/video/BV1LgDzYME7c/?t=1053)。

![条件生成的结果：给定 0 到 9 的标签，输出就是整齐的 0 到 9，而不是随机数字](assets/条件%20VAE：把标签拼进编码器和解码器，采样才可控/01078.webp)

作者还对比了普通 VAE 的采样结果：每一波都是随机的，五波下来没有规律。这就是「条件」带来的可控性——**同一批随机 $z$，换一个 $c$ 就换一个类别**。

## 四、$z$ 与 $c$ 的职责怎么分

把上面的机制翻译成职责划分，就是这张表：

| 量 | 是否已知 | 谁提供 | 负责回答的问题 |
| --- | --- | --- | --- |
| $c$（标签、批次、供体等） | 训练和生成时都知道 | 人工输入，one-hot 或嵌入 | 生成**哪一类** |
| $z$（潜变量） | 训练时未知，靠编码器推断 | 从先验采样，或编码器后验 | 这一类里的**哪一个** |

用同一个观测在不同条件下的生成图来检验这个分工最直观：固定 $z$ 不动、只把 $c$ 从 1 改成 7，输出就从「某个 1」变成「某个 7」，而笔迹粗细、倾斜角度这些「同一个 1 的不同写法」应当由 $z$ 承担。如果换 $c$ 之后连笔迹风格都跟着大变，说明 $z$ 和 $c$ 的职责没有分开。

这里要区分两件容易混为一谈的事：

- **条件建模**（本文讲的 cVAE）：承认 $c$ 会影响 $x$，于是把 $c$ 显式放进生成过程 $p(x \mid z, c)$，让模型去学「给定 $c$ 时 $x$ 长什么样」。$c$ 的影响**仍然存在**，只是被单独建模了。
- **去除已知背景**：把 $c$ 的影响从表示里**剥离掉**，希望 $z$ 里不再含 $c$ 的信息，从而在不同 $c$ 之间可比。

cVAE 做的是前者。它把 $c$ 交给解码器，间接减轻了 $z$ 记 $c$ 的压力，但**并没有强制** $z$ 与 $c$ 独立——这一点在下一节会看到后果。

## 五、两个容易踩的坑

### 5.1 把 $c$ 泄漏进 $z$

如果只把 $c$ 拼到编码器、忘了拼到解码器，会发生什么？解码器看不到 $c$，就只能从 $z$ 里把类别信息读出来，于是 $z$ 被迫编码「这是几」。这时 $z$ 和 $c$ 高度相关，采样时你给了解码器一个 $c$ 也没用——它根本不接收。

反过来，即使两端都拼了 $c$，$z$ 里仍然可能残留 $c$ 的信息：KL 项只是把 $q(z \mid x, c)$ 拉向标准正态，并没有约束 $z$ 与 $c$ 的互信息。这正是「条件建模不等于去除背景」的技术根源，也是后来自对抗去除、正交约束一类方法要解决的问题——它们的目标是让 $q(z \mid x, c)$ 在 $c$ 变化时尽量不变。本系列 2.2.2 会接着讨论「怎么证明 $z$ 真的分开了」。

### 5.2 条件分布与边缘分布混淆

第二个坑更隐蔽。cVAE 学的是**条件分布** $p(x \mid c)$：给定 $c=1$，它给你「1 的分布」。它**没有**直接学边缘分布 $p(x)$。

这意味着两件事：

1. 想得到「全体数字的分布」，必须自己按 $p(c)$ 把各个条件分布混合起来：$p(x) = \sum_c p(x \mid c)\, p(c)$。如果你在采样时把 $c$ 均匀地轮一遍，那实际上是在按均匀的 $p(c)$ 混合，而不是训练集里真实的类别比例。
2. 评估时也不能拿条件生成的样本去和「无条件分布的样本」直接比。条件生成的质量高，不代表无条件生成的质量高，反之亦然。

视频里那句「我限定了他是 0123456789」，恰好就是第一种情况的实例：作者手动指定了一个均匀的 $c$ 序列，所以输出是均匀的 0 到 9，而不是按 MNIST 真实频率分布的样本。

## 小结

- 自编码器只能一对一压缩—恢复，隐空间点与点之间是空白，所以「会压缩但不会生成」；VAE 把编码结果变成一个分布，再用重参数化让采样可导。
- 无条件 VAE 的采样是随机的，你没法指定生成哪一类，因为「这是几」被混在 $z$ 里由运气决定。
- 条件 VAE 的改动极小：把 one-hot 的 $c$ 拼到编码器输入（784→794）和**解码器输入**（$z \oplus c$）两处，生成时手动指定 $c$。
- 职责划分：$c$ 回答「哪一类」，$z$ 回答「这一类里的哪一个」；固定 $z$ 换 $c$，输出应当换类别而保留风格。
- 条件建模 $\neq$ 去除背景：cVAE 只是把 $c$ 显式建模，并没有强制 $z$ 与 $c$ 独立，$c$ 仍可能泄漏进 $z$。
- 条件分布 $\neq$ 边缘分布：$p(x) = \sum_c p(x \mid c) p(c)$，采样时 $c$ 的取法决定你实际在采哪个混合分布。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 自编码器（AE） | 编码器把输入压到低维隐空间、解码器还原，只优化重建误差，隐空间不可采样 |
| 变分自编码器（VAE） | 编码器输出均值与方差定义一个分布，采样后解码；损失为负 ELBO |
| 重参数化技巧 | 用 $z = \mu + \sigma \odot \varepsilon$ 把随机性挪到固定噪声上，使采样可导 |
| 条件 VAE（cVAE） | 把已知条件 $c$ 拼到编码器和解码器输入，学习 $p(x \mid z, c)$ |
| one-hot 编码 | 把 $K$ 类标签写成 $K$ 维向量，只有对应位置为 1，其余为 0 |
| 条件分布与边缘分布 | $p(x \mid c)$ 是给定 $c$ 的分布，$p(x)$ 是把 $c$ 混合掉之后的分布 |
| 条件建模与去除背景 | 前者把 $c$ 显式放进生成过程，后者要求 $z$ 不含 $c$ 的信息 |
