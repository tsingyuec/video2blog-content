# 稀疏注意力与 Infini-attention：改变可见性，还是改变函数形式？

> 视频来源：[【10】Sparse Attention & Infini Attention 稀疏注意力和无限注意力](https://www.bilibili.com/video/BV1ErPkeSEND/)（B 站 · LLM张老师 · 时长约 35 分钟）
> 本文基于视频演说图文稿整理，配图截取视频幻灯片。这支视频把两条常被混为一谈的路线摆在一起：**稀疏注意力只是少算一些格子**，**Infini-attention 干脆换掉了注意力的算法**。看懂这个区别，就能判断一个"高效注意力"到底动了模型的哪根神经。

## 本讲要解决的核心问题（SCQA）

**背景**：注意力的核心运算是 $QK^\top$，得到一个 $N\times N$ 的分数矩阵；此外解码时还要为每层缓存 K 和 V（KV cache），显存随窗口长度线性增长。

**冲突**：想把上下文从 4K 拉到 100 万 token，$N^2$ 的分数矩阵先撑不住——矩阵一大，矩阵乘法就慢，显存还会溢出；KV cache 随窗口线性涨，多层叠加后增长更猛。

**疑问**：稀疏注意力到底省掉了什么？它和 FlashAttention 那种"算得更快但结果不变"的优化是一回事吗？Infini-attention 号称百万级上下文，它凭什么能做到"无限"？

**回答（中心思想）**：这两条路动的不是同一个东西。**稀疏注意力改的是"可见性"**——它仍然算 softmax 注意力，只是规定每个 token 只能看见一部分位置（随机、邻近、全局），于是 $N\times N$ 里大部分格子根本不计算，代价是信息丢失。**Infini-attention 改的是"函数形式"**——它把历史压成一个 $d\times d$ 的摘要矩阵，用 $Q(K^\top V)$ 代替 $(QK^\top)V$，从此不再有 $N\times N$ 的两两分数，代价是只能"记住摘要"而无法"逐字回看"。前者是同一个函数的稀疏采样，后者是另一个函数。

---

## 一、先把两笔账摆出来

### 1.1 第一笔账：$N\times N$ 的分数矩阵

设序列长度为 $N$、每个 head 的维度为 $d$：

$$
S=QK^\top\in\mathbb{R}^{N\times N},\qquad O=\mathrm{softmax}(S)V
$$

$N$ 从 1K、4K、8K、2 万一路涨到 100 万时，$S$ 的元素个数按 $N^2$ 增长。讲者的说法很直白：**这个方形矩阵是长上下文最要命的瓶颈**，矩阵一长，乘法就慢，最终显存溢出 [【跳转到 00:25】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=25)。

### 1.2 第二笔账：KV cache 随窗口线性增长

解码时每一步都要用到历史所有 token 的 K 和 V，所以要缓存。K 一份、V 一份，**每层 Transformer 各有一份自己的缓存**——层数一乘，增长就是"暴涨"级别 [【跳转到 09:09】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=549)。

### 1.3 一个具体场景：三体十章

讲者用小说举例：假设《三体》有 10 章、每章 1 万 token，而训练/推理窗口只有 1 万。

- 训练第二章时，模型看不到第一章的任何信息；
- 训练第三章时，前两章都没了；
- 写作时第一章出现过的人名，第二章只提一次，第三章再出现，模型就"蒙了"——它不知道这个名字是谁。

要想不遗忘，就得把窗口拉到"从第一章到当前章"那么大。但窗口一大，1.1 与 1.2 两笔账同时爆掉。**所有高效注意力方法，本质上都是在回答"这两笔账怎么还"** [【跳转到 07:29】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=449)。

## 二、稀疏注意力：只算一部分格子（改可见性）

稀疏注意力的做法朴素到近乎粗暴：既然 $N\times N$ 里大部分格子不重要，那就**挑一部分算**。

### 2.1 第一步：随机 token

![第一步 random tokens：在 N×N 矩阵里随机挑一些行列交叉点计算，幻灯片里高亮的部分约占 15%](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/00077.webp)

在 $QK^\top$ 里随机选一些行和列，只算这些交叉点。比例可以设成 15% 之类——**只计算 15% 的注意力分数**，其余格子直接当作不存在 [【跳转到 01:17】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=77)。

### 2.2 第二步：窗口 token

![第二步 window tokens：把注意力集中在主对角线附近的带状区域，即每个 token 只看自己前后最近的若干 token](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/00102.webp)

矩阵的主对角线是"自己关注自己"，通常分数最高；紧邻的对角带是"隔壁的文字"，距离越近越重要。于是把这条带子算满——窗口可以是一两百个 token，而不是两三个 [【跳转到 02:07】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=127)。

> 窗口注意力的具体机制（滑动窗口如何移动、KV cache 如何用 rolling buffer 循环覆盖）已在 [§8.3.1 滑动窗口注意力与滚动缓存](../../../README.md#m02-8-3-1) 讲透，这里只把它当作稀疏模式的一种，不重复展开。

### 2.3 第三步：全局 token

![第三步 global tokens：让少数几个 token（矩阵最左一列与最上一行）与所有位置互相可见，充当全局信息汇聚点](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/00197.webp)

全局 token 表现为"左边一列 + 上面一行"全部算满：被选中的那几个 token 关注所有位置，同时被所有位置关注。讲者留了个小作业——从 $QK^\top$ 的行列含义出发，想清楚为什么全局性体现为一行加一列 [【跳转到 02:47】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=167)。

### 2.4 三者相加就是 BigBird

![三种稀疏模式相加：random + window + global 得到 BigBird 的注意力矩阵，与 Full Attention 相比稀疏很多但保留了关键连接](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/00377.webp)

把三种模式叠加，就得到谷歌论文里的 **BigBird** 注意力矩阵。讲者还给了图论视角：全注意力是每个词与所有词连线的"戴森球"；随机注意力是随机连几根线；窗口注意力是一圈相邻连线；全局注意力是一个星形（中心节点连所有节点）。三者相加，就是 BigBird 那张"稀疏但抓住重点"的图 [【跳转到 05:52】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=352)。

### 2.5 代价：丢信息，靠多头兜底

稀疏注意力的收益是计算量大幅下降，代价写在同一句话里：**同时也丢失了一些信息**。讲者给了两条缓解理由：

- 精度要求不高、词与词之间依赖不强的任务，挑重点做总结就够了；
- 别忘了还有多头——某些头看漏的信息，别的头可能抓住 [【跳转到 03:17】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=197)。

**关键判断**：稀疏注意力算的仍然是 softmax 注意力，只是把"不该看的格子"置为不可见。函数形式没变，变的是**可见性假设**——它承认"我看不全"，并把这个假设写进模型结构。

## 三、Infini-attention：把历史压成摘要（改函数形式）

### 3.1 两个核心部件

![Infini-attention 的两条主线：左侧 Infini-Transformer 在每层挂一块压缩记忆，右侧把"压缩记忆检索"与"段内因果注意力"拼接后做线性投影](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/00768.webp)

Infini-attention 的逻辑只有两条：

1. **压缩记忆（compressed memory）**：每层 Transformer 都保存一块自己的记忆，把处理过的历史压缩进去；
2. **线性获取（linear access）**：用当前 Query 去读这块记忆，读出的是"摘要"而不是原始 token。

注意"每层一份记忆"这一点——和 KV cache 一样按层分布，但**大小是恒定的**，不随上下文长度增长 [【跳转到 09:48】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=588)。

### 3.2 分段训练：记忆怎么传下去

假设窗口 4K，把长文档切成 Segment 1、Segment 2……依次喂入：

- 处理 Segment 1 时正常算段内注意力，结束后把这段的 K、V 压缩成记忆；
- 处理 Segment 2 时，除了段内 $QK^\top$，还要用当前 Q 去检索上一段留下的记忆，把两部分结果**拼接**（concat）后做一次线性投影；
- 段末再把 Segment 2 的内容并入记忆，供下一段使用。

于是训练第二章时模型能"看到"第一章的摘要，训练第三章时能看到前两章的摘要。讲者的说法是：这相当于把历史信息一直带着走，而不是每段重新开始 [【跳转到 11:08】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=668)。

### 3.3 关键一步：先算 $K^\top V$，再乘 $Q$

![线性注意力与点积注意力的结构对比：右边把 K 与 V 先乘成 d×d 的全局上下文向量，再与 Q 相乘，省掉 N×N 的两两相似度矩阵](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/00903.webp)

这套机制来自线性注意力（linear attention）论文。两种计算顺序：

$$
\text{标准：}\ O=(QK^\top)V \qquad\text{线性：}\ O=Q\,(K^\top V)
$$

![矩阵形状对比：上面先算 Q@K 得到 4096×4096 的大矩阵，下面先算 K@V 得到 512×512 的小矩阵，再乘 Q 仍然得到 4096×512 的输出](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/01129.webp)

形状一摆就清楚了。取 $N=4096$、$d=512$：

- 标准顺序：$QK^\top$ 是 $4096\times4096$（约 1600 万个元素），再乘 V 得 $4096\times512$；
- 线性顺序：$K^\top V$ 是 $512\times512$（约 26 万个元素），再乘 Q 仍得 $4096\times512$。

输出形状一模一样，中间矩阵小了两个数量级。而且 $K^\top V$ 这个矩阵**可以增量累加**——新来一段就把它的 $K^\top V$ 加进去，这正是"压缩记忆"的物理形态 [【跳转到 16:43】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=1003)。

### 3.4 它到底是不是"等价"？

讲者在这里非常克制，值得照抄他的措辞：

- 如果**不加 softmax、不做归一化**，纯矩阵运算下两种顺序是**数学恒等**的；
- 但真实注意力里有 softmax、有 $1/\sqrt{d}$、有因果掩码——这些一加，两种顺序就**不再恒等**，论文的说法是"应用 softmax 之后结果极其近似"。

所以线性注意力不是"换个顺序算同一个东西"，而是**用另一个函数去近似原函数**。这是它与 FlashAttention 的根本区别：FlashAttention 的结果逐元素等价，线性注意力只是相近 [【跳转到 17:33】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=1053)。

### 3.5 为什么能"无限"

记忆矩阵 $K^\top V$ 的大小是 $d\times d$，与序列长度无关；每来一段就累加一次，显存占用恒定。于是理论上可以一直累积下去——**有限的 GPU 显存下实现无限长的记忆累积**，这就是 Infini-attention 名字的由来 [【跳转到 25:54】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=1554)。

讲者提到谷歌 Gemini 1.5 的百万级上下文（Pro 版本约 200 万）很可能就建立在这类机制上，并强调这是他的推测；同时给出一个实用的观察：线性注意力**不需要从零预训练**，可以在已有基座模型上做全参数微调，把压缩记忆"学"出来 [【跳转到 26:54】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=1614)。

### 3.6 代价：只剩摘要，没有逐字回看

局限同样明确：把历史压成摘要，就意味着**不可能对第一章的每个字都保持关注度**，只能对"第一章的重点总结"保持关注度。信息丢失不可避免。讲者还提醒，厂商发布会上"在 100 万 token 里大海捞针"的演示往往针对任务做过优化，自己实测未必有那么好 [【跳转到 28:09】](https://www.bilibili.com/video/BV1ErPkeSEND/?t=1689)。

## 四、长上下文技术栈：谁改计算，谁改假设

![讲者总结的超长上下文技术组合（截至 2024 年 5 月）：小窗口预训练加大窗口微调、稀疏注意力、FlashAttention、MQA/GQA、Infini-attention、MLP 路由、更大 GPU、temp-lora](assets/稀疏注意力与%20Infini-attention：改变可见性，还是改变函数形式/01784.webp)

视频最后把这几年拉长上下文的手段列成一张清单。把它按"改了什么"重新归类，本小节的分界线就一目了然：

| 技术 | 做法 | 改变了什么 | 结果是否与全注意力一致 |
| --- | --- | --- | --- |
| 小窗口预训练 + 大窗口微调 + ALiBi/RoPE | 训练用 4K 省钱，微调时放大到 50K 并换位置编码 | 训练策略与位置外推 | 一致（同一函数，只是窗口变大） |
| FlashAttention | 分块 + online softmax，不落地 $N\times N$ | 计算顺序与访存 | **逐元素一致** |
| MQA / GQA | 多个 Query 头共享 K/V 头 | KV cache 的形状与体积 | 近似（表达能力略降） |
| 稀疏注意力（BigBird 类） | 只算随机、窗口、全局三类格子 | **可见性** | 不一致（少看了一部分） |
| Infini-attention | 历史压成 $d\times d$ 记忆，$Q(K^\top V)$ | **函数形式** | 不一致（换了算法） |
| MLP 路由（大小隐藏层） | 简单请求走小 FFN，复杂请求走大 FFN | FFN 的宽度选择 | 近似 |
| 换更大更新的 GPU | 加显存、加带宽 | 什么也没改 | 一致 |
| temp-lora | 边推理边把上下文写进临时 LoRA 权重，用完丢弃 | 权重（临时适配器） | 近似 |

这张表最有用的地方是最后两列：**只有"改计算"和"加硬件"能保证结果不变**；凡是动了可见性、函数形式、KV 形状或权重的，都在用精度换长度。

## 五、一条可操作的判据

遇到一个新的"高效注意力"，问三个问题就能归类：

1. **它还算 softmax 吗？** 如果每个输出仍是"对一组可见位置的分数做 softmax 加权"，那它改的是可见性（稀疏）；如果它把分数矩阵整个绕开（$K^\top V$ 摘要、核函数替换 softmax），那它改的是函数形式。
2. **$N$ 翻倍时结果逐元素不变吗？** 不变 = 精确分块（FlashAttention 一类）；变了 = 稀疏或近似。
3. **代价记在哪本账上？** 稀疏注意力省的是分数矩阵的格子数；线性/压缩记忆省的是中间矩阵的阶数；FlashAttention 省的是 HBM 流量。三本账不能混着记。

## 小结

- 长上下文有两笔硬账：$N\times N$ 的分数矩阵，以及按层线性增长的 KV cache。
- 稀疏注意力是"少看一些格子"：随机 token（如 15%）、窗口 token（对角线带）、全局 token（一行加一列），三者相加就是 BigBird。它算的仍是 softmax 注意力，改的是**可见性**，代价是丢信息，靠多头兜底。
- Infini-attention 是"换一种算法"：每层维护一块恒定的压缩记忆，用 $Q(K^\top V)$ 代替 $(QK^\top)V$，$d\times d$ 的摘要取代 $N\times N$ 的两两分数。
- 两种计算顺序只在**没有 softmax、没有归一化**时数学恒等；加上 softmax 后只是"极其近似"——所以线性注意力改的是**函数形式**。
- 记忆大小恒定，所以理论上可以无限累积；但只能记住摘要，无法对早期 token 逐字回看，信息丢失不可避免。
- 判据：**结果是否逐元素不变**。不变的是精确分块与硬件升级；变了的是稀疏（改可见性）与线性/压缩（改函数形式）。
