## 本讲要解决的核心问题（SCQA）

**背景**：自注意力已经很好用了——每个词都和同一句话里的其他所有词作比较，把上下文汇聚到自己身上。前提是我们手上已经有完整的一句话。

**冲突**：翻译任务里，手上不再只有一个序列，而是两个：一边是英语原句，一边是正在逐词生成的法语句。自注意力连接的是同一个句子内部的词，可翻译要做的恰恰是把两个不同句子之间的词连起来。更麻烦的是，解码器是逐词往外生成的，它自己的表示里只有"到目前为止"的信息，看不到原句里哪个词跟自己相关 [【跳转到 00:00】](https://www.bilibili.com/video/BV12Ut165Edd/?t=0)。

**疑问**：一个序列里的词，怎么知道另一个序列里哪些词跟自己相关？信息到底是从哪一边流到哪一边的？

**回答（中心思想）**：交叉注意力只改一件事——**Query 来自解码器（目标序列），Key 和 Value 来自编码器（条件序列）**。解码器用自己当前的隐藏状态提出一个问题（"我现在需要原句里的什么"），编码器早就把整句英语压成了 Key 和 Value，于是这个问题去和每个英语词的 Key 比对、按权重把对应的 Value 取回来。公式一个字没变，变的是三个矩阵的来源；正是这个来源区分，让"条件序列"的信息能按需、逐词地流进"目标序列" [【跳转到 06:42】](https://www.bilibili.com/video/BV12Ut165Edd/?t=402)。

## 一、先把两个序列摆到一张图上

### 1.1 编码器：一次性读完整个条件序列

设输入句子是 "The black cat slept"。编码器把整句一次性处理完——**这里没有因果掩码**，每个位置都能看到整句话。经过一层层自注意力和全连接网络，每个 token 都从周围的词那里获得含义，最终每个词的表示既反映自己的意思，也反映周围所有词的意思 [【跳转到 00:44】](https://www.bilibili.com/video/BV12Ut165Edd/?t=44)。

![翻译任务里有两个序列：左边是英语原句，右边是正在生成的法语译文](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00025.webp)

这一步的产物，就是后面要反复用到的"条件序列表示"。视频里把它记作矩阵 $H$，每一行是一个英语词的上下文向量。

### 1.2 解码器：一个词一个词地生成目标序列

解码器从特殊的 BOS token 出发，预测出第一个法语词；这个预测结果再被送回解码器，用来生成下一个词，如此重复直到整句生成完毕 [【跳转到 01:14】](https://www.bilibili.com/video/BV12Ut165Edd/?t=74)。解码器一侧是**带掩码的自注意力**：每个位置只能往回看，看不到还没出现的词。

![编码器—解码器架构：左侧编码器没有因果掩码，右侧解码器先做带掩码的自注意力](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00044.webp)

### 1.3 直接把编码器输出塞给解码器，为什么不行

最朴素的做法是：把编码器的输出直接交给解码器，让它在每一步生成时都使用。问题立刻出现——**每一步解码拿到的信息都完全一样**，这个句子的表示永远不会变，于是每个法语词看到的都是同一份固定上下文 [【跳转到 01:39】](https://www.bilibili.com/video/BV12Ut165Edd/?t=99)。

可不同的词需要的恰恰是不同的信息：生成"黑"对应的法语词时，模型应该聚焦在 "black" 上；生成"睡着"对应的法语词时，就该聚焦在 "slept" 上。下图把这件事画得很清楚：横轴是原句的四个英语词，每一根柱状图对应一个正在生成的法语词，柱子高低就是它此刻的关注分布——"noir"（黑）那一列明显压在 "black" 上。

![逐词变化的关注点：生成 noir 时注意力集中在 black，生成 chat 时集中在 cat](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00124.webp)

所以需要的不是"一份固定的上下文"，而是**每个目标位置自己去取一份定制的上下文**。这就是交叉注意力要解决的问题 [【跳转到 02:04】](https://www.bilibili.com/video/BV12Ut165Edd/?t=124)。

## 二、来源分工：谁提问，谁作答

### 2.1 一句话记住分工

进入交叉注意力层之前，先捋清信息怎么流：**编码器的输出被映射成 Key 和 Value；解码器把当前已知的全部信息转换成一个 Query** [【跳转到 02:44】](https://www.bilibili.com/video/BV12Ut165Edd/?t=164)。

这个 Query 本质上就是解码器提出的一个问题：*针对我现在正在生成的这个词，我到底需要从英语句子里拿到什么？* 当某个 Query 和某个 Key 匹配得很好时，模型就更关注那个词的含义——它就是靠这个从原句里提取出正确的信息 [【跳转到 03:09】](https://www.bilibili.com/video/BV12Ut165Edd/?t=189)。

![交叉注意力层的数据流：编码器输出以 K、V 进入，解码器自己提供 Q](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00222.webp)

把它和自注意力对照着记，差别只有一处：

| | Query 来自 | Key / Value 来自 | 注意力矩阵形状 |
| --- | --- | --- | --- |
| 自注意力 | 同一序列 | 同一序列 | $n \times n$（方阵） |
| 交叉注意力 | 目标序列（长度 $m$） | 条件序列（长度 $n$） | $m \times n$（可非方阵） |

表格里那个"可非方阵"是交叉注意力最实用的性质，第四节会专门讲。

### 2.2 为什么带掩码的自注意力必须排在交叉注意力前面

这里有个容易被跳过的问题：为什么不直接跳到交叉注意力去看编码器输出，非要先做一遍带掩码的自注意力？

因为 **Query 决定了解码器能从编码器那里拿到什么信息**。如果解码器没有先处理它已经生成的那些词，这个 Query 就没有足够的上下文，问不出正确的问题。带掩码的自注意力帮解码器先搞清楚"我在句子的哪个位置、前面已经说了什么"，然后才向交叉注意力提出 Query [【跳转到 03:17】](https://www.bilibili.com/video/BV12Ut165Edd/?t=197)。

![解码器块内顺序：Masked Multi-Head Attention → Add and Norm → Cross-Attention → Add and Norm → FFN](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00164.webp)

换句话说，解码器块里两个注意力子层的分工是：**带掩码的自注意力负责"整理我要问什么"，交叉注意力负责"去条件序列里取答案"**。

## 三、矩阵层面走一遍：形状怎么对上

### 3.1 解码器侧：从隐藏状态 $X$ 到 $Q$

掩码自注意力那一层的输出是一个隐藏状态矩阵 $X$，每个法语 token 占一行，每一行是维度为 $d_{\text{model}}$ 的向量，浓缩了解码器对这个 token 及其上下文的全部了解。视频里为了方便演示取 $d_{\text{model}}=4$，所以四个法语 token 每个用一个四维向量表示——不管实际是 512 还是 1024，思路完全一样 [【跳转到 04:03】](https://www.bilibili.com/video/BV12Ut165Edd/?t=243)。

关键一步：**不把 $X$ 直接送进注意力，而是先乘一个训练好的权重矩阵 $W_Q$**：

$$
Q = X W_Q, \qquad X \in \mathbb{R}^{m \times d_{\text{model}}},\; W_Q \in \mathbb{R}^{d_{\text{model}} \times d_k}
$$

$W_Q$ 的维度是 $d_{\text{model}} \times d_k$，其中 $d_k$ 是 key 向量和 query 向量的维度。单头系统里 $d_k$ 直接等于 $d_{\text{model}}$，所以这里是 $4 \times 4$。实际 Transformer 并行使用多个头时，$d_k$ 会缩小成 $d_{\text{model}}$ 除以头数，让每个头专注嵌入空间里属于自己的那一段 [【跳转到 05:18】](https://www.bilibili.com/video/BV12Ut165Edd/?t=318)。

![Q = X·W_q：解码器隐藏状态 4×4 乘上 4×4 的查询权重，得到 4×4 的 Q](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00293.webp)

留意维度为什么能对得这么齐：$X$ 是 $4 \times d_{\text{model}}$，$W_Q$ 是 $d_{\text{model}} \times d_k$，内部维度刚好抵消，得到的 $Q$ 就是 $4 \times 4$——每个解码器 token 对应一个 query 向量。

### 3.2 编码器侧：从 $H$ 到 $K$ 和 $V$

解码器在生成 Query 的同时，编码器正忙着处理完整的英语句子，产出矩阵 $H$——每一行是某个英语词的含义概括，还补充了它周围所有其他词的信息。和 $X$ 投影成 Query 一样，**$H$ 被投影成两个不同的东西**：Key 矩阵 $K$ 和 Value 矩阵 $V$，分别由独立的权重矩阵 $W_K$、$W_V$ 负责，两者都在训练中学出来，各有各的用途 [【跳转到 06:17】](https://www.bilibili.com/video/BV12Ut165Edd/?t=377)。

![同一个编码器输出 H 乘两套不同的权重，分别得到 Key 和 Value](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00377.webp)

一句话总结：**输入 Query 来自解码器，Key 和 Value 来自编码器**——这正是交叉注意力的关键区别。

### 3.3 三个矩阵相乘

三个矩阵齐了，后面就是熟路：先算 $QK^{\top}$ 得到分数网格，每个数字表示"这个 Query 和那个 Key 匹配得有多好"；分数越高，匹配越紧，注意力就越往那边集中 [【跳转到 07:07】](https://www.bilibili.com/video/BV12Ut165Edd/?t=427)。维度变大时点积方差会跟着变大，所以要除以 $\sqrt{d_k}$——这一步的理由与自注意力完全相同，跳过它 softmax 会被推到极端、梯度消失、训练崩掉。

softmax 把缩放后的分数变成真正的注意力权重，每一行的和等于 1，也就是把注意力分配到所有英语 token 上 [【跳转到 07:32】](https://www.bilibili.com/video/BV12Ut165Edd/?t=452)。

![softmax 之后的交叉注意力权重矩阵：行是法语 token，列是英语 token，每行和为 1](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00452.webp)

只看其中一行：法语词 "chat" 拿自己的 Query 去和每个英语 Key 比较，softmax 之后最大的权重落在 "cat" 上，比其他词都高 [【跳转到 07:57】](https://www.bilibili.com/video/BV12Ut165Edd/?t=477)。

![单行注意力分布：chat 对 cat 的权重 0.75，对 The / black / slept 分别只有 0.05 / 0.10 / 0.10](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00477.webp)

值得停下来想一下：模型根本不知道什么是法语、什么是英语，但它正在学会把两种完全不同的语言里的词正确对应起来。**注意力告诉我们"该往哪儿看"，而我们真正取走的是那些位置上的含义**——最后一步把注意力权重乘上 $V$，做加权求和，得到上下文矩阵 $Z$，每一行就是解码器为某个法语词从英语句子里提取出来的内容 [【跳转到 08:22】](https://www.bilibili.com/video/BV12Ut165Edd/?t=502)。

说到底还是同一套数学，只是从一个序列扩展到了两个序列。实际中和自注意力一样，这一步会并行做很多次：每个头有自己的一套权重，自然学会关注不同类型的关联；最后把所有头的输出合并成一个向量，再做一次线性投影交给下一层 [【跳转到 09:12】](https://www.bilibili.com/video/BV12Ut165Edd/?t=552)。

## 四、序列长度不同时，怎么"对上号"

### 4.1 注意力矩阵不是方阵

交叉注意力最容易被忽略、也最重要的一点：**Query 的个数由目标序列长度决定，Key 的个数由条件序列长度决定，两者不必相等**。所以注意力矩阵是 $m \times n$，不是方阵。

视频最后给了一个真实例子：英语句子四个词，法语翻译却有五个词 [【跳转到 09:37】](https://www.bilibili.com/video/BV12Ut165Edd/?t=577)。

![四个英语词对五个法语词：注意力连线不是一对一，而是按语义对齐](assets/交叉注意力：Query%20由解码器发问，Key%20与%20Value%20由编码器作答/00577.webp)

### 4.2 对齐可以是多对一

从这张图能读出两种对齐模式：

1. **近似一对一**：解码器生成第一个 token 时，它的 Query 很明确地对应上输入句子的第一个词；生成下一个 token 时，注意力转移到下一个相关的词。
2. **一对多**：有时候意思并不是一一对应的，英语里的一个概念在法语里可能要拆成好几个 token，这时注意力就会分散到输入里那一整段词上。

这也解释了为什么不能用一个固定的"句子向量"代替整套 Key/Value：对齐关系本身就是**因位置而异、因语言而异**的，只能让模型在每一步自己算。

### 4.3 因果掩码在这一层就不需要了

长度不同还带来一个结构上的差别：**交叉注意力这一层不需要因果掩码**。

视频里已经交代过，编码器处理整句时"没有因果掩码"，每个英语词都能看到整句话 [【跳转到 00:44】](https://www.bilibili.com/video/BV12Ut165Edd/?t=44)。既然条件序列在进入这一层之前就已经被完整读完，Key 和 Value 里不存在"还没发生的词"，那么 Query 去和所有 Key 比对就没有任何信息泄漏问题。

因果掩码只属于解码器自己的那个带掩码自注意力子层，作用是挡住"未来"的目标 token。所以看到交叉注意力时不要条件反射地去找下三角矩阵：**这一层挡的是目标侧的未来，而不是条件侧的可见性**。

## 五、把"来源分离"当成一个模板

这支视频只讲了翻译，但它给出的其实是一个**可复用的模板**：公式不用改，只要换掉"谁提供 Query、谁提供 Key/Value"，同一个层就能干别的事。翻译里是"解码器问、编码器答"；换到别的任务，只要有一个"要生成的东西"和一个"用来约束它的条件"，就可以把前者当 Query、后者当 Key/Value。

同一小节另一篇《把文本条件注入图像：Query 取图像，Key 与 Value 取文本》走的就是这个模板——那里 Query 来自图像 patch，Key/Value 来自文本编码器，公式一模一样，只是"谁提问"换了角色。

## 小结

- 交叉注意力与自注意力的**唯一区别是三个矩阵的来源**：Query 来自目标序列（解码器），Key 和 Value 来自条件序列（编码器）。
- 直接复用一份固定的编码器输出不行，因为不同目标位置需要不同的上下文；Query 就是"按需索取"的机制。
- 解码器块里顺序不能颠倒：**先带掩码自注意力整理出问题，再交叉注意力去取答案**。
- 形状上 $Q \in \mathbb{R}^{m \times d_k}$、$K \in \mathbb{R}^{n \times d_k}$、$V \in \mathbb{R}^{n \times d_v}$，注意力矩阵是 $m \times n$，**两个序列长度可以不同**。
- 长度不同带来的是"软对齐"：可以近似一对一，也可以一个概念对上一整段词。
- 交叉注意力层不需要因果掩码：条件序列已经完整读完，因果掩码只属于解码器自己的自注意力子层。
- 这套机制的模板是"一个要生成的东西 + 一个约束它的条件"：前者当 Query，后者当 Key/Value。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 交叉注意力（cross-attention） | Query 来自一个序列、Key/Value 来自另一个序列的注意力，用于把条件信息注入目标序列 |
| 条件序列（condition sequence） | 提供 Key/Value 的那一侧，如翻译里的原句、文生图里的文本提示 |
| 目标序列（target sequence） | 提供 Query 的那一侧，如正在逐词生成的译文、正在去噪的图像 patch |
| 编码器输出 $H$ | 条件序列经过双向自注意力后的上下文表示，每行一个 token |
| 解码器隐藏状态 $X$ | 目标序列经过带掩码自注意力后的表示，是 Query 的来源 |
| $W_Q, W_K, W_V$ | 三个独立的学习权重，把 $X$ 或 $H$ 投影到注意力的子空间 |
| 软对齐（soft alignment） | 注意力权重给出的、可多对一的对齐关系，不需要两个序列等长 |
