# MoE 稀疏激活：门控网络如何为一个 token 挑出 Top-2 专家

> 视频来源：[一个 token 是怎么穿过 MoE 的？手撕混合专家模型的前向传播全过程](https://www.bilibili.com/video/BV16XDYBXEdb/)（Bilibili · 作者武辰）｜时长约 27 分钟
> 导读：UP 主用一张纸、一支笔，把「我爱吃苹果」里一个 token 的向量（四维，`[0.1, 0.2, 0.3, 0.4]`）手工推过一遍 MoE 层：先算稠密 FFN 的参数账，再画门控网络给八个专家打分，取 top-2、重新归一化、加权求和，最后算总参数量与激活参数量。本文按这条手算链路整理，并补上视频后半段讲的两个坑——显存不会因为稀疏而变小、专家会坍缩。字幕中的口误（`deepsick`、`getit 网络`、`8 7B` 等）已按上下文订正；视频里没有给出 softmax 公式，本文用标准写法把他说到的「分数加起来等于一」补成可计算的式子。

## 本讲要解决的核心问题（SCQA）

**背景**：Transformer 的每一层由自注意力和 FFN（前馈网络，也就是全连接层）两部分组成，而参数量的大头在 FFN 上。一个 7B 模型，FFN 的中间维度是 4096 到 6144，一层 FFN 就有三亿左右的参数。

**冲突**：想让模型更聪明，最直接的办法是把 FFN 加宽——比如把中间 6 个神经元换成 12 个。但参数量翻倍的同时，**每个 token 的计算量也一起翻倍**。参数和算力被绑死在一起，这条路很快就走不动。

**疑问**：有没有一种结构，能让参数量翻倍、甚至翻很多倍，但每个 token 实际参与计算的那部分参数不跟着涨？

**回答（中心思想）**：MoE（Mixture of Experts，混合专家）把一个大 FFN 拆成 $N$ 个结构相同、参数不同的「专家」，再加一个很小的**门控网络（gating network，也叫 router）**：它给每个 token 打出 $N$ 个分数，只保留分数最高的 $k$ 个专家，把这两个专家的输出按分数加权求和。于是**参数量随 $N$ 增长，单 token 计算量只随 $k$ 增长**——这就是「稀疏激活」。[【跳转到 04:15】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=255)

## 一、先把稠密 FFN 的参数账算清楚

### 1.1 一个四维的小例子

UP 主把维度压到 4 维来讲，因为「维度大小不影响数学的本质，只是方便看懂」[【跳转到 01:12】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=72)。假设「I」这个词的向量是：

$$
x = [0.1,\ 0.2,\ 0.3,\ 0.4]
$$

Transformer 里的 FFN 是一个「先升维再降维」的过程：4 个神经元 → 6 个神经元 → 4 个神经元。

### 1.2 参数量怎么数

拿中间第一个神经元举例：它把输入的四个数各乘一个权重再求和。假设四条线的权重分别是 1、2、3、4，那么它的输出就是

$$
0.1\times 1 + 0.2\times 2 + 0.3\times 3 + 0.4\times 4
$$

每个神经元都这么算一遍。第一层是 4 个输入连到 6 个神经元，参数量 $4\times 6 = 24$；第二层是 6 个连回 4 个，参数量同样是 24。两层加起来 **48 个参数**（这里先不算 bias）。[【跳转到 02:50】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=170)

![手算稠密 FFN：四维输入 [0.1, 0.2, 0.3, 0.4] 经过 4→6→4 的两层全连接，第一层 4×6=24、第二层 24，合计 48 个参数](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/00261.webp)

### 1.3 换成真实维度就是三亿

把 4 换成 4096、6 换成 6144，参数量就是 $4096\times 6144\times 2$，三亿的量级。UP 主强调，**FFN 是整个 Transformer 里参数占比最高的部分**，能力也最强 [【跳转到 03:32】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=212)。

### 1.4 想变强，只能加宽吗

想扩展能力，第一反应是把中间 6 个神经元换成 12 个——参数量翻倍。但本来就好几亿的参数再翻一倍，「就不得了了」，而且算力同样翻倍 [【跳转到 04:05】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=245)。这就是 MoE 要解决的矛盾。

## 二、MoE 的第一件事：门控网络怎么挑专家

UP 主把 MoE 拆成两个同等重要的部分：**怎么挑专家**、**挑完怎么算**。「因为我们只有先挑完专家之后才能去计算」[【跳转到 04:21】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=261)。

### 2.1 门控网络就是一个 N 分类器

假设一共有 8 个专家，每次挑 2 个。挑专家的那个网络叫 **gating 网络**（也叫 router，路由网络）[【跳转到 05:08】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=308)。

它的结构简单到可以一句话说完：**有多少个专家，就做多少分类**。8 个专家就是 8 分类，输入还是那个四维向量，输出是 8 个分数，而且这 8 个分数加起来等于 1——「因为它是一个八分类，加起来等于一」[【跳转到 06:10】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=370)。

这一步用公式写出来，就是常见的 softmax 门控。设门控矩阵为 $W_r$，先算 logits：

$$
h(x) = W_r x
$$

再对 $N$ 个专家做 softmax，得到每个专家的门控分数：

$$
p_i(x) = \frac{\exp(h_i(x))}{\sum_{j=1}^{N}\exp(h_j(x))},\qquad i = 1,\dots,N
$$

这里的 $p_i(x)$ 就是视频里「第一个专家 0.5、第二个 0.1、第三个 0.4、其余为 0」那 8 个分数。

### 2.2 取分数最高的 k 个

八个专家「择优录取」，挑两个，那就是分数最高的两个：第一个（0.5）和第三个（0.4）。这就是 **top-k 选择**：

$$
\mathcal{T} = \operatorname{TopK}\big(p(x),\ k\big)
$$

被选中的下标集合 $\mathcal{T}$ 是 $\{1, 3\}$，其余六个专家对这个 token 完全不参与计算。[【跳转到 06:15】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=375)

![门控网络输出八个分数（0.5、0.1、0.4，其余为 0），圈出分数最高的第 1 和第 3 个专家作为 top-2 选择结果](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/00370.webp)

### 2.3 门控网络自己只占一点点参数

有人会问：多加了一个网络，参数量不是变多了吗？在这个四维玩具例子里确实变多了——门控网络 $4\times 8 = 32$ 个参数，比 FFN 的 24 还多。

但真实情况不是这样。输入是 4096 维，门控网络是 $4096\times 8$，而 FFN 是 $4096\times 6144\times 2$。**门控网络带来的参数增量不值一提** [【跳转到 06:58】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=418)。这一点很关键：MoE 用极小的额外参数换来了「选择权」。

### 2.4 每个 token 走的路都不一样

门控网络是**逐 token** 计算的。同一个句子里，「I」这个 token 可能选中第一、第三专家，下一个 token 可能选中第七、第八专家——「每个 token 各走各的路」[【跳转到 09:35】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=575)。

![同一个句子「我爱吃苹果」里，不同 token 被路由到不同的专家组合：有的去 ①③，有的去 ②⑤](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/01292.webp)

有意思的是，虽然没人规定哪个专家该负责什么，训练完之后却会自发出现分工：第一个专家擅长代码、第二个擅长数学、第三个擅长历史人文。UP 主强调这是**训练后涌现**的，不是硬性指定的 [【跳转到 15:49】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=949)。

## 三、MoE 的第二件事：被选中的专家怎么算

### 3.1 八个专家长得一模一样，只有参数不同

每个专家都是一个独立的 FFN：4 个神经元 → 6 个 → 4 个，结构完全一样，但参数各不相同（第一个专家的权重是 1，第二个可能是 1.5）[【跳转到 07:37】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=457)。

所以「8 个专家」不是 8 种不同的网络结构，而是**8 份独立的 FFN 权重**。这也是 MoE 参数量能做得很大的原因：专家数一加，参数就线性增长。

### 3.2 两个专家各算一遍

选中的是第一和第三专家，输入不变（还是 `[0.1, 0.2, 0.3, 0.4]`），分别送进去：

- 第一个专家输出：$A = [0.5,\ 0.1,\ -0.3,\ 0.2]$
- 第三个专家输出：$B = [0.2,\ 0.4,\ 0.1,\ -0.1]$

其余六个专家「失业下岗」，对「I」这个 token 不做任何计算 [【跳转到 09:24】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=564)。

![两个被选中的专家各自对同一个输入做一次前向，得到两个四维输出向量](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/00615.webp)

### 3.3 加权求和：把两个四维向量压回一个

两个专家各输出一个四维向量，如果直接拼起来就是八维，但这一层的输出必须还是四维（才能接回残差）。所以要做**加权求和**：

$$
y = \alpha A + \beta B
$$

视频里把门控分数改成好算的数：第一个专家 0.6 分、第三个 0.4 分，于是 $\alpha = 0.6$、$\beta = 0.4$：

$$
y = 0.6\begin{bmatrix}0.5\\0.1\\-0.3\\0.2\end{bmatrix} + 0.4\begin{bmatrix}0.2\\0.4\\0.1\\-0.1\end{bmatrix} = \begin{bmatrix}0.38\\0.22\\-0.14\\0.08\end{bmatrix}
$$

![加权求和的具体算式：0.6 乘第一个专家的输出，加上 0.4 乘第三个专家的输出](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/00742.webp)

「I」这个 token 原本输入 `[0.1, 0.2, 0.3, 0.4]`，经过两个专家的计算再混合，输出 `[0.38, 0.22, -0.14, 0.08]`——**维度没变，值变了** [【跳转到 12:37】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=757)。

### 3.4 归一化：分数加起来不等于 1 怎么办

如果门控分数是 0.5 和 0.4，加起来只有 0.9，直接加权会让输出整体变小。处理办法是**在选中的 k 个专家上重新归一化**：

$$
\tilde p_i(x) = \frac{p_i(x)}{\sum_{j\in\mathcal{T}} p_j(x)},\qquad y = \sum_{i\in\mathcal{T}} \tilde p_i(x)\, E_i(x)
$$

也就是 0.5 变成 $0.5\times\frac{10}{9}$、0.4 变成 $0.4\times\frac{10}{9}$，比例不变、和变成 1 [【跳转到 12:05】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=725)。

![重新归一化的写法：把 0.5 和 0.4 各乘 10/9，使权重之和回到 1](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/00899.webp)

这里要留意一个容易混淆的点：视频里的门控分数是**先对全部 8 个专家做 softmax**（和为 1），再在选中的 2 个上**重新归一化**。另一种实现是只在选中的 k 个 logits 上做 softmax，两者在数值上不同（前者保留了「被淘汰专家占了多少概率质量」的信息，后者把它丢掉了）。读源码时要看清用的是哪一种。

## 四、稀疏激活到底省了什么：省算力，不省显存

### 4.1 计算量要跟谁比

第一反应是「这么折腾，计算量不是变多了吗」：原本稠密 FFN 是 $24+24=48$，现在两个专家各 48，加起来 96，再加门控网络，一百多 [【跳转到 14:03】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=843)。

UP 主说这是**对比对象错了**。MoE 不该跟「一个专家」比，而该跟「同样参数量的稠密 FFN」比：把中间 6 个神经元扩到 $6\times 8 = 48$ 个，参数量和 8 个专家持平，但计算量是 $4\times 48\times 2$，四百的量级。而 MoE 这边只有一百多的量级 [【跳转到 14:59】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=899)。

一句话：**参数量对齐时，MoE 的计算量只有稠密模型的 k/N**。

### 4.2 总参数量 vs 激活参数量

拿 2023 年开源的 8×7B 混合专家模型算一遍 [【跳转到 16:37】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=997)：

- 名字里的 8 是 8 个专家，7B 是「一个专家 + 共享部分」的规模；
- 每个专家约 5.6B 参数（都在 FFN 上），自注意力层约 1.4B，$5.6+1.4=7$；
- MoE 只作用于 FFN，自注意力层是所有专家共享的。

于是：

$$
\text{总参数量} = 8\times 5.6 + 1.4 \approx 47\text{B}
$$

$$
\text{激活参数量} = 2\times 5.6 + 1.4 \approx 13\text{B}
$$

![参数账：8×5.6+1.4≈47B 是总参数量，2×5.6+1.4≈13B 是每个 token 的激活参数量，比值约 1/3 到 1/4](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/01207.webp)

这也解释了开头那个奇怪的名字。**Qwen3-235B-A22B**：235B 是总参数量，A22B 的 A 是 activated（激活），22B 是每个 token 实际激活的参数量，$22/235$ 比 1/10 还小 [【跳转到 18:56】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1136)。

### 4.3 显存必须按总参数量准备

这是视频反复强调的「面试最大的坑」：很多人以为只激活 13B，显存就只要 13B。**不对** [【跳转到 20:16】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1216)。

「I」这个 token 确实只用了第一、第三专家，但下一个 token 可能用第七、第八专家，再下一个用第二、第五专家。**所有专家都得原地待命**，所以显存里必须装下全部 47B。稀疏只发生在「每个 token 算多少」，不发生在「模型要占多少地方」。

所以工程落地时的结论是：**MoE 计算量减少了、速度变快了，但显存并没有减少** [【跳转到 20:33】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1233)。也因此，8×7B 该对标的是 47B 的稠密模型，而不是 7B——「用 13B 的激活量去挑战 47B 的模型，这就是 MoE 的魔力」。

## 五、稀疏激活的副作用：专家坍缩

### 5.1 少数专家被挤爆，多数专家没人用

门控网络是可学习的，而它天然倾向于「谁好用就一直用谁」。训练下去可能出现：不仅「I」选第一、第三专家，「评」「token」「专家」「过」「吃」全都选第一、第三专家，第四、第五、第六专家无人问津 [【跳转到 21:43】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1303)。

这就是**专家坍缩（expert collapse）**。后果很直接：明明有 8 个专家，实际只用 2 个，那和砍掉 6 个有什么区别？「我为什么何必假惺惺地计算八个专家」[【跳转到 21:58】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1318)。

### 5.2 三种主流补救手段

UP 主给了三种思路，点到为止 [【跳转到 22:04】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1324)：

1. **加损失函数约束**：某个专家被光顾得太少，给它一点鼓励；被选得太多的专家，给它一点惩罚。用「万能的损失函数」把分布往均匀方向推。
2. **容量上限（capacity）**：一个 batch 有 1000 多个 token，除以 8 平均每个专家 125 个。如果定一个阈值 200，某个专家被调用超过 200 次后，本批次后续 token 就不再派给它，逼着 token 去别处。
3. **注入噪声**：训练时给门控分数加噪声，强行把热门专家的一部分流量分给冷门专家。UP 主打了个比方——你考了最高分，但上级为了「雨露均沾」，把你的资源强行分给了学习最差的同学。

这三种手段分别对应「软约束（loss）」「硬约束（容量）」「随机扰动（噪声）」，后面的 Switch Transformer 会把前两种做成标准配置。

## 六、为什么专家越拆越多

视频最后用排列组合解释了一个趋势 [【跳转到 25:34】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1534)：

- 8 个专家选 2 个，$\binom{8}{2}=28$ 种组合；
- 256 个专家选 8 个，$\binom{256}{8}\approx 4\times10^{14}$ 种组合。

组合数越大，「可选的丰富性」越多，模型的表达能力就越强。所以从 8 个专家（2023 年的开源 MoE）到 160 个（DeepSeek-V2）、再到 256 个（DeepSeek-V3），专家数量一路上涨 [【跳转到 25:13】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1513)。

![MoE 的演进时间线：1991 年提出思想，2017 年谷歌论文论证对 NLP 有用，2023 年开源 8×7B，之后 DeepSeek 把专家数推到 160、256](assets/MoE%20稀疏激活：门控网络如何为一个%20token%20挑出%20Top-2%20专家/01534.webp)

顺带一提，1991 年 MoE 的思想就出现了：把一个大问题切成若干小问题，每个小问题由 gating 决定要不要用某个专家——和今天的 MoE 一模一样，只是当年没有深度学习、算力和数据都不够，所以没激起火花 [【跳转到 24:09】](https://www.bilibili.com/video/BV16XDYBXEdb/?t=1449)。

## 小结

- **MoE 只改 FFN**：自注意力层不动，把一层 FFN 换成 $N$ 个同构专家 + 一个门控网络。
- **门控网络是一个 N 分类器**：输入 token 向量，输出 $N$ 个和为 1 的分数，参数量只有 $d\times N$，相对 FFN 可以忽略。
- **top-k 选择**：取分数最高的 $k$ 个专家，其余专家对该 token 不参与计算；每个 token 选中的专家可以不同。
- **加权求和**：$y=\sum_{i\in\mathcal{T}}\tilde p_i(x)E_i(x)$，权重是重新归一化后的门控分数，输出维度不变。
- **稀疏激活的本质**：参数量随 $N$ 线性增长，单 token 计算量只随 $k$ 增长；对齐参数量时，MoE 的计算量约为稠密模型的 $k/N$。
- **省算力不省显存**：所有专家都要常驻显存，8×7B 要按 47B 准备，只是每 token 只算 13B。
- **专家坍缩是主要副作用**：门控会偏心，需要辅助损失、容量上限、噪声注入来维持负载均衡。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| MoE（Mixture of Experts） | 混合专家：用多个结构相同、参数不同的 FFN 专家替代单个大 FFN，每个 token 只走其中一部分 |
| 门控网络 / 路由网络（gating / router） | 一个 $d\times N$ 的小线性层加 softmax，给每个 token 打出 $N$ 个专家分数 |
| top-k 选择 | 只保留分数最高的 $k$ 个专家，其余不参与该 token 的计算 |
| 门控分数 $p_i(x)$ | 第 $i$ 个专家的权重，全部专家上 softmax 后和为 1 |
| 重新归一化 | 在选中的 $k$ 个专家上把权重再除以它们的和，使加权系数之和回到 1 |
| 总参数量 | 所有专家 + 共享层的参数总和，决定显存占用 |
| 激活参数量 | 单个 token 实际经过的参数（$k$ 个专家 + 共享层），决定计算量 |
| 专家坍缩（expert collapse） | 门控长期偏向少数专家，其余专家训练不到、形同虚设 |
| 容量上限（capacity） | 限制单个专家在一个 batch 内最多处理多少 token，超出部分不再派发 |
| 辅助损失（aux loss） | 额外加在门控分布上的损失项，惩罚不均衡的专家使用率 |
