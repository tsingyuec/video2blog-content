# T5 去噪预训练：片段破坏如何把填空变成序列到序列

> 视频来源：[【自娱自乐读paper】T5模型论文精读](https://www.bilibili.com/video/BV1u14y1B7WF/)（Bilibili · c10coin）｜时长约 38 分钟
> 导读：这是一次按论文结构走的 T5 调研报告，最有价值的部分是"无监督预训练目标"那一节——作者把三种高层目标、三种破坏策略、四种破坏比例、四种片段长度放在一张搜索空间里逐个做实验，最后挑出 span corruption。本文重点讲清"破坏什么、破坏多少、预测什么、损失算在哪"，其余部分（结构、位置编码、微调、规模）按视频顺序整理。字幕里的口误与错拼已按上下文订正。

## 本讲要解决的核心问题（SCQA）

**背景**：BERT 用掩码语言模型做预训练，随机挖掉 15% 的词元再填回来，在各类自然语言理解任务上效果很好。但它有一个明显的边界：预训练是"填空"，输出是每个位置上的一个词表分布，这套目标只擅长理解类任务。

**冲突**：NLP 里还有大量生成类任务——翻译、摘要、阅读理解式的问答。如果每个任务都要单独加一个输出层、单独设计损失函数，"一个模型通吃"就无从谈起。更麻烦的是，掩码目标本身还有一堆没定下来的细节：破坏什么、破坏多少、一次破坏多长、预测哪些位置。这些选择在 BERT 那里是拍定的，但没人系统比较过。

**疑问**：能不能设计一个统一的框架，让所有任务都变成同一件事？在这个框架里，自监督的"去噪重建"目标应该怎么设计——破坏的粒度和比例怎么取，预测的目标是整段原文还是只预测被破坏的片段？

**回答（中心思想）**：T5 把所有任务统一成 **text-to-text**：输入一段文本、输出一段文本，用同一个损失函数、同一套解码过程。在这个框架下，它把预训练目标做成**去噪重建**——随机破坏输入里 15% 的内容，让模型把被破坏的部分"翻译"回原文。关键改进是 **span corruption**：不再一个词元一个词元地挖，而是**一次挖掉平均长度为 3 的连续片段**，每个片段在输入里换成一个哨兵记号（如 `<X>`），输出端则按片段顺序列出"哨兵 + 原文片段"。这样输入更短、预测目标更短，计算效率更高，而且实验证明效果最好。 [【跳转到 18:18】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1098)

## 一、为什么要有 T5：从"分类器"到"文本进、文本出"

### 1.1 BERT 的边界

视频开场先交代动机 [【跳转到 00:14】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=14)：5 年前 BERT 横空出世，实验证明它能解决 80% 以上的自然语言理解任务。但 BERT 的弊端也很明显——它只适用于各类**文本分类**任务，比如判断这句话是喜欢还是讨厌、两句话是相似还是相反。而 NLP 里不只有分类，还有各类**生成**任务。

于是 Google 开始想办法：把当下最流行的预训练技术的各个环节——模型架构、无监督预训练目标等等——挨个做对比实验，最后拼出号称"万事皆可 text-to-text"的 T5 [【跳转到 00:39】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=39)。

### 1.2 text-to-text：用前缀代替输出层

BERT 微调时，要针对不同下游任务增加相应的输出层。T5 的改法是：**不加任何非线性层，只在输入数据前加一个任务声明前缀**，模型就会把答案"说"出来 [【跳转到 01:09】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=69)。

视频举了三个例子 [【跳转到 01:39】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=99)：

- **翻译**：以前是直接输入要翻译的句子、等结果；T5 则在输入前加上"把中文翻译成英文"的前缀，明确告诉它现在做的是翻译。
- **文本分类**：以前输入一段用户搜索文本，输出一个 label（0 表示不感兴趣、1 表示感兴趣）；T5 加上任务前缀，输出也是一个文本，直接写"感兴趣"。
- **阅读理解**：同样是文本进、文本出。

这样做的收益是：**指令写在输入里，就不需要在后续流程里为特定任务添加输出层**，也就省掉了那部分额外开销 [【跳转到 02:54】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=174)。

## 二、结构：三种架构比出来一个 encoder-decoder

T5 的模型结构本身不算创新，作者直接拿了三个主流架构做实验 [【跳转到 03:09】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=189)：

- **encoder-decoder**：传统 Transformer。编码器输入能看到所有字符，解码器输出只能看到当前及之前的字符。
- **LM（language model）**：就是 GPT 的结构，相当于 encoder-decoder 里的 decoder 部分，单向，每次只能看到当前和之前的内容。
- **prefix LM**：基于前缀的语言模型。前面一段文本当作"前缀"，像编码器一样双向可见；后面剩下的内容像 decoder 一样单向，只能看到自己和之前的内容。

三者的本质区别就是**注意力掩码** [【跳转到 03:59】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=239)。以"我想吃苹果"为例：

- encoder-decoder：每个字符都能看到全体，不需要管顺序；
- LM：每个字符只能看到自己和之前的，比如"吃"只能看到"我""想""吃"；
- prefix LM：前缀"我想吃"双向可见，"苹果"单向可见——"想"能同时看到"我""想""吃"，而"苹"看不到后面的"果"。

![T5 第 3.2 节对比三种架构：encoder-decoder、language model、prefix LM，以及"我想吃苹果"在三种掩码下的可见性矩阵；表 2 显示 encoder-decoder 在去噪目标下综合最好](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/00239.webp)

实验结果：**encoder-decoder 架构效果最好**，所以 T5 本质上就是一个基于 Transformer 的 encoder-decoder 模型 [【跳转到 05:14】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=314)。

### 2.1 分词：SentencePiece 把空格也当成普通字符

BERT 用的是 subword 粒度的 WordPiece，把稀有单词拆成有意义的字词单元（比如词根）。但这里有个前提问题：这些分词算法都默认用**空格**分隔单词，可不是所有语言都用空格分词——中文、日文都不是 [【跳转到 05:39】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=339)。

一种解法是为每种语言准备专门的 tokenizer，但那样预处理会变得特别复杂。Google 的方案是 **SentencePiece**：不把空格当分隔符，而是把字符串按原始格式输入，再用 BPE 或 unigram LM 构建词表，这样就可以直接从原始句子上训练，速度很快 [【跳转到 06:04】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=364)。

### 2.2 位置编码：相对位置 + 分桶

因为 T5 把所有 token 一起输入，必须额外注入位置信息。视频先回顾了 Transformer 的绝对位置编码：三角函数有规律性，所以有一定外推性，但它**无法表示两个 token 之间的方向关系** [【跳转到 07:03】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=423)。

相对位置编码则是根据 token 与 token 之间的位置关系生成权重 [【跳转到 07:28】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=448)。假设有 5 个 token，对 $x_4$ 来说：

- $w_0$ 表示它与自己的位置关系；
- $w_1$ 表示向右移动一个位置，即 $x_4$ 与 $x_5$；
- $w_{-1}$ 表示向左移动一个位置，即 $x_4$ 与 $x_3$。

以此类推，5 个 token 只需要 9 个不同的位置编码 $w_{-4},\dots,w_4$。

![T5 输入表示：相对位置编码用 token 之间的相对距离生成权重，5 个 token 只需 $w_{-4}$ 到 $w_4$ 共 9 个编码](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/00473.webp)

但序列一长就出问题：如果有 $N$ 个 token，对第一个 token 来说就要有 $w_0$ 到 $w_{N-1}$，参数量爆炸。所以相对位置编码会设一个**阈值**：超过阈值的距离，一律用最近的、已被分配的位置编码 [【跳转到 08:17】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=497)。

T5 更进一步做了**分桶**：因为远距离的依赖往往稀疏且不精细，近处需要区分得细、远处可以粗糙，于是把相对位置按距离放进 32 个桶，用桶号代替相对距离 [【跳转到 09:29】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=569)。视频给的分割线是：双向 attention 用 8，单向 attention 用 16——低于它的算"近"，每个距离单独一个桶；高于它的算"远"，多个距离共用一个桶，距离越远共用范围越大 [【跳转到 09:54】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=594)。

![T5 相对位置的分桶映射：num_buckets=32、max_distance=128，双向 attention 以 8 为远近分割线，近处 0~7 各占一个桶，远处 8 以后逐段合并](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/00594.webp)

还有一个实现上的差异：Transformer 是把 position embedding 加到 input embedding 上再进编码器；T5 则是在编码器每一层的 self-attention 里，**算完 $QK^\top$ 之后**再加一个可学习的相对位置偏置 [【跳转到 10:44】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=644)。为了简便，所有编码器层共享同一组 embedding 参数，但因为不同 head 不同，偏置矩阵的维度是 $\text{num\_relative\_buckets} \times \text{num\_heads}$。

视频把三种模型的位置方案串了一遍 [【跳转到 11:51】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=711)：Transformer 用绝对位置编码（三角函数，有外推性，但看不出方向）；BERT 改成可学习的绝对位置编码，靠 segment embedding 区分方向，缺点是配置文件里卡死了最多 512 个词；T5 用相对位置编码，在 attention 矩阵上加可训练偏置，能处理变长输入，但实现更复杂。

## 三、预训练目标：一次系统的"破坏—重建"实验

这是本文的重点，也是 T5 论文真正花力气的地方。

### 3.1 先造一个够大的数据集：C4

在讲目标之前，视频先介绍了 T5 的另一个贡献——**C4 数据集** [【跳转到 14:22】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=862)。要准确评估"扩大预训练规模"的效果，需要一个高质量、多样化、规模足够大的数据集，而现有数据集无法同时满足：维基百科质量高、格式统一，但规模偏小。C4 是 Common Crawl 的清洁版本，比维基百科大两个数量级，清洗过程包括删除重复数据、去除不完整句子、消除冒犯性或噪音内容 [【跳转到 14:47】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=887)。

### 3.2 搜索空间：四个维度

作者对无监督目标做了一系列探索，实验沿四个维度展开 [【跳转到 15:37】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=937)：

1. **高层目标**（high-level approaches）：语言模型式、BERT-style、顺序还原式（deshuffling）；
2. **破坏策略**（corruption strategies）：mask、replace spans、drop；
3. **破坏比例**（corruption rate）：10%、15%、25%、50%；
4. **被破坏片段长度**（corrupted span length）：2、3、5、10。

![T5 无监督预训练的搜索空间：三种高层目标 × 三种破坏策略 × 四种破坏比例 × 四种片段长度，最后收敛到 BERT-style + replace spans + 15% + 长度 3](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/00962.webp)

### 3.3 第一维：三种高层目标

T5 在这里主要选了三种方式 [【跳转到 16:02】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=962)：

- **语言模型式**：就是 GPT-2 的训练方式，从左到右单向预测；
- **BERT-style**：像 BERT 一样用掩码语言模型随机破坏一部分内容，然后再还原；
- **顺序还原式（deshuffling）**：把文本随机打乱，再让模型还原顺序。

实验证明 **BERT-style 在各类数据集上效果最佳**，于是高层目标定为 BERT-style [【跳转到 16:27】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=987)。

这里值得停一下：语言模型式被排除，说明 T5 从一开始就没打算走"预测下一个词"的路线；它要的是**破坏—还原**这种去噪式目标。这正是本小节"去噪重建"的落点。

### 3.4 第二维：三种破坏策略

确定高层目标之后，接下来是"怎么破坏" [【跳转到 16:52】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1012)：

- **Mask**：把被破坏的 token 换成一个特殊符（如 `[M]`）。这就是 BERT 的做法，一个位置一个特殊符。
- **Replace span（小段替换）**：在 mask 的基础上叠加"合并"。假如现在有两个相邻的 `[M]`，在小段替换法里会合并成一个特殊符——原本要预测两次，现在只预测一次，从而提高了计算效率。
- **Drop**：没有替换操作，直接随机丢弃一些字符。

![T5 表 5：比较 BERT-style 目标的几种变体。Replace corrupted spans 与 Drop corrupted tokens 只预测被破坏的片段，而不是重建整段原文；前者综合最优](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/01012.webp)

实验证明**小段替换法在多数数据集下效果最佳**，因此保留 replace span [【跳转到 17:17】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1037)。

注意这里的差别不只是"效率"：mask 法与 replace span 法的**预测目标长度不同**。前者要逐个位置预测，后者只预测每个片段一个符号序列，输出序列短得多。

### 3.5 第三维：破坏比例 15%

破坏多少合适？作者筛了四个值：10%、15%、25%、50% [【跳转到 17:30】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1050)。

![T5 表 6：不同破坏比例下的下游表现，15% 一行被标星，GLUE、SQuAD、SGLUE 等多数指标最好](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/01075.webp)

结果是 **15% 最优**，于是确定把 15% 的内容替换成特殊字符。这个数字和 BERT 的 15% 一致，但含义不同：BERT 的 15% 是**被选中的词元位置比例**，T5 的 15% 是**被破坏的内容比例**，而由于片段是整段挖掉的，实际被替换的 token 数会围绕这个比例波动。

### 3.6 第四维：片段长度 3

最后一个维度是"一次破坏多长"。T5 不再是一个 token 一个 token 地替换，可能是单个 token，也可能是多个 token 组成的一小段，所以作者专门研究了最佳替换长度 [【跳转到 17:55】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1075)。

实验结果是**长度为 3 时效果最好**。综合四个维度，T5 的预训练方法就定下来了 [【跳转到 18:18】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1098)：

- 高层目标：BERT-style；
- 破坏策略：replace span（小段替换）；
- 破坏比例：15%；
- 片段长度：3。

### 3.7 一个具体例子：span corruption 长什么样

视频用一个例子把输入输出摆清楚 [【跳转到 18:43】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1123)：

```
原文   The weather recently is so good, I want to invite you to come to my party tomorrow.
输入   The <X> so good, I <Y> you to come to my party tomorrow.
目标   <X> weather recently is <Y> want to invite <Z>
```

![T5 最终的预训练配方与一个 span corruption 实例：输入里被挖掉的片段换成 <X>、<Y> 哨兵，目标端按顺序输出"哨兵 + 原文片段"，末尾用 <Z> 收尾](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/01123.webp)

这个例子把前面几个决定串起来了：

1. **破坏是成段的**：`weather recently is` 和 `want to invite` 各是一段被整体挖掉，长度正好是 3；
2. **输入里用哨兵占位**：`<X>`、`<Y>` 标记"这里原本有一段内容"；
3. **目标端是"哨兵 + 原文"的序列**：模型要按片段出现的顺序，把每个哨兵对应的原文片段吐出来，最后用 `<Z>` 收尾。

这一步非常关键，它解释了为什么 T5 能统一到 text-to-text：**去噪重建被改写成了一个序列到序列任务**。输入是残缺的句子，输出是被挖掉的片段序列。损失就落在输出序列的每个 token 上——预测的是"被破坏的那部分原文"，而不是整段输入的每个位置。

和 BERT 的 MLM 对比一下会更清楚：

| 维度 | BERT 的 MLM | T5 的 span corruption |
| --- | --- | --- |
| 破坏单位 | 单个词元（15% 的位置） | 连续片段（平均长度 3，总量 15%） |
| 输入里的占位 | 每个位置一个 `[MASK]` | 每个片段一个哨兵 `<X>`/`<Y>` |
| 预测什么 | 每个被掩码位置的词 | 按顺序输出"哨兵 + 片段原文" |
| 输出长度 | 与输入等长 | 远短于输入 |
| 损失位置 | 只在被掩码的位置 | 在输出序列的每个 token 上 |

最后一行是关键差别：BERT 是在**输入序列的稀疏位置上**算损失，T5 是在**一个独立的、更短的输出序列上**算损失。这也是视频反复强调"输入序列变短、预测目标序列变短，从而提高计算效率"的原因 [【跳转到 32:49】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1969)。

## 四、微调：两种省参数的替代方案

预训练结束后进入微调。这部分同样是实验定下来的：微调**所有**参数效果最好，但在资源匮乏时可能导致结果欠佳，所以论文提出两种替代方案 [【跳转到 19:05】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1145)。

![T5 第 3.3 节：Adapter layers 在每个块的前馈网络后插入 dense-ReLU-dense 适配层，只更新适配器层和归一化层；Gradual unfreezing 从最后一层开始逐层解冻](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/01145.webp)

- **Adapter layers**：微调时保持大多数参数固定，在 Transformer 每个块的前馈网络之后插入适配器层，只更新适配器层和归一化层的参数。这样需要调整的参数数量大大降低。它的主要超参数是前馈网络的内部维度 $d$，$d$ 决定了新增参数的数量。
- **Gradual unfreezing（逐渐解冻）**：微调开始时只更新最后一层，训练一段时间后倒数第二层开始更新，如此逐层放开，直至整个网络都被微调。

实验结果 [【跳转到 20:08】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1208)：

- 所有参数一起更新效果最好，但特别慢；
- adapter layers 在维度较小时，在斯坦福数据集这类**低资源任务**上表现不错；对高资源任务则必须用较大的维度才能达到合理性能。所以它是一种有前途的"少参数微调"技术，只要把维度按任务规模调整好；
- gradual unfreezing 确实带来一定加速，但全局解冻可能让所有任务都轻微掉点，需要更仔细地调解冻 schedule [【跳转到 20:33】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1233)。

## 五、多任务预训练：把有监督任务混进预训练

作者接着问了一个问题：既然都是在单个无监督任务上预训练、再对每个下游任务分别微调，那能不能做多任务学习？加入更多任务能否提升性能 [【跳转到 20:58】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1258)？

视频特别澄清：T5 最后选的"多任务"**不是绝对意义上的多任务**——它针对多个任务训练单个模型，但报告性能时可以为每个任务挑不同的 checkpoint，也就是每个任务保存一个专属的最佳参数 [【跳转到 21:23】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1283)。

大多数 NLP 多任务工作会加任务特定的分类网络、或为每个任务用不同损失函数。T5 的做法简单得多：**把多个数据集混在一起**，预训练时把有监督训练也加进来，这样就不需要不同的损失函数了——因为一切都是 text-to-text [【跳转到 21:48】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1308)。

### 5.1 怎么采样：三种混合策略

混起来之后新问题来了：无监督任务 + 若干有监督任务，按什么比例采样？作者做了三个实验 [【跳转到 22:13】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1333)：

- **Example proportional mixing**：按每个任务数据集大小按比例采样。问题是占最大头的往往是无监督数据，模型看到的大多是无标签数据，监督任务就缺乏训练；而且即使没有无监督任务，像 WMT 英法翻译这种大数据集也会占据大多数批次。解法是给数据集大小设一个人为上限 $K$。
- **Temperature-scaled mixing**：为缓解数据集大小差异，把混合率提高到 $1/T$ 次幂再重新归一化。$T=1$ 时等价于 example proportional mixing，$T$ 越大比例越接近均等混合 [【跳转到 23:28】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1408)。
- **Equal mixing**：每个任务等概率采样。

结果：多任务学习的效率其实**不如**"预训练后对大多数任务微调" [【跳转到 23:53】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1433)。equal mixing 尤其糟，性能急速下降——可能是在低资源任务上过拟合，而在高资源任务上又没看到足够数据，或者模型没看到足够未标注数据来学通用语言能力。example proportional mixing 中，多数任务都存在一个最佳的 $K$；temperature-scaled mixing 则提供了"从大多数任务都拿到合理性能"的办法，$T=2$ 时在多数情况下最佳 [【跳转到 25:08】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1508)。

### 5.2 多任务 + 微调

既然纯多任务不如"预训练 + 微调"，作者又试了组合方案 [【跳转到 25:33】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1533)：

1. 在人工混合数据集上预训练，再在每个下游任务上微调——用来衡量预训练时是否该把监督任务和无监督任务混在一起，也让模型对下游任务有"早期暴露"；
2. 在同样的混合数据上预训练，但把某个下游任务从混合集里抽走，再在这个任务上微调（leave-one-out）；
3. 去掉所有无监督目标，只用监督任务预训练。

结果：**多任务训练 + 微调与无监督预训练 + 微调性能相当**，leave-one-out 稍差 [【跳转到 26:48】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1608)。这说明多任务训练不会造成严重的任务干扰。而多任务还多一个好处：**整个训练期间都能监控下游任务的性能**，而不只是在微调阶段 [【跳转到 29:25】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1765)。

## 六、规模：把算力花在哪里

回到最基础的问题：模型变大，效果是不是更好？这里的"变大"包括更大的模型、更多训练步数、以及模型集成 [【跳转到 27:13】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1633)。

假设有四倍算力，可以做六个实验：训练步数 ×4；batch size ×4；模型参数 ×2 且步数 ×2；模型参数 ×4；四个 baseline 模型融合；以及四个模型的集成（它们源自同一个预训练模型，但微调时用不同随机数，所以是四个不同模型）[【跳转到 27:38】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1658)。

结论：**增大规模确实能提升性能**，但要权衡资源与最终效果。大模型会让下游微调和推断更贵；而把小模型训更久、用到很多下游任务上，可能更有效地摊销成本 [【跳转到 28:03】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1683)。

| Small | 6 | 512 | 8 | 6000 万 |
| Base | 12 | 768 | 12 | 2.2 亿 |
| Large | 24 | 1024 | 16 | 7.7 亿 |

## 七、贡献、局限与后续变体

### 7.1 贡献

视频把 T5 的贡献总结成六条 [【跳转到 31:49】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=1909)：

![T5 的贡献清单：text-to-text 统一框架、原始 encoder-decoder 最好、去噪目标最优、C4 数据集、多任务预训练 + 微调、规模扩展](assets/T5%20去噪预训练：片段破坏如何把填空变成序列到序列/01919.webp)

- **Text-to-text**：把所有 NLP 任务转成文本进、文本出，用相同的损失函数和解码过程训练单个模型，性能可与任务特定架构相比；
- **Architectures**：尽管此前有各种 Transformer 变体，原始的编码器/解码器形式在 text-to-text 框架里效果最好。编码器/解码器使用的参数是"仅编码器"（如 BERT）或"仅解码器"（语言模型）的两倍，但计算成本相似；在编码器和解码器中共享参数不会导致性能下降，还能让总参数减半；
- **Unsupervised objectives**：去噪（BERT-style）目标最好，并且把连续的破坏片段用一个哨兵 token 代替，预测目标从"预测原序列"变成"预测这些被破坏的 token"，目的是让输入序列变短、预测目标序列变短，提高计算效率；
- **Datasets**：引入 C4。用任务领域相关的数据预训练效果最好，但会限制适用范围；数据不够大又会导致过拟合、损害下游性能，所以推荐大而丰富的数据集；
- **Training strategies**：微调时所有参数一起更新最好但代价大；text-to-text 让多任务预训练变简单，难点在采样比例，多任务预训练 + 微调能有效缓解；
- **Scaling**：更多数据、更大模型、模型融合都能提升性能。

### 7.2 局限

视频也列了几条 T5 没解决的问题 [【跳转到 33:56】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=2036)：

- 扩大规模确实能提升性能，但资源匮乏时用大模型会带来额外开销，如何用更便宜的模型达到更强性能仍需研究（模型蒸馏、参数共享都是方向）；
- 预训练目标虽然效果不俗，但**有理由怀疑它并不是教模型通用知识最有效的方法**，寻找更好的预训练目标需要持续研究；
- 预训练数据里与下游任务越接近效果越好，但相近任务太多又会让模型变局限，如何衡量任务相似度也是开放问题；
- 仅英语预训练在翻译任务上并没有达到最好，说明单一语言有局限，需要探究与语言无关的模型 [【跳转到 35:11】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=2111)。

### 7.3 三个后续变体

- **mT5**：语料从英语扩到 101 种语言，仍用 C4 训练，但在激活函数、参数共享、模型结构上做了调整，在多语言模型里表现最好 [【跳转到 35:35】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=2135)。
- **ByT5**：针对分词器的问题。BERT 用 WordPiece 把稀有词拆成词根，但分词过程可能出现拼写错误、大小写不规律、形态变化，导致 token 表示完全改变；如果遇到构建词表时没见过的新语言，还会超出词表。ByT5 直接把**字节序列**输入模型，可以处理任意文本序列，在标准英语和多语言基准上都有竞争力 [【跳转到 36:00】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=2160)。
- **FLAN-T5**：基于指令微调。普通 T5 靠任务前缀显性提示，虽然能给出准确答案，但模型并不是通过自然语言理解"要做什么"；FLAN-T5 改成直接给一段人也能看懂的话，让模型自己理解要回答什么，理解能力因此大幅提高 [【跳转到 37:15】](https://www.bilibili.com/video/BV1u14y1B7WF/?t=2235)。

## 小结

- **统一框架**：T5 把所有任务改写成 text-to-text，用任务前缀代替任务特定的输出层，从而共用同一个损失函数与解码过程。
- **架构**：三种架构对比后选 encoder-decoder；分词用 SentencePiece（不把空格当分隔符），位置用相对位置编码并做 32 桶分桶。
- **目标**：高层目标选 BERT-style 去噪重建，破坏策略选 replace span，破坏比例 15%，片段长度 3——四个维度都是实验选出来的。
- **span corruption 的形状**：输入里每个被挖掉的连续片段换成一个哨兵记号，输出端按顺序给出"哨兵 + 原文片段"，末尾 `<Z>` 收尾。
- **与 BERT MLM 的差别**：BERT 在输入序列的稀疏位置上逐点算损失；T5 在一个更短的输出序列上算损失，输入和目标都变短，计算更省。
- **训练策略**：微调全参数最好，adapter layers 与 gradual unfreezing 是省参数的替代；多任务预训练 + 微调性能与"无监督预训练 + 微调"相当，但能在训练中监控下游指标。
- **规模**：Small/Base/Large/3B/11B 五个尺寸，更多数据、更大模型、模型融合都能涨点。
- **局限**：去噪目标未必是教通用知识最有效的方式；仅英语预训练在翻译上不够好——这两点分别催生了新的预训练目标与 mT5/ByT5/FLAN-T5 等变体。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| text-to-text | 所有任务都写成"输入一段文本、输出一段文本"，共用同一损失与解码过程 |
| 任务前缀 | 写在输入开头的任务声明（如"把中文翻译成英文"），替代任务特定的输出层 |
| 去噪重建 | 随机破坏输入的一部分，再让模型把被破坏的内容还原 |
| span corruption | T5 的去噪目标：按连续片段破坏，输入用哨兵占位，输出"哨兵 + 原文片段" |
| 哨兵记号（sentinel） | `<X>`、`<Y>` 这类占位符，标记"这里原本有一段内容"，末尾 `<Z>` 收尾 |
| 破坏比例（corruption rate） | 被破坏内容占原文的比例，T5 取 15% |
| 片段长度（span length） | 一次破坏的连续 token 数，T5 取平均 3 |
| replace span | 把相邻的多个 mask 合并成一个特殊符的破坏策略，减少预测次数 |
| deshuffling | 把文本随机打乱再让模型还原顺序的高层目标，实验中被 BERT-style 击败 |
| C4 | Common Crawl 的清洁版本，比维基百科大两个数量级，用于 T5 预训练 |
| adapter layers | 在前馈网络后插入的小适配层，微调时只更新它与归一化层 |
| gradual unfreezing | 从最后一层开始逐层解冻的微调策略 |
| 相对位置编码 | 用 token 之间的距离生成权重，T5 在 attention 矩阵上加可学习偏置 |
| 分桶（bucketing） | 把不同距离映射到有限个桶，近处细、远处粗，控制参数量 |
