> 工作目录：`/workspace/working/video2blog-content`

> 本文件是**唯一规则来源**。驱动脚本（`scripts/rl_auto_process.sh`）与 Maka 定时任务都只读本文件，不再另设副本；驱动模式下的差异见第 7 节。

## 0. 运行模型

- 每次定时触发（**每 20 分钟**）= **一次独立运行**，运行间无记忆。进度只存在于 README 的行尾标记里，每次运行必须重读 README 定位。
- 一次运行**只处理一个条目**，完成即结束。
- **不设并发限制**：单个条目（探索 + 下载 + 抽帧 + 字幕 + 图文稿 + 博客）常要 1 小时以上，因此**多轮运行并行是常态**。各运行自行认领**互不相同**的条目，互不等待、互不取消。
- 并发安全靠三条约定：**认领用「局部替换 + 重读校验」**，**README 只改自己那一行**，**产出目录只写自己的条目**。
- **待处理条目**：README 中以 `-` 开头、且行尾**既无** `【处理中】` **也无** `【已完成】` 标记的行。

### 图片读取硬限制（必须遵守）

- 使用 Maka `Read` 读取图片时，**单次模型请求最多读取 5 张图片**；严禁一次性读取或并行提交超过 5 张图片。
- 图片较多时必须分批读取：每批 1～5 张，等待本批结果返回后再读取下一批。
- 该限制适用于候选图、视频帧、contact sheet、博客配图和临时截图；违反后模型请求会因图片数量超限而失败。

## 1. 认领

1. 重读 README，按出现顺序列出待处理条目（无任何标记的行）。若一条都没有，结束本次运行。
2. 从第一个候选开始尝试认领：在该行行尾追加 `**【处理中】**`。
   - 写入**只能精确替换这一行**（先 `grep -n` 定位行号再用 `sed -i "<行号>s/$/ **【处理中】**/"`，或 Python 读全文 → 按内容匹配唯一行 → 只替换该行 → 写回），**严禁整体重写覆盖文件**；
   - 写完**立即重读该行**确认：仍以 `**【处理中】**` 结尾，且未被别的运行改成 `【已完成】`；
   - 若该行已被别的运行抢先标记、或写入被覆盖丢失，**回到步骤 2 换下一个候选**。
3. 若所有候选都是在被处理中，**结束本次运行**（不等待、不重试、不排队）。
4. 认领成功后再开工（先标记后干活）。

### 1.1 已有 `**【处理中】**` 标记的行怎么对待（只做回收，不做限流）

| 情形 | 处理 |
|---|---|
| 该条目博客已落位 | 只是没来得及写完成标记：**补写完成标记**（链接已有博客）后结束本次运行 |
| 博客未落位，`temp/reinforcement_learning/<条目名>/` **近 60 分钟内仍有文件变动** | 别人正在做，**跳过**，看下一个候选 |
| 博客未落位，且 temp 目录不存在或**已超 60 分钟无变动** | 中断残留：清理 temp、把该行标记回滚为空，随后可作为候选重新认领 |

- 回收只针对「明显已死」的残留（超 60 分钟无动静），**不要**因为「感觉慢」去抢别人的条目。

## 2. 探索视频

以条目内容（含编号、括号里的英文术语）构造中英文关键词，在 Bilibili / YouTube 探索：

1. **筛选**：按标题、简介剔除不相关或低质视频。
2. **精排**：对前 5~8 个候选**抓取字幕**，按内容详细程度与质量排序（是否系统覆盖知识点、是否讲清数学推导、信息密度）。
3. **同分时 Bilibili 优先于 YouTube**。
4. 选出 **1~3 个**视频；单个视频已充分覆盖则只选 1 个。

**选题取向（本系列特有）**：本系列是**公式密集的理论体系**，不是「调包跑一个 RL demo」的实操课。

- 优先：系统课程（David Silver 的 UCL 强化学习、Sutton & Barto 配套讲座、Stanford CS234、Berkeley CS285、HuggingFace Deep RL Course、李宏毅/王树森《强化学习》、蘑菇书《动手学强化学习》）、算法论文精读（DQN/PPO/SAC/AlphaZero/DPO/GRPO 等）、有推导过程的专题讲解；
- 慎选：只讲「装环境 + 跑通 gym 脚本」的入门 Demo，除非它能**实证机制**（如打印 TD 误差、对比 Q-Learning 与 Double Q 的高估、可视化策略分布）；
- 一个视频跨相邻两条时，归给它讲得更透的那条，避免同一条目反复用同一支视频凑数。

## 3. 处理视频

- 前置：确认已安装 `video2blog` skill（见仓库根 `AGENTS.md`）。
- 所有中间产物（视频 / 抽帧 / 字幕 / 图文稿）放 `temp/reinforcement_learning/<条目名>/`，按 video2blog 流程：**下载 → 抽帧 → 抓字幕 → 图文稿 → 通顺化**。
- `<条目名>`：条目编号+标题（如 `5.4_Q-Learning与最大化偏差`），去掉文件系统非法字符：**去掉 `$`、`\`、`{}`、`:`、`/`、`(`、`)`、`,` 等**（标题里的 LaTeX 如 `$\epsilon$`、`$\text{TD}(\lambda)$` 一律转成纯文本 `epsilon`、`TD(lambda)`）。

### 3.1 字幕获取降级链与限流应对

**字幕获取优先级**：
1. **首选**：kedou.life（与 video2blog skill 默认一致）；
2. **kedou 限流 / 失败时**：用 yt-dlp + B 站登录 cookie 直接抓取官方 AI 字幕：

   ```bash
   yt-dlp --cookies .agents/bili-subtitle/cookies.txt \
     --write-subs --sub-langs "ai-zh,zh-CN,zh" --sub-format srt --skip-download \
     -o "temp/reinforcement_learning/<条目名>/subs/%(id)s" "<视频URL>"
   ```

3. 两者都失败且已重试无效 → 按第 6 节异常处理回滚。

**Cookie 约束（重要）**：

- cookie 文件固定在仓库根 `.agents/bili-subtitle/cookies.txt`（该目录已在 `.gitignore` 中，不会进 git），**严禁**复制到仓库其它位置、提交、上传或写入博客；
- cookie 有效期约 6 个月（当前这枚至 2027-04）。若 yt-dlp 报「Subtitles are only available when logged in」或返回未登录，用官方接口检查：`curl -s -G 'https://passport.bilibili.com/x/passport-login/web/cookie/info' --data-urlencode 'csrf=<bili_jct值>' -b <cookie文件>`——`refresh: true` 或未登录时**不要反复重试**，在回滚标记时注明「cookie 需更换」，等待人工处理。

**远程中转（限流兜底）**：

- **触发条件**：下载或字幕抓取遇到限流（HTTP 429、风控验证、频繁失败）且本地重试无效时。
- **唯一允许的远程机器**：`jdcloud`（`~/.ssh/config` 已配置，即 `root@117.72.151.12`）。**严禁接触、扫描或登录任何其它远程机器**。
- **中转流程**：
  1. `ssh jdcloud`，在远程用 yt-dlp 等工具下载视频 / 抓取字幕；
  2. 用 `scp` 将产物传回本地 `temp/reinforcement_learning/<条目名>/` 对应子目录（视频放 `videos/`、字幕放 `subs/`）；
  3. **确认本地文件完整**（大小一致、能正常读取）后，**必须删除 jdcloud 上的临时下载文件**，不留残留；
  4. 断开连接，继续本地流程（抽帧及后续步骤仍在本地做）。
- 若 jdcloud 也被限流，记录原因并按第 6 节异常处理回滚，不得寻找其它机器。

## 4. 博客落位

层级是 `## 第 N 篇` → `### 第 N 章` → `- N.M 条目`，**没有 X.Y 小节层**，所以章节目录就是落位目录：

`content/reinforcement_learning/第<N>章_<章标题>/`（如 `第5章_时序差分学习Temporal-Difference Learning`，章节标题里的英文括号与空格可保留）

- **该条目只选了 1 个视频** → 不建子目录，博客直接放章节目录：

  ```
  content/reinforcement_learning/第5章_时序差分学习/时序差分TD(0)预测.md
  content/reinforcement_learning/第5章_时序差分学习/assets/时序差分TD(0)预测/
  ```

- **该条目选了多个视频** → 每个视频一个子目录：


- 配图 `assets/` 必须与博客一起放；**只放博客与配图**，字幕、文稿、视频一律不进 `content/`。

### 4.1 公式与记号（重要）

站点**未启用 MathJax/KaTeX**（`mkdocs.yml` 无 `pymdownx.arithmatex`），裸 `$...$` 会原样显示成美元符号。因此博客里：

- 行内公式用**代码样式**：`V(s) = E[R + γV(s')]`，或用 Unicode 直写 `V(s) = E[R + γV(s′)]`；
- 成块推导用围栏代码块：

  ```
  Q(s,a) ← Q(s,a) + α [ r + γ max_a' Q(s',a') − Q(s,a) ]
  ```

- 不要写 `$\epsilon$`、`\text{TD}(\lambda)` 这类 LaTeX 命令；统一用 `ε`、`TD(λ)` 等 Unicode 写法。
- 具体判据是**不得出现 LaTeX 数学定界符**（`$...$`、`$$...$$`）与 LaTeX 命令（`\epsilon`、`\text{}`、`\frac` 等）。普通的美元符号（如金额 `$5`）本身不受限制，只是本系列基本用不到。
- 记号首次出现给全称（状态价值 `V(s)`、动作价值 `Q(s,a)`、优势 `A(s,a)`），后文保持一致，同一篇内不要混用 `V_π` 与 `V^π` 两种写法。

```markdown
- 5.2 TD(0) 预测算法：TD 目标与 TD 误差 **【已完成】** 📺 [TD(0)预测算法详解](第5章_时序差分学习/TD(0)预测算法详解.md)
```

```markdown
- 9.3 近端策略优化 (PPO)：PPO-Penalty 与 PPO-Clip **【已完成】** 📺 [PPO原理与推导](第9章_现代主流深度强化学习算法/9.3_近端策略优化PPO/PPO原理与推导.md) · 📺 [PPO代码实操](第9章_现代主流深度强化学习算法/9.3_近端策略优化PPO/PPO代码实操.md)
```

**并发写入要求**：此时可能已有别的运行改过 README。必须重读文件、**只替换自己那一行**（`grep -n` 定位后 `sed -i`，或 Python 按行内容精确匹配单行替换），不得整文件重写；写完后重读确认自己那行是 `【已完成】` 且其它行未被自己改动。若自己的行已被改回空（被别的运行当残留回收），**不要抢回**：检查自己的博客是否已落位——已落位则补写完成标记，否则直接结束本次运行（避免重复产出）。

完成后清理 `temp/reinforcement_learning/<条目名>/`（可选），**结束本次运行，不处理下一个条目**。

## 6. 异常处理

| 情形 | 处理 |
|---|---|
| 下载/抽帧/字幕失败（重试 1 次仍失败） | 清理临时目录，标记回滚为待处理，结束 |
| 看到别人标记的 `【处理中】` 但博客不存在 | **不抢跑**：temp 近 60 分钟无变动才按 1.1 节当残留回收，否则跳过 |
| 自己的条目被别的运行改回未标记 | 博客已落位就补写完成标记，否则结束本次运行 |
| 完成标记中链接指向的文件不存在 | 该条目视为待处理（若其同时被标 `【处理中】`，按 1.1 节超时规则处理） |

## 7. 驱动模式（批量自动处理）

由 `scripts/rl_auto_process.sh` 驱动时，除本节外**全部沿用第 0~6 节**，不另设规则副本。差异只有三点：

| 项目 | 差异 |
|---|---|
| 认领 | **跳过第 1 节**。条目已由驱动脚本预先标好 `**【处理中】**`，直接开工 |
| 并发 | 每批固定 2 个条目并行，各自独立 temp 目录与博客目录，互不干扰 |
| 失败回滚 | 把自己那行的 `**【处理中】**` 去掉（回滚为待处理），并在结束消息里说明原因 |

其余（探索与选题取向、字幕降级链、落位规则、公式与记号、回写标记、异常处理）一律以第 2~6 节为准。
