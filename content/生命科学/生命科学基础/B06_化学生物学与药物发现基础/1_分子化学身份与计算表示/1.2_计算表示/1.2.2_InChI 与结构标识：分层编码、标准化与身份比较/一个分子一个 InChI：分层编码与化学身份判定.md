# 一个分子一个 InChI：分层编码如何判定化学身份

> 视频来源：[InChI: Measuring the Molecules](https://www.youtube.com/watch?v=B881b5BasnU)（YouTube · AI3SD Online Seminar，讲者 Jonathan Goodman，剑桥大学化学系）｜时长约 46 分钟
> 导读：这是一场从「什么是一个分子」讲起的报告，用同一个分子的五种写法、咖啡因的逐层拆解、以及一次真实的 InChIKey 碰撞，把 InChI 的分层设计、编号算法和身份判定规则讲透。本文按「为什么需要 → 分层怎么读 → 编号怎么来 → 哪些结构会出问题 → InChIKey 怎么用」重排，SMILES 语法请回看 1.2.1，构象问题见 1.2.3。

## 本讲要解决的核心问题（SCQA）

**背景**：化学家描述一个分子有很多手段：IUPAC 名称、CAS 登记号、SMILES 字符串、二维结构图、mol 文件。数据库、专利、论文里到处都在用这些写法。

**冲突**：这些写法没有一种能同时做到「唯一」和「自己就能算出来」。同一个分子有两个都正确的系统名；CAS 号必须向美国化学文摘社申请；同一个分子可以写出很多条都合法的 SMILES；二维图更是想怎么摆就怎么摆。于是两个人在不同地方做同一个分子，很可能拿到不同的字符串，数据库查重、跨库合并、专利比对都会出错。

**疑问**：有没有一种字符串，**一个分子只对应一个、一个只对应一个分子**，而且不需要跟任何机构打交道，只凭结构本身就能算出来？

**回答（中心思想）**：有，就是 **InChI**（International Chemical Identifier，国际化学标识符）。它把「你说得有多细」拆成一层层可选的**层（layer）**：分子式、连接关系、氢原子位置、电荷、立体化学、同位素、固定氢。同一层里再靠**规范化 + 图同构编号**保证「不管你从哪个原子开始画，算出来的串都一样」。需要塞进定长字段或丢进搜索引擎时，再把它哈希成 **InChIKey**——代价是不可逆，而且极低概率会碰撞。

## 一、同一个分子有五种写法，只有一种能当「身份证」

### 1.1 名称：两个都对，但互相认不出来

报告开场展示了一个很普通的分子——对氯苯乙酮。它有两个都正确的系统名：

- `1-(4-chlorophenyl)ethan-1-one`（英式命名，把主体看成乙酮）
- `4-chloroacetophenone`（美式命名，把主体看成苯乙酮加一个氯）

两个名字都「完全合理」，但它们强调的骨架不同。讲者指出的问题很实际：如果你在找其中一个名字对应的东西，很可能根本意识不到另一个名字说的就是它。

### 1.2 CAS 号：唯一，但要向机构申请

更省事的办法是登记号。美国化学文摘社（CAS）给这个分子分配了 `99-91-2`：有人把结构交给他们，他们保证这个号不会再分配给别的分子，于是「一号一物、一物一号」基本成立。

代价是这套系统**只因为 CAS 这个机构存在才成立**。讲者的原话很直白：你只能通过和 CAS 打交道才能拿到 CAS 号——如果你在发明新分子，而你又没在跟哥伦布市（CAS 总部所在地）联系，那就很麻烦。

[【跳转到 03:02】](https://www.youtube.com/watch?v=B881b5BasnU&t=182)

### 1.3 SMILES：人能读，但不唯一

SMILES 是另一条路：把结构写成字符串，`CC(C1=CC=C(Cl)C=C1)=O`。它「差不多」人能读——`C` 是碳，`CC` 是两个碳相连，括号是支链，数字是环的闭合标记。

问题在于**起点可以随便选**。你可以从氯开始写，可以从环上某个碳开始写，也可以先绕一圈再补氧。讲者的结论是：一条 SMILES 只对应一个分子，但一个分子可以有很多条都正确的 SMILES。两个人各写各的，字符串就不一样，搜索和比对都很难做。

苯环是最清楚的例子：`C1=CC=CC=C1`（凯库勒式，用双键表示芳香性）和 `c1ccccc1`（小写表示芳香原子）都是好写法，但它们是两条不同的字符串。

![苯的多种表示：CAS、两条 SMILES、一条 InChI、一条 InChIKey](assets/一个分子一个%20InChI：分层编码与化学身份判定/00532.webp)

[【跳转到 08:52】](https://www.youtube.com/watch?v=B881b5BasnU&t=532)

### 1.4 InChI：唯一性来自算法，不来自登记

InChI 的设计目标正好补上前两者的缺口：**一个分子只有一条 InChI，一条 InChI 只对应一个分子**，而且转换程序是开源、放在公有领域的，谁都能自己算，不必问任何机构。

苯的 InChI 是这样的：

```text
InChI=1S/C6H6/c1-2-4-6-5-3-1/h1-6H
```

注意 `c` 后面那串编号的顺序 `1-2-4-6-5-3-1` 看起来毫无逻辑——这正是重点：它不是人挑的，是算法算出来的。讲者的说法是：写 InChI 时你必须按这个顺序编号，这一点极其重要。

## 二、InChI 的承诺：同结构同串，不同结构不同串

### 2.1 两条硬要求

讲者把 InChI 的要求归结成两条对称的约束：

1. **怎么画都得是同一串**：同一个化合物，不同人用不同风格画出来，必须归一到同一条 InChI。
2. **不同结构必须不同串**：顺式和反式辛三烯长得像，但它们是不同的东西，就该有不同的 InChI。

另外还有几条工程上的要求：纯文本字符格式；能处理化学中大量存在的「平衡态结构」（一瓶试剂里往往是几种互变形态的混合物）；要能容纳人画结构时犯的错——尤其是立体化学，几乎人人都会标错，所以这部分信息要单独放进一层，出错时不至于把整个搜索毁掉。

### 2.2 名字生成不出来时，InChI 仍然给得出

讲者用同事做出的一个无机大环分子做对照：ChemDraw 的「结构转名称」功能直接回复 **A name could not be generated for this structure**（无法为该结构生成名称）。SMILES 可以生成，但同样有很多条——幻灯片上给出的是其中一条，长达数行；InChI 也能算出来，只是很长：

这条串以 `InChI=1S/C40H95N15P10/c1-31(2,3)46-56-41-58-...` 开头，后面是一长串连接编号，最后以氢层 `/h41-45H,1-30H3` 收尾——完整串在幻灯片上占满一整行。这说明了 InChI 的定位：它不追求好读，只追求**可算、唯一、可机读**。

## 三、分层：InChI 把「你知道多少细节」写进字符串

InChI 最核心的设计就是**分层**。每一层用斜杠 `/` 开头，前面带一个字母标记这一层是什么；只有分子式那一层不带字母——讲者特意强调：**分子式是唯一不以字母开头的一层**。

### 3.1 主层：分子式 + 连接关系

以咖啡因为例：

```text
InChI=1S/C8H10N4O2/c1-10-4-9-6-5(10)7(13)12(3)8(14)11(6)2/h4H,1-3H3
```

拆开看：

| 片段 | 含义 |
| --- | --- |
| `InChI=1S` | 这是 InChI，版本 1，`S` 表示 **Standard InChI**（标准 InChI） |
| `C8H10N4O2` | 分子式，按 Hill 顺序：先碳、再氢、其余元素按字母序 |
| `/c1-10-4-9-6-5(10)7(13)12(3)8(14)11(6)2` | 连接层：原子 1 连 10、连 4、连 9、连 6…… |
| `/h4H,1-3H3` | 氢原子层：4 号原子上有 1 个氢，1 到 3 号原子各有 3 个氢 |

![咖啡因的 InChI 逐层标注：主层、/c 连接层、/h 氢层](assets/一个分子一个%20InChI：分层编码与化学身份判定/01665.webp)

[【跳转到 27:45】](https://www.youtube.com/watch?v=B881b5BasnU&t=1665)

### 3.2 氢原子层：把「会跑的氢」写成一组可能位置

氢层不只写「哪个原子挂几个氢」，还能写**可移动氢**。乙酰胺（acetamide）的例子：

```text
InChI=1S/C2H5NO/c1-2(3)4/h1H3,(H2,3,4)
```

`(H2,3,4)` 的意思是：这两个氢可以在 3 号和 4 号原子（氮和氧）之间移动。所以酰胺式和亚胺醇式这两种互变异构体，得到的是**同一条 InChI**。

![乙酰胺与它的亚胺醇式共用同一条 InChI，氢层写作 (H2,3,4)](assets/一个分子一个%20InChI：分层编码与化学身份判定/02040.webp)

[【跳转到 34:00】](https://www.youtube.com/watch?v=B881b5BasnU&t=2040)

### 3.3 电荷层 `/p`

质子化状态单独成层，前缀是 `/p`。例如 `/p+1` 表示整体带一个正电荷。讲者强调：**电荷是分子整体的属性，不属于某个特定原子**，所以它不写进连接层，而是单独一层。

### 3.4 立体层 `/t` `/m` `/s`：一个手性中心要三层来描述

立体化学用的是三个子层：

- `/t`：立体中心本身的构型（类似 `t1-`、`t5-`）
- `/m`：整个分子的镜像关系（`m0` / `m1`）
- `/s`：立体层的类型（`s1` 表示绝对立体化学）

讲者承认「一个手性中心用三层描述」听起来很奢侈，但这样做的收益是：既能表达**绝对**立体化学，也能表达**相对**立体化学，还能只比较前几层就做「宽匹配」。

### 3.5 同位素层 `/i` 与固定氢层 `/f`

同一个分子带同位素标记时，会多出 `/i` 层；如果还要把氢的位置彻底钉死（不允许互变），则再加 `/f` 固定氢层。下面这条 InChI 把五层一次性用全了：

```text
InChI=1/C2H4ClNO2/c3-1(4)2(5)6/h1H,4H2,(H,5,6)/p+1/t1-/m1/s1/i3+0/fC2H5ClNO2/h4-5H/q+1
```

按斜杠切开就是：主层 → `/p+1` 电荷层 → `/t1-/m1/s1` 立体层 → `/i3+0` 同位素层 → `/f...` 固定氢层 → `/q+1` 电荷（固定氢层内部）。

![一条 InChI 同时包含主层、电荷层、立体层、同位素层与固定氢层](assets/一个分子一个%20InChI：分层编码与化学身份判定/01840.webp)

[【跳转到 30:40】](https://www.youtube.com/watch?v=B881b5BasnU&t=1840)

注意这条串开头是 `InChI=1/` 而不是 `InChI=1S/`——因为它用了同位素层和固定氢层，超出了标准 InChI 的范围，属于**非标准 InChI**。这一点在跨软件交换数据时很关键：带 `1S` 的才是各方都认的标准串。

### 3.6 分层带来的实用技巧：截断比较

分层不只是为了好看，它直接支撑检索策略。想同时找到「某单一对映体」和「外消旋体」时，只要比较到主层为止、忽略后面立体层即可。讲者的说法是：只看 InChI 的开头、忽略最后一段，就能同时命中单一对映体、外消旋体和你要的那个对映体。

## 四、编号不是随便编的：规范化 + 图同构

### 4.1 三步流水线

讲者把 InChI 的生成概括成三步：

1. **规范化（normalization）**：把画出来的结构里「对命名没用的信息」去掉——电子密度、共振式的画法、部分立体标记等；这一步是「化学的部分」。
2. **数学处理（canonicalization）**：把结构当成一张数学图，用图论算法求出唯一的原子编号。讲者提到算法基于 McKay 的图同构工作，否则遇到高度对称的分子可能算到天荒地老。
3. **输出**：按编号顺序把结果拼成字符串。

### 4.2 编号规则：氢多的编号小

咖啡因的例子说明了规则的风格：三个甲基碳各带 3 个氢，编号是 1、2、3；4 号碳只带 1 个氢；其余碳不带氢。所以「氢越多的原子编号越小」是一条可观察到的规律。但为什么三个甲基偏偏是 1、2、3 这个次序而不是别的，讲者说「更微妙」——那是由算法在对称性破缺时决定的。

### 4.3 改一行代码，全世界的串都会变

这是 InChI 与普通字符串格式最大的区别：**它是一套算法，而不是一种文件格式**。讲者反复强调，算法里任何一行代码的细微改动，都会改变编号顺序，从而让所有已发布的 InChI 全部失效。所以标准只能有一份、必须集中维护——这也是 InChI 由 IUPAC 下设委员会托管、代码开源但只有一个官方实现的原因。

## 五、身份判定中最容易踩的四类结构

### 5.1 互变异构：默认允许质子移动

鸟嘌呤的四种互变异构体（酮式、烯醇式、亚胺式等）在 InChI 里得到的是**同一条串**：

```text
InChI=1S/C5H5N5O/c6-5-9-3-2-4(11)10-5-7-1-8-3/h1H,(H4,6,7,8,9,10,11)
```

`(H4,6,7,8,9,10,11)` 把可移动的氢一次性列了出来。讲者的判断是：如果这瓶东西放在水里，你根本分不出、也分不开这四种形态，那它们「也许就是同一个分子」；但如果你讨论的是气相中的孤立分子，或者反应机理中的某一步，它们又确实不同。

![鸟嘌呤的四种互变异构体共用一条 InChI](assets/一个分子一个%20InChI：分层编码与化学身份判定/02090.webp)

[【跳转到 34:50】](https://www.youtube.com/watch?v=B881b5BasnU&t=2090)

InChI 目前的取舍是：**上面这类互变体算同一个，但大多数互变异构体并不等同**。委员会仍在讨论这条界线该画在哪，讲者现场征集意见——这本身说明「互变异构对身份判定的影响」目前没有唯一正确答案，取决于你要拿标识做什么。

### 5.2 电荷离域：画法不同，串相同

Munchnone 类分子必须同时带正负电荷才能画出来，而负电荷画在氧上还是碳上，都是对同一个离域体系的不同近似。因为 InChI **不指定电荷具体落在哪个原子上**，这些画法会得到同一条 InChI——这既是优点（统一了不同人的画法），也提醒我们：InChI 描述的是「连接关系 + 整体电荷」，不是电子分布。

### 5.3 立体化学：主层相同，立体层不同

2-氯哌啶的两个结构最能说明立体层的作用：

```text
未标立体：InChI=1S/C5H10ClN/c6-5-3-1-2-4-7-5/h5,7H,1-4H2
标了立体：InChI=1S/C5H10ClN/c6-5-3-1-2-4-7-5/h5,7H,1-4H2/t5-/m1/s1
```

两条串的**主层完全一样**，差别只在末尾多出的 `/t5-/m1/s1`。这正是「未指定立体」和「指定了某一个对映体」在身份上的区别：前者是一个更宽的描述，后者是精确描述。

### 5.4 表示方式会改变立体层的解读：瑞德西韦的例子

这是全场最有警示性的案例。同一个瑞德西韦分子，画成两种二维图（一种强调它像 RNA 片段，一种用合成化学家习惯的伸展画法），按理应该得到同一条 InChI。

![瑞德西韦的两种二维画法：同一个分子，两种强调重点](assets/一个分子一个%20InChI：分层编码与化学身份判定/01221.webp)

[【跳转到 20:21】](https://www.youtube.com/watch?v=B881b5BasnU&t=1221)

实际算出来的结果是：

| 画法 | InChIKey |
| --- | --- |
| 画法一 | `URWWYLEGWBNMMLJ-YSOARWBDSA-N` |
| 画法二 | `URWWYLEGWBNMMLJ-YXUZYEHRSA-N` |

**第一段完全相同**（说明连接关系一致），**第二段不同**（说明立体化学被判为不同）。讲者起初也困惑，后来发现原因：他用 ChemDraw 生成 InChI 时，程序把两个立体中心当成了**未定义**——因为图里用了 `CN`、`PhO` 这类缩写，InChI 的转换程序没能正确理解它们代表什么。

![瑞德西韦两种画法的 InChIKey：第一段相同、第二段不同](assets/一个分子一个%20InChI：分层编码与化学身份判定/01321.webp)

这件事的教训有两层：

1. **立体中心一旦被漏判，身份就变了**。对瑞德西韦来说，那个立体中心对活性至关重要，判错等于换了一个分子。
2. **InChI 的差异可以当作质检信号**。如果你认为两张图是同一个东西，却算出不同的 InChIKey，那多半是某一步表示出了问题——这比人眼逐张核对可靠得多。

讲者还提到另一类漏判：螺环和缩醛类结构里，InChI 的算法**会漏掉极少数立体中心**。算法整体很强，但不是完美的。

## 六、InChIKey：定长哈希，方便检索但不可逆

### 6.1 结构：三段定长

InChIKey 是把 InChI 哈希压缩后的定长串。讲者的描述是「固定长度、25 个字符」，幻灯片上的写法是 `RYYVLZVUVIJVGH-UHFFFAOYSA-N`（咖啡因）。按 InChI 官方规范，它由三段字母组成、中间用两个连字符隔开：14 个字母 + 10 个字母 + 1 个字母，共 **25 个字母、27 个字符**（讲者说的 25 指字母数）。

三段的含义：

| 段 | 含义 |
| --- | --- |
| 第一段（14 字母） | 由连接关系（主层）哈希而来 |
| 第二段（10 字母） | 立体化学、同位素等附加信息 + 标志位 |
| 第三段（1 字母） | 校验字符 |

`UHFFFAOYSA` 这个组合反复出现在苯、咖啡因、对氯苯乙酮的 Key 里，它是「没有立体化学」的标志——所以看到它以 `UHFFFAOYSA` 结尾，就知道这条 Key 描述的是一个不区分立体的结构。

![InChIKey 的定义：25 字符定长、碰撞概率、咖啡因的 Key](assets/一个分子一个%20InChI：分层编码与化学身份判定/02290.webp)

[【跳转到 38:10】](https://www.youtube.com/watch?v=B881b5BasnU&t=2290)

### 6.2 不可逆：只能查表，不能反推

哈希是单向的。拿到 InChIKey，你没法把它还原成结构，甚至没法还原成 InChI。所以 InChIKey 只能当**检索键**用：数据库里同时存 InChI 和 InChIKey，用 Key 做快速匹配，命中后再用 InChI 确认。

（补充：正因为不可逆，社区后来做了 Resolver 之类的服务——拿 Key 去公开数据库里反查对应的 InChI。这属于应用层的补救，不是哈希本身可逆。）

### 6.3 碰撞：真实发生过

理论上 Key 会碰撞，只是概率极低——幻灯片给的数量级是「相当于 75 个十亿条记录的数据库里出现一次碰撞」。讲者随后讲了一次真实碰撞：抗生素大环内酯 **spongistatin 1** 和两个「不是 spongistatin」的立体异构体，算出了完全相同的 InChIKey：

```text
InChIKey=ICXJVZHDZFXYQC-AAAYXFPSBK
```

这三个分子的连接关系相同、立体化学不同，却撞在同一个 Key 上。原因不难理解：第二段只有 10 个字母，要装下大量立体中心的信息，空间不够。

![spongistatin 与两个立体异构体共享同一个 InChIKey](assets/一个分子一个%20InChI：分层编码与化学身份判定/02365.webp)

[【跳转到 39:25】](https://www.youtube.com/watch?v=B881b5BasnU&t=2365)

### 6.4 使用规则

讲者给出的判据很干脆：

- **Key 不同 → 两个分子一定不同**（可以放心排除）。
- **Key 相同 → 还要回查 InChI**（不能直接认定相同）。

这条规则应该写进任何用 InChIKey 做去重的流程里。

## 七、InChI 是索引，不是分子的完整描述

### 7.1 它不记录三维结构和构象

讲者明确说过：InChI 不试图编码三维结构，它给的是连接关系；同一个分子的不同构象在 InChI 里没有区别。分子的构象、运动、反应性都不在 InChI 里。所以 InChI 适合当**标识符**，不适合当**结构描述**。

[【跳转到 40:39】](https://www.youtube.com/watch?v=B881b5BasnU&t=2439)

### 7.2 它算不清的结构类型

讲者列举了 InChI 目前的短板：

- **有机金属化合物**：不是所有都能算，项目正在补。
- **高级立体化学**：当一个分子有两组立体中心、组内相对构型已知但组间关系未知时，现有 InChI 表达不了——这在天然产物结构鉴定里是真实问题。
- **互变异构**：策略仍在讨论（见 5.1）。
- **聚合物、混合物、纳米材料、超大分子**：需要专门的扩展（如聚合物用重复单元括号、反应另立 RInChI）。

### 7.3 扩展方向：从分子到反应、到二维码

报告的收尾是一张「轮盘」图：中心是 InChI，外面一圈圈是围绕它长出来的应用——InChIKey、RInChI（反应）、QR InChI（把 InChI 编成二维码贴在试剂瓶上）、MInChI（混合物）、以及面向聚合物、无机物、同位素体的各条分支。

## 小结

- **身份问题的根源**：名称、CAS 号、SMILES 各自只满足「唯一」或「可自算」中的一个；InChI 同时满足两个，代价是难读。
- **分层是 InChI 的核心**：分子式（唯一不带字母前缀的一层）、`/c` 连接、`/h` 氢、`/p` 电荷、`/t` `/m` `/s` 立体、`/i` 同位素、`/f` 固定氢；`1S` 前缀表示标准 InChI。
- **唯一性靠算法**：规范化去掉无关信息，图同构求唯一编号；算法改一行，全世界的串都会变，所以只能有一个官方实现。
- **互变异构默认归一**：可移动氢写成 `(H2,3,4)` 这样的形式，酰胺/亚胺醇、鸟嘌呤的多种互变体共用一条串；这条界线仍在讨论中。
- **立体层决定精确度**：未标立体与标了立体的分子主层相同、只差立体层；表示方式（缩写基团）可能导致立体中心被判为未定义，从而算出不同的 Key。
- **InChIKey 是哈希**：定长、便于检索、不可逆；Key 不同一定不同，Key 相同还要回查 InChI，因为碰撞真实发生过（spongistatin）。
- **InChI 是索引不是描述**：不含三维构象，有机金属、高级立体化学、聚合物与混合物仍在扩展中。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| InChI | 由结构算出的唯一文本标识符，IUPAC 标准，开源可自算 |
| Standard InChI | 用默认参数算出的 InChI，串以 `InChI=1S/` 开头，是各方互认的那一种 |
| 层（layer） | InChI 中以 `/` 分隔的信息块，越往后细节越多、越可省略 |
| 主层（main layer） | 分子式 + 连接关系，所有 InChI 都有 |
| 可移动氢 | 氢层里 `(H2,3,4)` 这类写法，表示氢可在几个原子间移动，用于归一互变异构体 |
| `/p` 电荷层 | 记录分子整体质子化/电荷状态 |
| 立体层 `/t` `/m` `/s` | 分别记录立体中心构型、镜像关系、立体层类型 |
| InChIKey | InChI 的定长哈希（25 字母 / 27 字符），用于检索，不可逆 |
| 碰撞（collision） | 不同结构算出同一个 InChIKey，概率极低但真实存在 |
| CAS 号 | 美国化学文摘社分配的登记号，唯一但需向机构申请 |
| 规范化（normalization） | 生成 InChI 的第一步：去掉与身份无关的表示差异 |
| 规范化编号（canonicalization） | 用图同构算法给原子定出唯一编号，保证同一结构同一串 |
