> 本文基于视频演说图文稿整理，配图截自视频。原视频为英文讲解 + 中英文字幕，本文按中文叙述重写；命令行与文件名保留原样。这是一支**动手演示**视频：它把"无模板从头预测"拆成片段库、片段插入、协议运行、打分筛选、收敛判断五步，正好补上理论课里看不到的工程细节。

## 本讲要解决的核心问题（SCQA）

**背景**：从头预测的原理一句话就能说完——在能量函数定义的构象空间里找最低点。但真到命令行上，你得先回答几个很具体的问题：能量面那么大，搜索从哪儿起步？每一步改什么？跑完几百个模型怎么挑？

**冲突**：如果每一步都让算法自己决定某个残基的二面角，搜索空间会大到无法收敛；如果只跑一个模型，你根本不知道它是不是运气好。

**疑问**：Rosetta 的 de novo 流程究竟用什么来压缩搜索空间、用什么来产生"合理"的构象变化、又用什么来判断"这一堆模型到底收敛了没有"？

**回答（中心思想）**：Rosetta 的做法是**用片段库把"连续的二面角空间"离散成"从真实结构里统计出来的局部构象"**——一次片段插入就是把一段残基的 φ/ψ/ω 换成片段库里某条记录的值；然后反复采样 + 打分，产出几百个模型；最后**不靠 native 结构**，而是用"候选模型相对最低分模型的 RMSD"来判断这一池模型是否收敛到同一个能量极小。

## 二、片段文件里装的是什么

先看体积。讲师用 `du -sh` 量了一下：**3 残基片段库 5.8 MB，9 残基片段库 17 MB**，而这只是一个 100 多残基的蛋白；蛋白大五倍，文件也大五倍。 [【跳转到 02:12】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=132)

![du 结果：3 残基片段库 5.8 MB，9 残基片段库 17 MB](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00132_fragment_sizes.webp)

所以它不可能用文本编辑器打开看，只能在命令行里 `head` 前几十行。内容长这样： [【跳转到 02:56】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=176)

![3 残基片段库内容：来源 PDB 与链、残基编号、phi/psi/omega 三列角度](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00176_frag3_content.webp)

每一行（严格说是每三行一组）记录的是：

- **来源**：`2oqa A`——这个片段取自 PDB 2OQA 的 A 链；
- **残基编号与类型**：`189 I`、`190 T`、`191 H`，即这段片段的序列身份；
- **三个主链二面角**：φ、ψ、ω 的具体数值（例如 −140.176 / 157.939 / −179.962）。

9 残基片段库格式完全一样，只是每组 9 行： [【跳转到 05:07】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=307)

![9 残基片段库：同样的字段，每组 9 行，覆盖更长的一段主链](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00307_frag9_content.webp)

这就把"片段插入"讲清楚了：**片段插入 = 把某一段残基的主链二面角替换成片段库里某条记录的数值**。 [【跳转到 02:56】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=176)

为什么这么做？因为主链几何几乎完全由 φ/ψ/ω 决定（键长键角基本固定）。与其在连续角度空间里随机游走，不如从"真实结构里出现过的角度组合"里抽一个——**每一个候选都天然是合理的局部构象**。3 残基片段负责微调，9 残基片段负责一次改出一段二级结构，长短片段配合是 Rosetta 采样的基本手感。

## 三、片段库从哪来：Robetta Fragment Server

片段库可以用 Robetta 的 Fragment Server 生成（需要学术许可）：打开 `old.robetta.org` → fragment libraries → 填邮箱、目标名、FASTA 序列 → 提交。 [【跳转到 03:56】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=236)

![Robetta Fragment Server 提交页：邮箱、目标名、FASTA，以及关键的 Exclude Homologues 选项](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00236_robetta_fragments.webp)

这里有一个**必须讲的坑**：片段是从一个蛋白结构数据库里抽出来的，而如果你要预测的蛋白已经有实验结构，它很可能就在那个数据库里。用自己蛋白的真实结构生成片段，等于把答案提前塞进搜索空间——**这是 benchmark 作弊**。所以要勾上 **Exclude Homologues** 并填 PDB 编号，把这些同源结构排除掉。 [【跳转到 03:56】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=236)

这条注意事项和本系列 1.2.5（结构模板）讲的是同一件事的两面：模板方法要防的是"训练/评测泄漏"，片段方法要防的是"片段来源泄漏"。两者都会让指标虚高。

## 四、跑一次 ab initio：选项文件与 246 秒

真正运行时，所有参数都写在一个 options 文件里（这里叫 `2LZM_broker.options`），命令行只需指向它，效果等同于把全部参数敲进命令行。 [【跳转到 05:07】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=307)

回车之后，一次 ab initio 预测大约 **5 到 10 分钟**。跑完目录里多出两个文件： [【跳转到 06:01】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=361)

![协议运行日志与产物：score.fsc 打分文件 + 结构输出文件](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00361_protocol_log.webp)

- `score.fsc`：打分文件，逐项列出打分函数各分量的值；
- 结构输出文件：模型本身（Rosetta 自己的格式）。

日志里还能看到协议内部在做什么：`FastRelax` 反复做 repack、min（侧链重排与能量最小化），`ClassicAbinitio` 负责主链采样，最后 Finished _0001 in 246 seconds——**一个模型 246 秒**。 [【跳转到 06:01】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=361)

这个数字很关键：折 100 个模型就是 6~7 小时，折 1000 个就是几天。**从头预测的成本是按"模型数 × 单模型时间"计的**，这正是上一篇文章里"200 残基上限"和"要等两三天"的微观来源。

## 五、读懂打分文件：列名就是能量函数的解剖图

`score.fsc` 第一行是表头，第二行是数值。总能量在第二列，其余每一列是一个能量项： [【跳转到 07:56】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=476)

![score.fsc：总分在第二列，其余列是 fa_atr、fa_rep、fa_sol、hbond_*、rama_prepro 等分量](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00476_scorefile.webp)

从表头能直接看出打分函数的构成（下一篇文章会逐项解释）：

| 列名 | 含义 |
| --- | --- |
| `score` | 加权总分，越低越好 |
| `fa_atr` / `fa_rep` | 范德华吸引项 / 排斥项 |
| `fa_sol` | 隐式溶剂化 |
| `fa_elec` | 静电 |
| `hbond_sr_bb` / `hbond_lr_bb` / `hbond_bb_sc` / `hbond_sc` | 主链短程、主链长程、主链—侧链、侧链—侧链氢键 |
| `dslf_fa13` | 二硫键 |
| `rama_prepro` | 主链 Ramachandran 偏好（知识基） |
| `omega` | 肽键 ω 角约束 |
| `rms` | 与 native 的偏差（仅 benchmark 时有意义） |

这个例子里，模型的 RMSD 是**二级结构残基上 1 Å、全部残基上 4.2 Å**——注意两者差很多：核心二级结构摆对了，但 loop 区还差得远。 [【跳转到 07:01】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=421)

## 六、从几百个模型里挑：silent 文件、表格与排序

真实使用中不会只跑一个模型。教程直接提供了几百个已生成的模型，它们被打包在一个 **silent 文件**里：每个模型一段记录，前面是打分项，后面是结构信息（二进制/编码形式，人读不了）。 [【跳转到 09:06】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=546)

![silent 文件：每个模型一段，含打分项与编码后的结构信息；下方是用 Python 脚本抽出的 table](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00546_silent_table.webp)

思路是"**别去读结构，只读分数**"：用教程附带的 Python 脚本把每个模型的 tag、核心残基 RMSD、总分抽成一张三列表格（`2LZM_models.table`），再用 `sort` 按分数从低到高排序。 [【跳转到 09:06】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=546)

拿到最低分模型的 tag 之后，用 Rosetta 自带的 **ScoreJD2** 把它从 silent 文件里单独抽出来，转成 PDB： [【跳转到 10:10】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=610)

```bash
# 从 silent 文件中抽出指定 tag 的模型，输出全原子 PDB
score_jd2 -in:file:silent 2LZM_broker_01.out \
          -in:file:tag S_0000010_6 \
          -in:file:fullatom \
          -out:file:fullatom \
          -out:pdb
```

不给 tag 就会把所有模型都抽出来——几百个 PDB 一次导出，磁盘会很难看。

## 七、没有 native 怎么知道"算对了"：收敛判据

这是整支视频最有价值的一段。真实预测时你**没有** native 结构，那怎么判断这堆模型可不可信？

讲师的答案是：**把每个模型与"最低分模型"算 RMSD**。 [【跳转到 11:35】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=695)

- 如果分数好的那些模型彼此 RMSD 都很低 → 说明它们收敛到了**同一个能量极小**，这一池模型很可能代表类天然状态；
- 如果 RMSD 到处都是 → 说明根本没收敛，**这些模型都不该信**。

做法上还是用 ScoreJD2，只是加一个"与指定 PDB 比较"的 flag，并指定用哪些残基来算 RMSD，重新打分后得到新表： [【跳转到 12:17】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=737)

![按分数排序的新表：最低分模型对自己 RMSD 为 0，紧随其后的模型 RMSD 只有 1.5~1.8 Å](assets/Rosetta%20从头折叠实操：片段库、片段插入与模型收敛判断/00805_sorted_scores.webp)

结果很干净：最低分模型对自己当然是 0，紧随其后的模型是 1.8、1.8、1.5 Å——**收敛了**。这个例子里还能用 native 的 RMSD 交叉验证，但即使没有 native，这个"相对最低分模型的 RMSD 分布"也足以支撑结论。 [【跳转到 13:25】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=805)

把它和上一篇文章的模型质量评估放在一起看，无模板路线的验收其实有三层：

1. **能量层**：总分够低（打分函数自己给的）；
2. **一致性层**：多个模型彼此 RMSD 小（本节讲的收敛判据）；
3. **几何层**：Verify3D、拉氏图等独立工具检查立体化学是否合理。

三层都过，才敢说"这个模型可以用"。

## 八、边界：这是"盲折"，更常见的是带约束的折叠

视频结尾提到教程还有两部分：**用约束折叠蛋白**和**膜蛋白折叠**，并建议一定要过一遍前者，因为"那可能是你更常遇到的情形，而不是像这样盲折"。 [【跳转到 14:45】](https://www.bilibili.com/video/BV1jM4y1F7ka/?t=885)

这句话点出了从头预测的定位：**完全无信息的盲折是它的极限用法**。实际项目里通常有交联质谱距离、突变效应、低分辨率电镜轮廓、同源片段等弱信息，把它们作为约束/restraint 加进能量函数，能把搜索空间再砍掉一大块，成功率显著提高。

这也解释了为什么"纯从头"路线在 AlphaFold 之后迅速退居二线：AlphaFold 类方法把"同源信息"以 MSA 的形式直接喂进网络，本质上也是给搜索加了极强的先验，只是先验的来源和用法不同（见 1.2.9）。

## 小结

- 从头折叠的输入不只是序列：还需要**二级结构预测**和**两个片段库**（3 残基与 9 残基）。
- 片段库记录的是"某段残基的 φ/ψ/ω 来自哪个 PDB 结构"，所以**片段插入就是替换主链二面角**；片段的长度决定了每次改动的尺度。
- 片段库要防泄漏：benchmark 时必须勾 **Exclude Homologues**，否则等于用答案生成候选。
- 一次 ab initio 约 5~10 分钟、单模型 246 秒；成本按"模型数 × 单模型时间"增长，这是链长上限的微观原因。
- 打分文件 `score.fsc` 的每一列就是一个能量项（范德华、溶剂化、静电、氢键、二面角偏好……），总分在第二列。
- 几百个模型存在 silent 文件里，先用脚本抽成"tag / RMSD / score"三列表格排序，再用 ScoreJD2 抽取指定模型为 PDB。
- **没有 native 时的收敛判据**：算每个模型与最低分模型的 RMSD；分数好的模型彼此 RMSD 低 = 收敛可信，RMSD 散乱 = 不可信。
- 盲折只是极限用法；带实验约束的折叠更常见、也更可靠。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 片段库（fragment library） | 从 PDB 统计出的短片段集合，每条记录是一段残基的 φ/ψ/ω 值 |
| 片段插入（fragment insertion） | 把一段残基的主链二面角替换成片段库中某条记录的值 |
| 3-mer / 9-mer 片段 | 长度为 3 或 9 个残基的片段；短片段微调、长片段一次改出一段二级结构 |
| Robetta Fragment Server | 在线生成片段库的服务器，可勾选排除同源结构以防泄漏 |
| options 文件 | 把一次运行的全部 Rosetta 参数写进文件，命令行只引用它 |
| score.fsc | Rosetta 的打分文件，逐列给出各能量项与总分 |
| silent 文件 | 把多个模型（打分 + 结构）打包在一个文件里的格式 |
| ScoreJD2 | Rosetta 应用：从 silent 文件抽取模型、转 PDB、重新打分 |
| 收敛判据 | 用候选模型相对最低分模型的 RMSD 判断这一池模型是否落在同一能量极小 |
| 约束（constraint / restraint） | 把实验得到的距离等信息加入打分，缩小搜索空间 |
