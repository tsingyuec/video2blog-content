# 容器技术自动整理任务规则

> 供 Maka 定时任务使用。目标文件：`/workspace/working/video2blog-content/content/容器技术/README.md`
> 工作目录：`/workspace/working/video2blog-content`

## 0. 运行模型

- 每次定时触发 = **一次独立运行**，运行间无记忆。进度只存在于 README 的行尾标记里，每次运行必须重读 README 定位。
- 一次运行**只处理一个条目**，完成即结束。
- **待处理条目**：README 中第一个以 `-` 开头（前可有空格）且行尾**没有** `【处理中】` / `【已完成】` 标记的行。

## 1. 认领

1. 读取 README，找到第一个待处理条目；若全部已标记，结束本次运行。
2. **并发防护**：若发现某个条目已标记 `**【处理中】**`：
   - 其对应博客已存在 → 按已完成处理（补写完成标记）后继续；
   - `temp/<条目名>/` 存在且最近 10 分钟内有文件变动 → 上一次运行可能仍在进行，**本次直接结束**；
   - 否则视为中断残留：清理临时目录，回滚该条目标记，按待处理处理。
3. 在目标条目行尾追加 `**【处理中】**` 并保存（先标记后干活）。

## 2. 探索视频

以条目内容（含编号、括号注记）构造中英文关键词，在 Bilibili / YouTube 探索：

1. **筛选**：按标题、简介剔除不相关或低质视频。
2. **精排**：对前 5~8 个候选**抓取字幕**，按内容详细程度与质量排序（是否系统覆盖知识点、是否适合初学者、信息密度）。
3. **同分时 Bilibili 优先于 YouTube**。
4. 选出 **1~3 个**视频；单个视频已充分覆盖则只选 1 个。

## 3. 处理视频

- 前置：确认已安装 `video2blog` skill（见仓库根 `AGENTS.md`）。
- 所有中间产物（视频 / 抽帧 / 字幕 / 图文稿）放 `temp/<条目名>/`，按 video2blog 流程：**下载 → 抽帧 → 抓字幕 → 图文稿 → 通顺化**。
- `<条目名>`：条目编号+文字（如 `1.1.1_forkexec与进程创建`），去掉文件系统非法字符。

### 3.1 字幕获取降级链与限流应对

**字幕获取优先级**：
1. **首选**：kedou.life（与 video2blog skill 默认一致）；
2. **kedou 限流 / 失败时**：用 yt-dlp + B 站登录 cookie 直接抓取官方 AI 字幕：

   ```bash
   yt-dlp --cookies .agents/bili-subtitle/cookies.txt \
     --write-subs --sub-langs "ai-zh,zh-CN,zh" --sub-format srt --skip-download \
     -o "temp/<条目名>/subs/%(id)s" "<视频URL>"
   ```

3. 两者都失败且已重试无效 → 按第 6 节异常处理回滚。

**Cookie 约束（重要）**：

- cookie 文件固定在仓库根 `.agents/bili-subtitle/cookies.txt`（该目录已在 `.gitignore` 中，不会进 git），**严禁**复制到仓库其它位置、提交、上传或写入博客；
- cookie 有效期约 6 个月（当前这枚至 2027-04）。若 yt-dlp 报「Subtitles are only available when logged in」或返回未登录，用官方接口检查：`curl -s -G 'https://passport.bilibili.com/x/passport-login/web/cookie/info' --data-urlencode 'csrf=<bili_jct值>' -b <cookie文件>`——`refresh: true` 或未登录时**不要反复重试**，在回滚标记时注明「cookie 需更换」，等待人工处理。

**远程中转（限流兜底）**：

- **触发条件**：下载或字幕抓取遇到限流（HTTP 429、风控验证、频繁失败）且本地重试无效时。
- **唯一允许的远程机器**：`jdcloud`（`~/.ssh/config` 已配置，即 `root@117.72.151.12`）。**严禁接触、扫描或登录任何其它远程机器**。
- **中转流程**：
  1. `ssh jdcloud`，在远程用 yt-dlp 等工具下载视频 / 抓取字幕；
  2. 用 `scp` 将产物传回本地 `temp/<条目名>/` 对应子目录（视频放 `videos/`、字幕放 `subs/`）；
  3. **确认本地文件完整**（大小一致、能正常读取）后，**必须删除 jdcloud 上的临时下载文件**，不留残留；
  4. 断开连接，继续本地流程（抽帧及后续步骤仍在本地做）。
- 若 jdcloud 也被限流，记录原因并按第 6 节异常处理回滚，不得寻找其它机器。

## 4. 博客落位

基于图文稿写博客，落到 `content/容器技术/<所属小节>/`（`<所属小节>` = 该条目上方最近的 `### X.Y` 标题，目录名 `编号_标题`，如 `1.1_进程与执行模型`；注意：容器技术的层级是 `## 第 N 章` → `### X.Y 小节` → `- X.Y.Z 条目`，章节子目录取小节层）：

- **该条目只选了 1 个视频** → 不建子子目录，博客直接放章节目录：

  ```
  content/容器技术/1.1_进程与执行模型/进程与forkexec.md
  content/容器技术/1.1_进程与执行模型/assets/进程与forkexec/
  ```

- **该条目选了多个视频** → 每个视频一个子子目录（`temp/` 中的条目目录迁入）：

  ```
  content/容器技术/1.1_进程与执行模型/1.1.1_forkexec与进程创建/进程与forkexec.md
  content/容器技术/1.1_进程与执行模型/1.1.1_forkexec与进程创建/assets/进程与forkexec/
  ```

- 配图 `assets/` 必须与博客一起放；**只放博客与配图**，字幕、文稿、视频一律不进 `content/`。


## 5. 回写标记

把条目行尾的 `**【处理中】**` 替换为携带 Markdown 链接的完成标记（相对 README 所在目录的路径）：

```markdown
- 1.1.1 fork/exec 与进程创建 **【已完成】** 📺 [进程与forkexec](1.1_进程与执行模型/进程与forkexec.md)
```

多视频用 ` · ` 分隔多个链接：

```markdown
- 1.2.2 mount 与挂载命名空间 **【已完成】** 📺 [Linux挂载机制详解](1.2_文件系统与挂载/1.2.2_mount与挂载命名空间/Linux挂载机制详解.md) · 📺 [命名空间实战](1.2_文件系统与挂载/1.2.2_mount与挂载命名空间/命名空间实战.md)
```

找不到合适视频时：`**【已完成】**（未找到合适视频：<原因>）`，跳过该条目。

完成后清理 `temp/<条目名>/`（可选），**结束本次运行，不处理下一个条目**。

## 6. 异常处理

| 情形 | 处理 |
|---|---|
| 下载/抽帧/字幕失败（重试 1 次仍失败） | 清理临时目录，标记回滚为待处理，结束 |
| 条目标记 `【处理中】` 但博客不存在（上次中断） | 清理临时目录，回滚标记，本次重新处理 |
| 完成标记中链接指向的文件不存在 | 该条目视为待处理 |
