# 两种掩码各挡什么：Padding mask 管空位，Sequence mask 管未来

> 视频来源：[1.4.5 大模型掩码机制：Padding mask 与 Sequence mask](https://www.bilibili.com/video/BV1fuPizoEBD/?t=0)（Bilibili）
> 本文基于视频演说图文稿整理，配图截自视频。

![本讲主题：大模型掩码机制，两条主线分别是 Padding Mask 与 Sequence Mask](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00000.webp)

## 本讲要解决的核心问题（SCQA）

**背景**：Transformer 的注意力机制本质上是"每个位置去所有位置取信息"。所谓掩码（mask），就是个工具，像一块遮光板，把注意力计算中某些不想要的部分盖住——这个想法其实很早就有，Word2Vec 的 CBOW（用上下文预测中心词）里就有类似操作 [【跳转到 00:05】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=5)。

**冲突**：这块遮光板在 Transformer 里要盖两处完全不同的东西。一处是 minibatch 里为了对齐长度而补出来的填充符号 PAD，另一处是解码器训练时还不该被看到的"未来词"。两者都叫 mask，但一个按"这个格子是不是空的"来挡，一个按"这个格子是不是还没发生"来挡；混淆了就会写出"该挡的没挡住、不该挡的挡住"的代码。

**疑问**：这两种掩码各自挡什么？在计算流程的哪一步落地？形状为什么不一样？同时存在时怎么合并？

**回答（中心思想）**：**两者机制相同、判据不同**。机制相同——都在算完 $QK^T$ 之后、softmax 之前，把要屏蔽的位置的分数拉到一个极大的负数（如 $-10^9$ 或 $-\infty$），让 softmax 之后的权重变成 0；判据不同——padding mask 看"这一列是不是 PAD"，与句长有关、与顺序无关；sequence mask 看"这一列是不是在当前行之后"，是一张下三角矩阵，与句长和位置都有关。多个掩码并存时按"任一要求屏蔽就屏蔽"合并。

## 一、掩码是一块遮光板：它挡的是权重，不是内容

![Transformer 掩码机制概述：掩码是与目标张量同形的二值张量，自注意力里主要有 Padding Mask 与 Sequence Mask 两种](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00005.webp)

视频给的定义很直接：**掩码（Mask）是与目标张量同形的二值张量，用于"遮盖"特定位置** [【跳转到 00:00】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=0)。这句话里有两个关键词值得抠一下：

- **同形**：掩码的形状和被遮的东西一样。要遮注意力分数矩阵，掩码就得是"查询数 × 来源数"；要遮整个序列的特征，掩码就得是"批大小 × 序列长度"。形状对不上，广播（broadcast）就会把掩码贴错地方。
- **二值**：它本身只表达"留 / 不留"，不携带语义信息。这也是它便宜的原因——一个布尔张量而已。

在 Transformer 的自注意力里，这块遮光板主要有两种用法：**Padding Mask** 处理变长序列的填充符号，**Sequence Mask** 防止模型在生成时看到未来信息（因果性）[【跳转到 00:05】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=5)。

需要强调一点：掩码盖住的是"取用比例"，不是"内容本身"。被屏蔽的位置的词向量仍然在张量里、仍然参与 $QK^T$ 的矩阵乘法，只是它最后分到的权重为 0，于是在加权求和时贡献为零。理解这一点，后面所有"为什么要在 softmax 之前动手"的问题都会顺理成章。

## 二、Padding Mask 挡的是"为了对齐而补出来的空位"

### 2.1 没有 PAD 就没有 batch

![Padding Mask 要避免偏差：批量处理需要统一序列长度，截断或填充是必要手段](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00030.webp)

训练时经常把一堆句子打包成一个 batch 一起喂进去。麻烦在于每个句子长度不一样，而张量必须是规整的矩形。视频用了一个很形象的比喻：总不能让短的句子补点啥、长的句子砍掉点啥吧——为了整齐划一，通常会在短句后面加一些没意义的填充符号，比如 PAD，就像给短裤后面缝个补丁 [【跳转到 00:30】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=30)。

合并两句话，通常两种手段：**截断（Truncate）** 把过长序列截断，**填充（Pad）** 在短序列末尾补特殊符号。这样所有句子长度一样了，才能组成一个"批大小 × 序列长度 × 隐藏维度"的三维张量送进模型。

### 2.2 空位为什么会捣乱：因为 $\exp(0) = 1$

这里有个坑。这些 PAD 符号通常是 0 或者很小的随机数。如果在算注意力分数时把它们也当成正常词对待，它们就会参与 softmax 计算——而 $\exp(0) = 1$，这玩意儿在 softmax 里是个正经角色，会抢走其他真实词语的注意力权重 [【跳转到 00:55】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=55)。

视频的比喻是"你开会，结果让空气也举手发言，那还得了"。危害不只是浪费一点权重：**只要空位的数量随 batch 变化，"空气"分走的总份额就跟着变化，同一个真实 token 的权重就会被不同的 padding 挤成不同的值**，这就是标题里说的"引入偏差"。模型明明读的是同一句话，只因为同一批里别的句子更长，输出就变了。

还有一个更隐蔽的问题：PAD 位置的**行**也是没意义的。一个 PAD 行算出来的输出本来就不该被使用，但如果它去读了真实词的内容，它的输出就成了"有意义的错值"，一旦被后面的损失函数或池化操作误用，就会污染训练。

### 2.3 落地：算完 $QK^T$、softmax 之前，把分数拉到负无穷

![Padding Mask 实现细节：布尔型用 False 标记需处理位置，浮点型填极小数如 −1e9；四步走完整个流程](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00205.webp)

具体做法是：在算完 $Q$ 乘以 $K$ 的转置得到注意力分数之后、但在 softmax 之前，把这些填充位置的分数直接拉到负无穷 [【跳转到 01:20】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=80)。这样经过 softmax 归一化，这些位置的权重就变成 0 或无限接近于 0，相当于告诉模型：这些地方是空的，别理它们。

视频把实现拆成四步 [【跳转到 03:25】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=205)：

1. **创建掩码矩阵**，形状与注意力分数矩阵 $QK^T$ 相同。常见两种表示：**布尔型**用 True/False 表示是否需要处理（False 表示需屏蔽的位置）；**浮点型**直接在需要屏蔽的位置填一个非常小的数，比如 $-1e9$（即 $-10^9$），其他位置填 0。
2. **把掩码矩阵加到原始注意力分数矩阵上**。填充位置本来就是 $-10^9$，加上之后这些位置的分数也变成 $-10^9$。
3. **应用 softmax**。由于 $-10^9$ 这个数实在太小，它的指数几乎就是 0，归一化后权重变成 0 或极接近 0；而其他有效位置的权重则保持不变——因为它们的分数没被干扰。
4. **用权重矩阵加权求和 $V$**。填充位置的权重已经是 0，所以它们的 $V$ 向量在最终加权和里自然没有贡献 [【跳转到 04:15】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=255)。

写成式子：

$$
S = \frac{QK^{T}}{\sqrt{d_k}}, \qquad
\tilde{S} = S + M_{\text{pad}}, \qquad
A = \operatorname{softmax}(\tilde{S})
$$

其中掩码矩阵 $M_{\text{pad}}$ 的元素取两个值：

$$
M_{\text{pad}}(i, j) =
\begin{cases}
-10^{9}, & \text{第 } j \text{ 位是 PAD} \\
0, & \text{第 } j \text{ 位是真实 token}
\end{cases}
$$

注意这个判据**只与列（来源位置）有关，与行无关**：只要第 $j$ 个位置是 PAD，那么所有查询行都不该看它，于是掩码的那一列整列都是极小值。这就是填充掩码在"列方向"上的一致性——也正因为如此，实现里常常直接用一个形状为"批 × 序列长度"的小掩码，靠广播把它铺到"序列长度 × 序列长度"的分数矩阵上。

## 三、Sequence Mask 挡的是"这个位置还没被写出来"

### 3.1 并行的代价：teacher forcing 把答案也一起喂了进去

Sequence Mask 更关键，主要用在解码器（decoder）里。解码器的任务是生成一个序列，比如翻译一句话或写一首诗：一个词一个词往外蹦，每蹦出一个新词，就基于已经蹦出来的词决定下一个词是什么——这就是所谓的**自回归特性** [【跳转到 01:45】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=105)。

但在训练时，为了加速，我们常常搞个 **teacher forcing**：一次性把整个目标序列喂给解码器，让它并行预测所有位置。这就尴尬了：如果解码器能看到整个句子，那它预测第 $T$ 个词时岂不是可以直接偷瞄后面的第 $T+1$ 及以后的词 [【跳转到 02:10】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=130)。

![Sequence Mask 要防止偷看：解码器只应依赖已生成的部分，否则会偷看未来、层间泄露](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00130.webp)

视频指出这类泄露有三个层次的危害：

- **模型可能变懒**：直接复制粘贴未来的信息，而不是真正学习怎么一步步生成内容；
- **信息泄露会层层传递**：第一层注意力看到了未来，第二层再用这个带了未来信息的输出去算，那就更乱套了；
- **训练与推理不一致**：推理时根本没有未来词可看，训练时却看得见，学到的行为在真实生成场景里对不上。

所以需要 Sequence Mask，也叫 **causal mask（因果掩码）**：在计算注意力分数时给每个位置画个圈，只允许它关注自己以及前面的词，坚决不允许它看到后面的词 [【跳转到 02:35】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=155)。

### 3.2 下三角矩阵：形状是"句长 × 句长"

![Sequence Mask 实现细节：形状为 seq_len × seq_len 的方阵，内容为含对角线的下三角，上三角置 −∞](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00305.webp)

具体做法是构造一个**下三角矩阵**，把注意力分数矩阵 $QK^T$ 中**对角线以上的部分**全设成负无穷；这样一来 softmax 之后这些位置的权重就变成 0，模型被强制要求只看过去、不看未来 [【跳转到 03:00】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=180)。这同时保证了训练过程和实际推理时解码器的行为是一致的，都是基于已知信息进行预测。

视频对这张矩阵的规格说得很明确 [【跳转到 05:05】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=305)：

- **形状**：方阵，大小是"序列长度 × 序列长度"（$seq\_len \times seq\_len$）；
- **内容**：下三角（含对角线）为可读；用布尔型表示时，下三角和对角线是 True、上三角是 False；用浮点型表示时，下三角和对角线是 0、上三角是负无穷。

和填充掩码对照一下就能看出关键差异：填充掩码是"整列同判"，而因果掩码是**"逐行递进"**——第 1 行只亮 1 格，第 2 行亮 2 格，第 $T$ 行亮 $T$ 格。所以它不能靠一个"批 × 长度"的小向量广播得到，必须是一张真正的二维方阵（或以等价方式按行索引生成）。

写成掩码矩阵：

$$
M_{\text{seq}}(i, j) =
\begin{cases}
0, & j \le i \\
-\infty, & j > i
\end{cases}
$$

计算流程是三步 [【跳转到 05:05】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=305)：

1. 先算出 $Q$ 和 $K$ 的点积，得到注意力分数矩阵；
2. 把 sequence mask 应用上去：对上三角部分的分数强制设为负无穷，这意味着计算第 $T$ 个位置的输出时，它与 $T+1$ 及之后位置的 key 的内积被设成负无穷，表示它们之间没有关联；
3. 应用 softmax，那些被设为负无穷的位置权重变成 0；最后用这个权重矩阵加权求和 $V$。

结果就是：**第 $T$ 个位置的输出只能由第 1 到第 $T$ 个位置的 value 向量加权得到**，这样就实现了单向注意力，保证模型不会偷看未来 [【跳转到 05:55】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=355)。

## 四、四种差别：把两种掩码放在一张表里

| 对比项 | Padding mask | Sequence mask（causal mask） |
| :--- | :--- | :--- |
| 挡什么 | 为对齐长度补出来的 PAD 空位 | 当前时刻之后、还没生成的 token |
| 为什么挡 | 空位会参与 softmax，抢走真实词的权重，引入偏差 | 不挡就等于训练时抄答案，模型学不会逐步生成 |
| 矩阵形状 | 通常"批 × 序列长度"，广播成"句长 × 句长" | 固定"句长 × 句长"的方阵 |
| 判据来源 | 哪些列是无效 token（与行无关） | 列号是否大于行号（逐行递进） |
| 主要出现位置 | 编码器自注意力、交叉注意力、解码器自注意力 | 解码器的 masked self-attention |
| 是否与顺序有关 | 无关，只与句长和 PAD 位置有关 | 有关，依赖序列顺序 |

两者的**共同点**也值得单列：都是在 $QK^T$ 之后、softmax 之前动手；都用"极小的数"实现；都靠 softmax 的指数函数把极小值变成 0 权重。也就是说，**记住一个"softmax 前把分数压到负无穷"的套路，就能同时理解两种掩码**——区别只在"压哪些格子"。

## 五、Masked Self-Attention：Q、K、V 同源，区别只在 softmax 前那一步

把镜头对准解码器的第一个多头注意力模块，也就是 masked self-attention。顾名思义，这里的 Q、K、V 都来自同一个输入序列，通常是目标语言的嵌入或者前一个解码器块的输出；这和编码器里的自注意力类似，**关键区别在于它必须带上 sequence mask** [【跳转到 06:20】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=380)。

![Masked Self-Attention：在 QK^T 之后、softmax 之前应用 Sequence Mask，每个位置 i 的输出只依赖 1 到 i 位置的 Key-Value 对](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00405.webp)

流程是：输入 $X$ 经过线性变换得到 $Q$、$K$、$V$，然后计算点积得到注意力分数矩阵，紧接着就是关键步骤——把这个矩阵乘上（或加上）一个下三角掩码，把上三角部分的分数设为负无穷。这样处理后，第 $i$ 行的分数就只剩下它和前 $i$ 个位置的 $K$ 的得分了 [【跳转到 06:45】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=405)。然后是 softmax，被设为负无穷的部分自然变成 0 权重；最后用这个权重矩阵乘以 $V$ 得到输出 $Z$。

用式子表达，第 $i$ 个位置的输出是

$$
Z_i = \sum_{j=1}^{i} \operatorname{weight}(i, j) \cdot v(j)
$$

求和上限是 $i$ 而不是 $n$，就是因果性的全部含义：$Z$ 实际上是 $V$ 矩阵中前 $i$ 个元素的加权平均，第 $i$ 个位置的输出只依赖于它自己以及前面 $i-1$ 个位置的信息 [【跳转到 07:10】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=430)。

如果是多头注意力，就有好几个这样的头并行计算，各自得到一个 $Z$，然后把它们拼接起来，再通过一个线性变换得到最终输出 [【跳转到 07:35】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=455)。**注意掩码是加在"每个头各自的分数矩阵"上的**：每个头有自己的一套分数，但"上三角一律屏蔽"这条规则对所有头完全相同，所以掩码只需要构造一次、广播到所有头。

## 六、交叉注意力不需要 sequence mask，但仍然需要 padding mask

![Cross-Attention 与掩码合并：第二个 MultiHeadAttention 不需要额外 Sequence Mask，但通常会把 Padding Mask 与 Sequence Mask 合并使用](assets/两种掩码各挡什么：Padding%20mask%20与%20Sequence%20mask%20的分工/00480.webp)

最后一个问题：解码器里那个交叉注意力（第二个 multi-head attention）也需要加 mask 吗？答案是**不需要额外的 sequence mask** [【跳转到 08:00】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=480)。原因有三条：

- 这一层里的 $Q$ 来自前面那个带了 mask 的 masked self-attention 的输出——它已经被因果掩码筛过一遍了；
- $K$ 和 $V$ 来自编码器的输出，而编码器能看完整个原序列，已经把所有信息编码进去了；
- 所以我们希望它在这里能充分理解原语言的信息，不再给它戴眼罩。

这个结论和"掩码的判据是'这个位置会不会被当成答案'"是同一件事：交叉注意力的来源是原文，不是待生成的译文，所以整句都该读。

但交叉注意力**仍然要用 padding mask**，用来屏蔽掉原序列中的填充符号 [【跳转到 08:25】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=505)。这里的判据很明确：原文里补出来的空位是无效来源，无论它在哪一行都不该被读取。

## 七、合并：任一掩码要求屏蔽，这个位置就屏蔽

实际代码里，两种掩码通常是同时存在的（比如解码器自注意力既有未来方向的问题，又有 PAD 的问题），常规做法是把 padding mask 和可能存在的 sequence mask 合并使用 [【跳转到 08:25】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=505)。

合并的语义是**逻辑或**：对每个位置，如果任何一个 mask 要求它被屏蔽，那它就被屏蔽。视频用的比喻是两个保安，只要有一个说这个人不行，这个人就得走开 [【跳转到 08:50】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=530)。这样既不会被填充符号干扰，也不会偷看未来。

对应到两种表示上：

$$
M_{\text{combined}} = \min\left(M_{\text{pad}},\; M_{\text{seq}}\right)
$$

浮点表示下取最小值即可——因为屏蔽值是很小的负数，`min` 天然实现了"一票否决"；布尔表示下则用逻辑或（二者恰好是数值 `min` 与布尔 `or` 的对应关系，取决于你把 True 定义成"保留"还是"屏蔽"，实现时容易搞反的就是这一处）。若同时还要缩放分数，顺序是：**点积 → 缩放 → 加掩码 → softmax → 加权求和**，掩码永远在 softmax 之前。

## 八、三个容易写错的细节

1. **不能用 0 屏蔽**。前面已经推过：$\exp(0)=1$，把分数清零只是"中立"，不是"排除"，被"清零"的位置照样分到份额。想让它彻底退出，必须是个足够小的负数，让 $\exp$ 之后真的变成 0。
2. **“$-10^9$”与“$-\infty$”是同一个意思**。视频里两种说法都出现过：口述说“拉到负无穷”，幻灯片给的实现值是 $-1e9$。它们效果等价——只要这个数足够小，$\exp$ 之后都会下溢成 0，而剩下的有效位置再重新归一化。
3. **因果掩码在推理阶段同样不能省**。有时会误以为"推理时反正只有前缀"就不需要掩码，但推理的 **prefill（预填充）** 阶段是把整段 prompt 一次性送进去并行计算的，此时序列内部同样"有未来"，sequence mask 必须继续生效 [【跳转到 04:40】](https://www.bilibili.com/video/BV1fuPizoEBD/?t=280)。这也是视频强调 sequence mask 的应用场景是"解码器训练（teacher forcing）**和推理预填充阶段**"的原因。

## 小结

- 掩码是与目标张量同形的二值张量，像遮光板一样盖住注意力计算中不想要的部分；它挡的是权重，不是内容。
- Padding mask 挡的是为对齐 batch 而补出的 PAD：因为 $\exp(0)=1$，空位会当成正常词参与 softmax、抢走真实词的权重并引入偏差。
- Sequence mask（因果掩码）挡的是当前时刻之后的 token：teacher forcing 一次性喂入整个目标序列，不挡就会偷看未来、层层泄露、训练与推理不一致。
- 两者机制相同：都在 $QK^T$ 之后、softmax 之前把目标位置分数压到极小（$-1e9$ 或 $-\infty$），使权重归零。
- 两者形状与判据不同：padding mask 看"这一列是不是 PAD"，可广播；sequence mask 是"句长 × 句长"的下三角方阵，逐行递进。
- masked self-attention 的 Q、K、V 同源，唯一区别是 softmax 前多了一步 sequence mask；多头各自算分，但共用同一条掩码规则。
- 交叉注意力不需要 sequence mask（来源是编码器已看完的原文），但仍需 padding mask 屏蔽原文中的 PAD。
- 多个掩码合并按"一票否决"：浮点取 min、布尔取或；顺序永远是点积 → 缩放 → 掩码 → softmax → 加权求和。

## 关键术语速查

| 术语 | 一句话解释 |
| :--- | :--- |
| 掩码（Mask） | 与目标张量同形的二值张量，用来遮盖注意力计算中的特定位置 |
| Padding mask | 把补齐长度用的 PAD 位置在 softmax 前压成极小值，使其权重为 0 |
| Sequence mask / causal mask | 用下三角矩阵屏蔽当前时刻之后的 token，保证单向（因果）注意力 |
| PAD | 填充符号，用于把变长句子补齐成规整张量，本身无语义 |
| teacher forcing | 训练时一次性喂入完整目标序列、并行预测所有位置的做法 |
| 自回归特性 | 每生成一个新词都基于已生成的部分，只能依赖过去、不能依赖未来 |
| masked self-attention | 解码器中带因果掩码的自注意力，Q、K、V 均来自同一输入序列 |
| prefill 阶段 | 推理时把整段 prompt 一次送入并行计算，此时仍需 sequence mask |
| 交叉注意力 | 查询来自解码器、K 与 V 来自编码器的注意力，不需要因果掩码但需要 padding mask |
