# Linux 网络命名空间与虚拟网络设备：用一根“虚拟网线”从零搭出 Pod 网络

> 本文基于视频《Linux网络命名空间核心 ｜ 虚拟网线、虚拟交换机、虚拟路由器》整理；下方时间戳可直接跳到 B 站对应画面。

## 本讲要解决的核心问题（SCQA）

**背景**：Docker（以及 Kubernetes）常被说成能提供网络隔离——比如“用 Docker 创建一个完全不联网的容器来保护隐私”。可这种隔离到底靠不靠谱？

**冲突**：要判断隔离是否可信，就得理解它背后的机制。而容器网络隔离的底层，正是 Linux 的**命名空间（namespace）**——命名空间本质上是**对内核不同资源进行划分**，其中和网络打交道的就是**网络命名空间（network namespace）**。

**疑问**：一个网络命名空间到底是怎么被“隔离”出来的？又该怎么把两个彼此隔离的命名空间接通、连成局域网、甚至让里面的进程访问互联网？

**回答（中心思想）**：网络命名空间主要靠 `ip` 命令这一套工具来创建和管理；而要让它联网，需要按“**虚拟网线（veth pair）→ 虚拟交换机（网桥 bridge）→ 虚拟路由器（带 IP 的网桥 + 路由 + 转发 + NAT）**”这条路径，一层层把虚拟的网络设备搭起来。理解了这条链路，你就能看懂 Pod 网络是怎么构造的，也能理解容器网络隔离的边界在哪里。

## 一、网络命名空间：把内核的网络资源“分房间”

视频一开始先破除一个疑问：Linux 里有很多种命名空间。用 `ip netns` 相关工具管理网络之前，先认清命名空间的种类——常见的有：

- `mnt`（挂载）、`uts`（主机名/域名）、`net`（网络）、`ipc`（进程间通信）；
- `pid`（进程号）、`user`（用户）、`cgroup`、`time`（时间）。

![Linux 各类命名空间：命名空间用于对内核不同资源进行划分](assets/Linux网络命名空间核心%20｜%20虚拟网线、虚拟交换机、虚拟路由器/00025.webp)

[【跳转到 00:20】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=20)

命名空间是对内核资源的划分，**网络命名空间**则是把网络相关的资源（网卡、IP、路由表、端口等）单独划分出来，做到彼此不可见。它主要用 `IP 命令`来操作。放到 **TCP/IP 五层模型**里看，`ip` 命令主要负责**网络层**和**数据链路层**：

![ip 命令负责网络层与数据链路层](assets/Linux网络命名空间核心%20｜%20虚拟网线、虚拟交换机、虚拟路由器/00045.webp)

[【跳转到 00:40】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=40)

> 注意一个容易被忽略的前提：电脑要联网，第一步其实不是配 IP，而是先确认**网卡（网络接口）的状态**——数据进进出出都靠它。

先看宿主机自己的接口：`ip link` 会列出 `lo`（loopback 回环接口，用于程序之间互相通信）和 `enp0s5`（以太网接口）等。两个接口都显示 `UP` —— 这不是“up 主”的 up，而是告诉你接口已经启动、已可对内对外通信。

[【跳转到 01:02】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=62)

创建第一个网络命名空间很简单：

```bash
ip netns add 七度空间      # 创建一个网络命名空间
ip netns list              # 列出所有网络命名空间
```

[【跳转到 01:27】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=87)

刚建好的命名空间是**完全隔离**的：只有宿主机能创建、管理、销毁它；要在这个空间里执行命令，得用 `ip netns exec <空间名> <命令>`。比如查它的链路层信息：

```bash
ip netns exec 七度空间 ip link show
```

[【跳转到 02:17】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=137)

结果里只有回环接口 `lo`，**没有以太网接口**——说明这个空间连不上外界；而且 `lo` 还没启动，它**连自己都通信不了**：在里面 ping 本地回环地址是通的不了的（网络完全不通）。想让同一空间内的两个程序互通，就得把回环接口开起来：

```bash
ip netns exec 七度空间 ip link set lo up
```

开了之后再看链路状态就是启动的，ping 本地回环也没问题。

[【跳转到 03:10】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=190)

## 二、把两个命名空间接起来：veth 虚拟网线

要让两个网络命名空间联网，得像两台老电脑用网线互联一样，给它们拉一根**虚拟以太网网线（veth pair）**。veth pair 和真实网线一样有**两个接口**（一头一个）。

先建两个空间（视频里叫“七度空间”“八度空间”），再在**宿主机环境**下创建 veth pair：

```bash
ip link add 七度空间-veth type veth peer name 八度空间-veth
```

[【跳转到 04:03】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=243)

此时两个接口都还“躺”在宿主机这边，**并没有插到任何空间上**：

![宿主环境下刚创建的 veth 两端接口](assets/Linux网络命名空间核心%20｜%20虚拟网线、虚拟交换机、虚拟路由器/00268.webp)

[【跳转到 04:53】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=293)

接着把两端分别“插”进各自的空间，并启动它们：

```bash
ip link set 七度空间-veth netns 七度空间     # 一端放进七度空间
ip link set 八度空间-veth netns 八度空间     # 另一端放进八度空间
ip netns exec 七度空间 ip link set 七度空间-veth up
ip netns exec 八度空间 ip link set 八度空间-veth up
```

接口移走后，宿主侧再 `ip link` 就看不到这根网线了；回到两个空间里看链路，就能看到各自的接口已经接上。

![veth 把两个网络命名空间连起来](assets/Linux网络命名空间核心%20｜%20虚拟网线、虚拟交换机、虚拟路由器/00343.webp)

[【跳转到 05:18】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=318)

万事俱备，只欠 IP：两个空间里只有回环有 IP，veth 接口还没地址，是没法用 ping 发数据的。用 `ip addr add` 逐个配置（用内网地址，并**别忘了子网掩码**——没有掩码系统无法判断数据包往哪个方向走）：

```bash
ip netns exec 七度空间 ip addr add 172.20.0.2/24 dev 七度空间-veth
ip netns exec 八度空间 ip addr add 172.20.0.3/24 dev 八度空间-veth
```

`/24` 意味着 `172.20.0.0` ~ `172.20.0.255` 属于同一个局域网；`dev` 表示把地址和掩码加到哪个接口上。配好后 `ip addr` 就能看到各自的 IP。

[【跳转到 06:08】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=368)

为什么配了掩码就能通？看路由表就明白了：加 IP 和掩码之前没有的那条规则，正是通往对端网段的规则；于是从七度空间发往八度空间的包，在逻辑上就找到了方向。此后两个方向互相 ping 都通——这就是**点到点（point-to-point）**通信，常用于前后端之间的网络通信。也可以在八度空间里启一个 web 服务，从七度空间访问它。

[【跳转到 07:23】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=443)

## 三、从点到点到局域网：网桥就是“虚拟交换机”

点到点虽然直接明了，但空间一多、两两拉线，就会乱成一团。现实中让**同一局域网的多台设备互通**靠的是交换机；在网络命名空间的世界里，用**网桥（bridge）**实现交换机的功能。

```bash
ip link add br0 type bridge     # 创建一个网桥接口
ip link set br0 up              # 启动网桥
```

[【跳转到 08:48】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=528)

为了让空间能通过网桥对外通信，通常把网桥**留在宿主机**里。把一个空间接到网桥上，仍然需要一根 veth “网线”：一端放进空间，另一端用 `master` 归到网桥（相当于把网线插到交换机上）：

```bash
# 先建一对 veth，一端给空间，另一端接网桥
ip netns exec 七度空间 ip link set 七度空间-br up
ip link set 七度空间-br master br0     # 把接口插到网桥上
ip link set br0 up
```

[【跳转到 09:38】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=578)

接着给**各自空间的接口**配置新的、不冲突的 IP：

```bash
ip netns exec 七度空间 ip addr add 172.20.0.2/24 dev 七度空间-br
ip netns exec 八度空间 ip addr add 172.20.0.3/24 dev 八度空间-br
```

![宿主机上用一个网桥把多个命名空间桥接起来](assets/Linux网络命名空间核心%20｜%20虚拟网线、虚拟交换机、虚拟路由器/00578.webp)

[【跳转到 10:03】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=603)

> 易错点：**不要习惯性地给网桥本身配 IP**。这里的网桥相当于**二层交换机**，只看 MAC 地址，只需要给两个空间各自的接口配 IP 即可。

配好后，从一个空间 ping 另一个空间就能通——网桥生效了，再多的空间也能桥接进来。

## 四、接入互联网：虚拟路由器 + 转发 + NAT

局域网解决了，可空间去访问公网 IP 还是不行——因为还缺一台**路由器**。好在可以把刚才的网桥“升级”成**虚拟路由器**：既然网线都插好了，就能省掉很多步骤。

### 4.1 给网桥配一个 IP，让它当网关

路由的本质是“根据 IP 地址转发数据包”，所以先给宿主机上的网桥接口配一个 IP（路由器地址末位习惯取 1）：

```bash
ip addr add 172.20.0.1/24 dev br0
```

然后在空间里加一条**默认路由**，把不在本局域网的数据包交给网桥（下一跳）：

```bash
ip netns exec 七度空间 ip route add default via 172.20.0.1
```

此时查看路由表就能看到默认路由规则。

[【跳转到 10:53】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=653)

> 视频里踩到一个坑：默认路由的接口显示成了之前点到点用的那个 veth，而不是新网桥。说明那条旧接口**仍绑在默认路由**上，得把没用的接口关掉或删掉，然后**重新设置默认路由**。建议打算用网桥/路由时，先把点到点连接全部关掉，以免弄混。

### 4.2 打开宿主机的 IP 转发

在宿主机上看转发开关：

```bash
sysctl net.ipv4.ip_forward
```

[【跳转到 12:33】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=753)

结果是 `0`：宿主机默认**不帮忙转发**，即使数据包被路由到宿主机，它也不会转发。要手动打开：

```bash
sysctl -w net.ipv4.ip_forward=1
```

> 安全提醒：一台电脑若能默认转发数据包，一旦被入侵，攻击者就能借它去攻击同一局域网里的设备——所以默认才是关的。

### 4.3 NAT：让内网地址能“出门再回来”

转发开了，数据包能出去，但**回不来**：空间用的是内网地址，目标设备无法把响应回给内网地址。因此要做 **NAT（网络地址转换）**，用 `iptables` 的 `nat` 表，在 `POSTROUTING`（数据包离开宿主机网卡前的最后一关）链上添加规则：

```bash
iptables -t nat -A POSTROUTING -s 172.20.0.0/24 -j MASQUERADE
```

![宿主机充当虚拟路由器，配合 ip_forward 与 NAT 让命名空间访问外网](assets/Linux网络命名空间核心%20｜%20虚拟网线、虚拟交换机、虚拟路由器/00819.webp)

[【跳转到 13:39】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=819)

其中：

- `-t nat` 指定 `nat` 表；`-A` 追加规则；`POSTROUTING` 是路由后链；
- `-s 172.20.0.0/24` 指定源地址范围；
- `-j MASQUERADE` 是“伪装”动作：它会自动查看宿主机**哪个网卡能访问外网**，并把数据包的源地址直接改成该网卡的 IP——比手动指定源地址省事得多。

[【跳转到 14:29】](https://www.bilibili.com/video/BV1Fd5V6VED8/?t=869)

配好后，在空间里就能直接访问外网了。视频结尾点题：**熟悉了这套核心后，再配合 `iptables`，做端口转发与网络安全隔离就很简单了。**

## 小结

- 命名空间是对内核资源的划分；**网络命名空间**隔离网卡、IP、路由、端口等，主要用 `ip` 命令管理（负责网络层与数据链路层）。
- 新空间完全隔离：只有宿主机能管它；里面默认只有 `lo`，且默认未启动，需要 `ip link set lo up` 才能自通信。
- 连网第一步是确认**网卡接口状态**，`ip link` 里 `UP` 才表示接口已启动。
- **veth pair** 是一根有两个接口的“虚拟网线”，先在宿主机创建，再分别 `ip link set ... netns ...` 插进两个空间，配 IP（带掩码）后即可**点到点**互通。
- 空间多了用**网桥（bridge）**当二层交换机：一端接空间、另一端用 `master` 归到网桥；**不要把 IP 配在网桥上**。
- 访问互联网需要三步：给网桥配 IP 当**网关** + 空间加**默认路由** → 宿主机打开 **`ip_forward`** → `iptables -t nat ... MASQUERADE` 做 **NAT**。
- 可把网桥“升级”为虚拟路由器；记得清理旧的点到点接口，避免默认路由串味。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 网络命名空间（net ns） | 对内核网络资源（接口、IP、路由、端口等）的隔离划分 |
| `ip netns` | 创建/查看/进入网络命名空间的命令族（如 `add`、`list`、`exec`） |
| `ip link` | 查看和设置网络接口（链路层）状态的命令 |
| veth pair | 成对出现的“虚拟以太网网线”，有两个接口，用于连接命名空间 |
| 网桥（bridge） | 二层设备，功能等同交换机，按 MAC 转发，用于把多个空间桥接成局域网 |
| 默认路由（default route） | 匹配不到本地网段时走的兜底路由，把包交给下一跳（如虚拟路由器） |
| `net.ipv4.ip_forward` | 宿主机是否转发数据包的开关，默认 0（关） |
| NAT / MASQUERADE | 改写数据包源地址的技术；`MASQUERADE` 自动选用能出网的宿主机网卡 IP |
| `iptables -t nat POSTROUTING` | 数据包离开宿主机网卡前的最后一条链，常用作源地址转换处 |
