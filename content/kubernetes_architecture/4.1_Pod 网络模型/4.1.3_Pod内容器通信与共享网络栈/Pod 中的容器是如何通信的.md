# Pod 中的容器是如何通信的

> 本文整理自视频 *闲聊 K8s - 3 - 网络篇 - 容器技术概述以及 K8s Pod 中的容器是如何通信的*（[Bilibili 原视频](https://www.bilibili.com/video/BV1GK4y1U7HY/)）。它用「观察 + 动手模拟」的方式，讲清一个 Pod 里的多个容器是怎样**共享同一组命名空间、进而共享网络**的。

## 本讲要解决的核心问题（SCQA）

- **背景**：容器本质上就是**被命名空间（namespace）和控制组（cgroup）隔离出来的进程**，它们其实都跑在同一个操作系统上。
- **冲突**：既然容器之间默认是相互隔离的，那同一个 Pod 里的多个容器，为什么能互相通信？它们又是靠什么被"组织"到一起的？
- **疑问**：Pod 到底做了什么，让一组本来互相隔离的容器变得"像在同一台机器上"？
- **回答（中心思想）**：**Pod 会先启动一个 pause 容器，由它创建好一组命名空间；随后 Pod 里的其他容器都 attach（加入）到这组命名空间上。** 于是同一个 Pod 内的容器**共享网络命名空间**（因此共享 IP、端口范围、主机名和路由，可用 `localhost` 通信），但**文件系统仍然各自独立**。

## 一、先打底：容器是"用命名空间和控制组隔离出来的进程"

要理解 Pod，先得理解容器本身。容器并不是"小虚拟机"，而是**一台宿主机上的普通进程**，只是被两项 Linux 内核技术隔了起来。

### 1.1 容器 vs 虚拟机

![容器与虚拟机的比较：容器共享宿主机内核，虚拟机各自带一套操作系统](assets/Pod%20中的容器是如何通信的/00025.webp)

- **容器**：在操作系统之上直接由容器引擎创建若干容器，应用跑在容器里，共享宿主机内核，**额外开销小**。
- **虚拟机**：在基础架构之上先有虚拟机监控程序（Hypervisor），再各自运行独立的操作系统（可以一个跑 Linux、一个跑 Windows），再在系统之上跑应用，隔离更彻底但更重。

### 1.2 镜像是怎么跑起来的：containerd + runc

![Docker daemon 调用 containerd 管理镜像与容器，最终由 runc 把容器创建起来](assets/Pod%20中的容器是如何通信的/00095.webp)

Docker 后台守护进程（`dockerd`）并不亲自管理容器，而是把它交给 **containerd**——一个专门管理容器与容器镜像的应用。containerd 把符合 **OCI（开放容器标准）** 的镜像解包处理，再主要通过 **runc** 把容器创建起来，应用就能在里面运行了。

### 1.3 容器技术的两大核心功能

![命名空间负责"隔离"，控制组负责"限制"](assets/Pod%20中的容器是如何通信的/00161.webp)

容器技术主要靠两个功能：

- **命名空间（Namespace）**：提供内核级别的资源隔离。它把系统的全局资源分配到不同的 namespace 中，让进程"觉得自己独立运行在某个空间里"。主要类别包括：
  - 文件系统（mnt）隔离、进程号（PID）隔离、**网络（net）隔离**、用户/用户组（user）隔离、主机名与域名（UTS）隔离、进程间通信（IPC）隔离。
- **控制组（Cgroup）**：用来**限制**进程能用的资源，例如限定 CPU、内存使用量，分配优先级，记录资源用量，以及对进程做挂起与恢复。

一句话：**命名空间负责"隔离"，控制组负责"限制"。**

## 二、Pod 为什么能让容器"共享"：pause 容器先建命名空间

### 2.1 观察一个 Apache 容器：它的网络命名空间来自"别人"

视频里先在一个 K8s 节点上看了个 Apache 的 Pod。查看这个容器的详情时，能看到它隔离出的各类命名空间（mnt、PID、net、IPC 等）。重点看**网络命名空间**：

- Apache 进程自身的 PID 是 **446531**；
- 但它的**网络命名空间**却挂在另一个进程 **446476** 下。

也就是说，Apache 容器的网络空间是**与进程 446476 共享的**。

### 2.2 找到那个"不干活"的 pause 进程

顺着进程号一查，446476 这个进程的名字是 **pause**——它在容器列表里对应一大堆名字类似的容器。而且查看它的状态会发现，它处于 **sleeping** 状态：**它本身什么都不干**。

![pause 创建命名空间，Apache 容器 attach 进去；两者的命名空间在同一个 K8s 节点（本质是 Linux）之上](assets/Pod%20中的容器是如何通信的/00682.webp)

### 2.3 机制：pause 创建命名空间，其他容器 attach 上去

为什么要有这个"不干活"的容器？它存在的意义正是：**创建命名空间**。

- Pod 启动时，**先启动一个 pause 进程，由它创建各种各样的命名空间**（net、PID、IPC、mnt 等）；
- 然后 Pod 里的应用容器（比如 Apache）**attach 到 pause 的这些命名空间上**；
- 于是**同一个 Pod 里无论有多少个容器，它们都共享同一组命名空间**。

特别针对**网络命名空间**而言，共享它意味着这些容器**拥有独立的端口范围、独立的主机名、独立的路由**——从外面看，它就是"一个 Pod 在上面运行着"，而 Pod 内部的所有容器则通过共享 pause 的命名空间，被封装成一个整体。

## 三、动手验证：用 Docker 模拟一个 Pod

为了把机制看清楚，视频用 Docker 亲手"拼"了一个 Pod。

### 3.1 造一个"只会睡觉"的 pause 容器

先做一个模拟 pause 的镜像：它的 `ENTRYPOINT` 就是 `sleep`，也就是说镜像一跑起来什么都不干、直接睡觉——但它起来时，Docker 引擎本身会给它创建好各种命名空间。

```bash
docker run -d --name pause --hostname apache -p 80:8080 my-pause-image
```

注意这里做了两件事：给容器指定了**主机名 `apache`**，并把**容器内的 8080 端口映射到宿主机的 80 端口**。

![用 docker run 启动 pause 容器，把它当作"命名空间的宿主"](assets/Pod%20中的容器是如何通信的/01057.webp)

### 3.2 让应用容器 attach 到 pause

再启动一个 Python 容器（方便起一个 web server 做验证）。它的运行脚本里关键的一行，就是让它 **attach 到 pause 容器**上——即**与 pause 共享同一个网络命名空间**。

### 3.3 结果：主机名共享、网络共享

起来之后可以看到：

- 这个 Python 容器**没有**自己指定主机名，但它现在的主机名变成了 **`apache`**——与 pause 容器一致（因为我们是在 pause 容器上指定的主机名）；
- 在它里面起的 web server 监听 8080 端口，对外就能通过宿主机的 80 端口访问到。

![在共享网络空间里起的 web server：浏览器能看到它提供的目录](assets/Pod%20中的容器是如何通信的/01347.webp)

## 四、共享网络栈带来的两个结论

### 4.1 同一个 Pod 里，端口会冲突

如果**再启动一个容器**、也 attach 到 pause，并且在里面**同样监听 8080**，就会立刻报错：**8080 端口已被占用**——因为它们在共享同一个网络栈，端口空间也是共用的。停掉前一个 web server 后，换成别的文件再起，才能正常访问新的内容。

![在共享的网络空间里，容器内起的 web server 通过 localhost 就能访问（浏览器打开 localhost/hello.txt）](assets/Pod%20中的容器是如何通信的/01450.webp)

### 4.2 但文件系统仍然相互独立

反过来验证"隔离"的部分：在其中一个容器里**新建一个空文件**，回到另一个容器里却**看不到**这个文件。这说明：**它们的文件系统是相互独立的，只有网络空间是共享的。**

## 小结

![视频结尾的总结：Pod 用 pause 容器创建命名空间并与用户容器共享](assets/Pod%20中的容器是如何通信的/01505.webp)

- **容器的本质**：用**命名空间**隔离、用**控制组**限制的进程，共享宿主机内核，开销小于虚拟机。
- **Pod 的机制**：先由 **pause 容器创建一组命名空间**，Pod 内的其他容器**attach** 到这组命名空间上，从而**共享同一组命名空间**。
- **同 Pod 内容器共享网络命名空间**：因此共享 IP、端口范围、主机名和路由，可以用 `localhost` 通信。
- **两个直接后果**：同一个 Pod 里容器的**端口会冲突**（共享网络栈）；但容器的**文件系统相互独立**（各自隔离）。
- **规模化的理解**：一台 node 上跑 10 个 Pod、每个 Pod 10 个容器，本质就是操作系统上 100 个进程，被命名空间"分组 + 隔离"成了 10 个 Pod。

## 关键术语速查

| 术语 | 一句话解释 |
| :--- | :--- |
| 命名空间（Namespace） | Linux 内核提供的资源隔离机制，让进程"看不到"别的进程的资源 |
| 控制组（Cgroup） | Linux 内核提供的资源限制机制，限制/统计进程组对 CPU、内存等的使用 |
| pause 容器 | Pod 中负责创建并持有命名空间的"占位"容器，本身不干活 |
| attach | 让一个容器加入已有容器的命名空间（如共享同一个网络空间） |
| containerd / runc | 分别负责"管理容器与镜像"和"真正创建容器"的组件，runc 按 OCI 标准运行容器 |
| 网络命名空间（net namespace） | 拥有独立网卡、IP、路由表、端口空间和主机名的隔离单元，是 Pod 内容器通信的基础 |
