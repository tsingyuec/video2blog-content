# VXLAN 还是 BGP？——Calico 两种数据面模式：封装与纯路由的取舍

> 本文整理自 B 站视频《[CNI 原理与 Calico VXLAN/BGP 双模式对比](https://www.bilibili.com/video/BV15yZFBiECF/)》（时长约 7 分钟）。文中概念、流程、对比表与选型建议均来自该视频的图文稿，可核对。

## 本讲要解决的核心问题（SCQA）

**背景（S）**：我们在 K8s 网络那期讲过，跨 Node 通信靠两件事——**CNI 插件**和 **VXLAN 隧道**；当时只给了结论，没拆机制。

**冲突（C）**：同样是让 Pod 跨节点互通，**Calico 却偏偏不走 overlay**，用 BGP 把 Pod IP 当作真实路由通告出去。这两种做法到底差在哪：包在路上各经历了什么？谁快谁慢？什么场景该选谁？

**疑问（Q）**：**Calico 的 VXLAN 模式和 BGP 模式，分别是怎么把包送到对端的？我们又该怎么选？**

**回答（中心思想 A）**：两种模式的本质是**一层封装要不要做**的取舍。**VXLAN 模式**把 Pod 包封进 UDP（约 **50 字节**开销、MTU 降到 **1450**、性能损失 **5%~15%**），换来「**任何网络都能开箱即用**」；**BGP 模式**不套任何外包装，直接把真实 Pod IP 通过 BGP 通告成路由（**零封装、纯 L3 转发**），性能和可观测性更好，但**部署更复杂、对底层网络有要求**。选型逻辑很简单：**云上用厂商 CNI，自建机房推荐 BGP；跨子网且路由器不支持 BGP，才退回 overlay。**

## 一、CNI 是「标准接口」，不是「网络方案」

要拆跨节点通信，得先分清腿是谁的。

**CNI 不是网络方案，而是调用网络插件的标准接口**——就像 **USB 接口定义了规范**，接鼠标还是键盘是外设自己的事。**Calico、Flannel、Cilium 都是 CNI 插件的具体实现**。

![CNI 是插件的标准接口：ADD/DEL/CHECK 三个核心操作，外加 IPAM 插件专门分配 IP](assets/CNI%20原理与%20Calico%20VXLAN、BGP%20双模式对比/00025.webp)

它的**核心只有三个操作**：

| 操作 | 含义 |
| :--- | :--- |
| **ADD** | 创建网络接口 |
| **DEL** | 清理 |
| **CHECK** | 健康检查 |

创建 Pod 时，**kubelet 直接调用 CNI 插件**，插件负责配置网络；另外还有 **IPAM 插件**，专门分配 IP 地址。关键就一句话：**kubelet 只管调用 CNI 接口，不管网络怎么实现，两者完全解耦**。

> 所以「CNI 是接口标准」——**具体怎么跨 Node 通信，取决于插件实现**。

## 二、Calico VXLAN 模式：把 Pod 包「装进快递盒」

Calico 的 VXLAN 模式，核心是**封装**。可以类比成**快递装箱**：你的 Pod 数据包是商品，装进快递盒（外层 UDP 封装），**快递员只看盒上的地址**（Node IP），到了目的地再拆箱。

![VXLAN 封装原理：Pod A → 经 veth/flannel 到宿主 → VTEP 封装 → 物理网络 → 对端 VTEP 解封 → Pod B](assets/CNI%20原理与%20Calico%20VXLAN、BGP%20双模式对比/00075.webp)

**跟着包走一遍七步完整流程**：

| 步骤 | 发生什么 |
| :--- | :--- |
| **1** | Pod A 发包，经 **veth pair** 到达宿主，记录路由表 |
| **2** | 到达 **VTEP**（隧道端点） |
| **3** | VTEP 查 **FDB 表**——这是 **Felix 维护**的转发表，本质是「**目标子网对应哪个 Node IP**」的映射 |
| **4** | VTEP **封装**：外层套上 **UDP 4789 端口**和 **VXLAN header**，总共约 **50 字节**开销 |
| **5** | 物理网络**只看到 Node A 到 Node B 的 UDP 流量** |
| **6** | 目标 Node 的 VTEP **解封装**，拿到原始 Pod 包 |
| **7** | 查路由表，经 **veth pair** 送到 Pod B |

注意：**NetworkPolicy 是在解封装之后**、由 **iptables** 匹配的，**对封装完全透明、功能不缩减**。

![VXLAN 的代价：每包 50 字节封装，Pod 可用 MTU 从 1500 降到 1450](assets/CNI%20原理与%20Calico%20VXLAN、BGP%20双模式对比/00125.webp)

**VXLAN 的代价很明确**：每包约 **50 字节**封装开销，Pod 可用 **MTU 从 1500 降到 1450**，**性能损失 5%~15%**，**排障也难**（物理网络只看到 UDP 流量，要在 overlay 内部抓包）。但它的**核心优势**是——**任何网络环境都能用，开箱即用，不需要底层网络支持 BGP**。

一句话：**用通用性换性能**——好处是哪都能用，代价是额外开销。

## 三、Calico BGP 模式：不套外包装，纯路由

封装有开销，那**有没有不需要封装的方案**？有，就是 Calico 的 **BGP 模式**，核心卖点是**零封装、纯路由**。

**BGP 的核心思路**：**不套外包装**，直接把**真实的 Pod IP** 通过 BGP 通告出去，让物理网络**一眼就看到目的地**。每个 Node 像一台路由器；两个组件分工明确：

- **Felix**：把路由规则写入内核的转发（FIB）表；
- **BIRD**：通过 BGP 协议**向其他 Node 通告路由**。

![BGP 模式：地址就是真实的 Pod IP；路由表里有一条 BGP 学来的路由](assets/CNI%20原理与%20Calico%20VXLAN、BGP%20双模式对比/00225.webp)

**跟着包走一遍完整路径**：Pod A 发包，经 veth pair 到达宿主，**路由表里有一条 BGP 学来的路由 `10.244.2.24 via node B`**，内核直接从物理网卡转发；**物理网络上跑的是原始 Pod IP 包，零额外封装头**；Node B 收到后查路由表，经 veth pair 送到 Pod B。

**对比 VXLAN 的关键区别**：**没有 VTEP 设备，没有封装解封装过程，物理网络直接看到 Pod IP**——这是**纯 L3 转发**。

### 同子网 vs 跨子网

这里有个**关键区别**：

- **同子网内**的 Node 之间直连 **iBGP peer**，**不需要物理路由器参与**，直接二层转发就行；
- 但**跨子网、跨机架**需要三层转发时，**中间的物理路由器必须支持 BGP**，否则路由信息传不过去——**这时候 VXLAN 反而成了兜底方案**。

### 规模问题：iBGP 全互联 → Route Reflector

但 BGP 模式有一个**规模问题**——**iBGP 全互联**：每两个 Node 之间都要建立 BGP 连接。

- 5 个 Node 需要 **10 条**连接；
- 10 个 Node 变成 **45 条**；
- 公式是 **N×(N−1)/2**，**N 平方增长**——集群一大就爆炸。

**解决方案是 Route Reflector（简称 RR）**：所有 Node 不再两两互联，而是**只跟一个中心节点 RR 建 peer**，连接数**从 N² 直接降到 N（线性增长）**——5 个 Node 只需 5 条，100 个 Node 也只需 100 条。

## 四、六个维度一次看清：VXLAN vs BGP

把两种模式放在一张表里对比：

![VXLAN vs BGP 硬核对比](assets/CNI%20原理与%20Calico%20VXLAN、BGP%20双模式对比/00300.webp)

| 维度 | VXLAN | BGP |
| :--- | :--- | :--- |
| **封装开销** | 每包约 50 字节（性能损失 5%~15%） | **0 封装，接近裸机** |
| **网络要求** | 无要求，开箱即用 | **跨子网需要路由器支持 BGP**（同子网没问题） |
| **排障** | 要**解 overlay** 才能看到真实流量 | 用**标准路由工具直接抓包** |
| **部署难度** | 开箱即用 | **复杂，需要网络工程师配合** |
| **Pod IP 可达性** | overlay 内部，对物理网络不可见 | **对物理网络可见** |
| **本质** | 用通用性换性能 | 性能换部署复杂度 |

## 五、怎么选：按「环境」而不是按「偏好」

![怎么选？云上与自建机房的选型](assets/CNI%20原理与%20Calico%20VXLAN、BGP%20双模式对比/00350.webp)

- **云上（AWS / GCP / 阿里云）**：厂商**自带 CNI 方案**，直接用底层网络就行；
- **自建机房**：**推荐用 BGP 模式**；
- **如果所有 Node 在同一个子网**：Calico 自己就能搞定 iBGP peer，**根本不需要物理路由器支持 BGP**；
- **只有跨子网时**：中间的**路由器才需要跑 BGP**；
- **如果你的路由器不支持 BGP、又要跨子网**：那才**用 VXLAN overlay**。

回顾核心要点：**CNI 是接口标准，不是网络方案**。选型逻辑很简单——**云上用厂商方案；自建推荐 BGP；同子网零门槛；跨子网需要路由器支持 BGP；搞不定就用 overlay。** 本质就是**一层封装的取舍**。

## 小结

- **CNI 是标准接口，不是网络方案**：它只定义 ADD/DEL/CHECK 三个操作，Calico/Flannel/Cilium 都是它的实现，kubelet 只负责调用、与实现完全解耦。
- **VXLAN 模式 = 封装**：把 Pod 包封进 UDP（**UDP 4789**），靠 **Felix 维护的 FDB 表**决定封给哪个 Node；代价是 **50 字节开销、MTU 1450、性能损失 5%~15%**，好处是**任何网络开箱即用**。
- **BGP 模式 = 零封装纯路由**：**Felix 写路由、BIRD 通告路由**，物理网络**直接看到真实 Pod IP**，纯 L3 转发；规模上靠 **Route Reflector** 把 **N² 的连接降成 N**。
- **两者的取舍**：VXLAN 用通用性换性能；BGP 用部署复杂度换性能与可观测性。
- **选型**：云上用厂商 CNI；自建推荐 BGP；同子网零门槛；**跨子网且路由器支持 BGP 才用 BGP，搞不定就退回 overlay**。

## 关键术语速查

| 术语 | 一句话解释 |
| :--- | :--- |
| **CNI** | 调用网络插件的标准接口（类比 USB），核心操作是 ADD / DEL / CHECK。 |
| **IPAM 插件** | CNI 里专门负责分配 IP 地址的插件。 |
| **VTEP** | VXLAN 隧道端点，负责把包封装/解封；VXLAN 模式下每个 Node 一个。 |
| **FDB 表** | 转发数据库，由 Felix 维护，记录「目标子网 → 哪个 Node IP」的映射。 |
| **BGP** | 边界网关协议，用来在 Node（和路由器）之间通告真实 Pod IP 路由。 |
| **Felix / BIRD** | Calico 组件：Felix 把路由写进内核，BIRD 用 BGP 向其他 Node 通告路由。 |
| **iBGP 全互联** | 每两个 Node 都建 BGP 连接，连接数按 N² 增长，规模一大就爆炸。 |
| **Route Reflector（RR）** | 让所有 Node 只跟中心节点建 peer，把连接数从 N² 降到 N。 |
| **NetworkPolicy** | 在解封装之后由 iptables 匹配，对 VXLAN 封装完全透明。 |
