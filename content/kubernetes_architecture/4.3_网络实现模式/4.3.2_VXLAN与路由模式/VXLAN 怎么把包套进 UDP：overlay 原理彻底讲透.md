# 一个包怎么被「套进」UDP——VXLAN 封装原理：VNI、VTEP 与 FDB 表

> 本文整理自 B 站视频《[05·VXLAN 怎么把包「套」进 UDP？overlay 原理彻底讲透](https://www.bilibili.com/video/BV19e4D6KEGq/)》（「Flannel 源码深读」系列第五期，时长约 5 分钟）。文中概念、字段与流程均来自该视频的图文稿，可核对。

## 本讲要解决的核心问题（SCQA）

**背景（S）**：同一台主机上的两个 Pod 通信，走 `cni0` 网桥二层直接就到，很简单。

**冲突（C）**：可一旦换成**跨主机**——两台不同宿主机上的 Pod 往往**不在同一张二层网络里**，物理网络并不会帮忙在它们之间转发。那跨主机的包怎么送到对端？封起来之后，发送方又怎么知道该发给谁？

**疑问（Q）**：**VXLAN 到底怎么把一个 IP 包「套进」UDP，跨主机送到对端？中间又是靠什么表来决定去向的？**

**回答（中心思想 A）**：VXLAN 在真实的 IP/UDP 网络之上**再叠一层虚拟网络**：把原始二层帧**封装**进 UDP 里，靠 **VNI** 区分网络、靠 **VTEP** 装包拆包，靠 **ARP / FDB / 路由三张表**决定「这个目的 IP 该封给哪台主机」。代价是每包约 **50 字节**的封装开销，因此 Pod 的 **MTU 要从 1500 减到 1450**——这一步没处理好，VXLAN 网络会莫名其妙地慢，甚至断。

## 一、为什么需要 overlay：物理网络不帮你转发

先把问题说清楚。**同主机**的 Pod 走 `cni0` 网桥，二层直接就到，没什么好讲的。

**跨主机**就麻烦了：

- 不同主机上的 Pod，**往往不在同一张二层网络里**；
- 物理网络**不会**帮你在它们之间转发。

所以要有一条**虚拟通道**，把报文从一台主机送到另一台——这就是 **overlay（覆盖网络）**：在真实的 IP 和 UDP 网络之上，**再叠一层虚拟网络**。而 **VXLAN** 就是其中**最经典、也最常用**的一种。

## 二、搞懂 VXLAN，只要三个词：VNI、VTEP、封装

VXLAN 的骨架其实就三个概念，记住它们，后面全都串得起来。

![VNI / VTEP / 封装：三个词，贯穿 VXLAN 的骨架](assets/VXLAN%20怎么把包套进%20UDP：overlay%20原理彻底讲透/00064.webp)

| 概念 | 含义 | 作用 |
| :--- | :--- | :--- |
| **VNI**（VXLAN Network Identifier） | **24 位**的网络标识 | 用来**区分不同的 overlay 网络**，就像 VLAN ID，但范围大得多 |
| **VTEP**（VXLAN Tunnel Endpoint） | VXLAN **隧道端点**，**每台宿主机上一个** | 负责把包**封装**起来，到对端再**解封** |
| **封装** | 把**原始二层帧**整个装进去 | 外层用**对端 VTEP 的公网 IP** 作为目的地址 |

一句话概括：**VNI 告诉你「这是哪个网络」，VTEP 负责「装和拆」，外层 UDP 负责「跨节点运输」。**

## 三、flannel 怎么建：flannel.1 就是这台主机的 VTEP

在 `registerNetwork` 里调用 `CreateVXLANDevice`，会在宿主机上创建一个叫 **`flannel.1`** 的网络设备。它有两点关键：

1. **建好后会把设备的 MAC 地址存进租约（lease）的 `backingData`**——这就是别的节点**用来认它**的依据；
2. **MTU 要减 50**：因为 VXLAN 封装要**额外占 50 字节**（见下表），所以 `flannel.1` 的 MTU 由 1500 减到 **1450**。

![flannel 怎么建 flannel.1：创建设备 + VTEP 认领 + MTU 减 50](assets/VXLAN%20怎么把包套进%20UDP：overlay%20原理彻底讲透/00101.webp)

这 50 字节是这样构成的：

| 封装内容 | 字节 |
| :--- | :--- |
| 外层 IP 头 | 20 |
| 外层 UDP 头 | 8 |
| VXLAN 头 | 8 |
| 外层以太网头 | 14 |
| **合计** | **50** |

**`flannel.1` 就是这台主机的 VTEP**——所有跨主机的包，都从这里进出。

## 四、一个包，跨主机怎么走：封装 → 跨节点 → 解封

一个包要真正跨过主机，走三步：

![一个包，跨主机怎么走：出版主机 → 跨节点 → 入对端](assets/VXLAN%20怎么把包套进%20UDP：overlay%20原理彻底讲透/00137.webp)

1. **出版主机（封装）**：Pod 发出的报文经 **veth** 送到 `cni0` 网桥，再被宿主路由送到 `flannel.1`（也就是 VTEP）。在 VTEP 上它被**封装**起来，套上外层 IP 和 UDP，**外层的目的地址就是对端 VTEP 的公网 IP**。
2. **跨节点（运输）**：封装好的包顺着物理网卡，走真实网络送到对端宿主机。
3. **入对端（解封）**：对端的 VTEP 收到后**剥掉外层**，还原出那个原始二层帧，再送进目标 Pod。

最关键的是——**整段封装和解封，Pod 完全无感**，它以为自己就在一张普通的二层网络里通信。这也是 overlay 的意义：**上层应用不必知道底下的真实网络**。

## 五、VTEP 怎么知道该发给谁：ARP + FDB + 路由三张表

包装好了，可 VTEP 怎么知道「某个目的 IP 该封给哪台主机」？答案靠**三张表**。每当发现一个**新租约**（也就是有一台新主机加入），`handleSubnetEvents` 会做三件事：

![ARP + FDB + 路由：怎么织网](assets/VXLAN%20怎么把包套进%20UDP：overlay%20原理彻底讲透/00188.webp)

| 表 | 记什么 | 类比 |
| :--- | :--- | :--- |
| **ARP 表** | 把那个 Pod **子网的网段 IP**，映射到对端 **VTEP 的 MAC** 上 | 收件人地址 |
| **FDB 表** | 把对端 **VTEP 的公网 IP**，映射到它的 **MAC** 上 | 下游/远端的通道 |
| **路由表** | 让内核知道「去那个子网，下一跳是这个子网的网段 IP」 | 让内核知道该往哪转 |

等主机退出时，就**反着删掉**这三样。

**这三张表一配合**，内核拿到一个目的 IP，就知道该把它**封装成哪一个 VTEP、往哪发**。

## 六、MTU 减 50：一个容易被忽略的坑

最后是一个生产上极易踩的坑——**MTU**。

![MTU 减 50：一个被忽略的坑](assets/VXLAN%20怎么把包套进%20UDP：overlay%20原理彻底讲透/00213.webp)

VXLAN 要**加 50 字节封装**：

- 本来一个 1500 的包，封装完就变成 **1550**；
- 如果**物理网络的 MTU 不够**，就会**触发分片**，性能下降；
- 更糟的是，**UDP 大包可能被中间设备直接丢掉**。

所以**生产上常见的做法**是：

1. 把 Pod（或 `flannel.1`）的 **MTU 减 50**；
2. 或者在配置里**显式指定 MTU 值**；
3. 或者**确认物理网络能承载多大帧**。

**这一步没处理好，VXLAN 网络可能会莫名其妙地慢，甚至断。**

## 小结

- **为什么要 overlay**：跨主机的 Pod 往往不在同一张二层网里，物理网络不帮忙转发，所以要在 IP/UDP 之上再叠一层虚拟网络；VXLAN 是最经典的一种。
- **三个词**：**VNI**（24 位网络标识）、**VTEP**（隧道端点，每台主机一个）、**封装**（原始二层帧 + 外层 UDP/IP）。
- **flannel 怎么建**：`CreateVXLANDevice` 创建 `flannel.1`，它**就是本机 VTEP**；MAC 存进租约，MTU 减 50。
- **一个包怎么走**：出版主机封装 → 跨节点运输 → 入对端解封，**Pod 全程无感**。
- **三张表**：**ARP + FDB + 路由**，合起来让内核知道该封给哪个 VTEP；新租约加，退租约删。
- **MTU 的坑**：封装多 50 字节，1500 → 1550，不处理会分片甚至丢包；生产需把 MTU 减 50 或显式指定。

## 关键术语速查

| 术语 | 一句话解释 |
| :--- | :--- |
| **overlay（覆盖网络）** | 在真实 IP/UDP 网络之上再叠一层虚拟网络，把报文从一台主机送到另一台。 |
| **VXLAN** | 最经典常用的 overlay 实现：把原始二层帧封进 UDP 里跨主机传输。 |
| **VNI** | 24 位网络标识，用来区分不同的 overlay 网络（类比 VLAN ID，但范围大得多）。 |
| **VTEP** | VXLAN 隧道端点，每台宿主机一个，负责封装与解封；flannel 里就是 `flannel.1`。 |
| **封装开销** | 外层 IP(20) + UDP(8) + VXLAN(8) + 外层以太(14) = 50 字节。 |
| **FDB 表** | 转发数据库，记录对端 VTEP 的公网 IP 到其 MAC 的映射。 |
| **MTU** | 最大传输单元；VXLAN 下 Pod 通常要由 1500 减到 1450，避免分片/丢包。 |
