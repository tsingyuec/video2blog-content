# HBM 显存拆解：为什么 GPU 需要数 TB 每秒的带宽

> 视频来源：[HBM 显存为什么这么贵？AI 芯片的另一条命脉，完整拆解！](https://www.bilibili.com/video/BV1CmHi6aEWU/)（Bilibili · 内核聊内核）｜时长约 5.5 分钟
> 简要导读：一支「结论先行」的短片，用三招（堆叠、硅通孔、近封装）解释 HBM 为什么能把带宽做到数 TB/s，并给出 H100 / H200 / B200 / RTX 5090 的实测带宽与容量数字。本文按「为什么需要带宽 → HBM 怎么做到 → 容量与能效 → 为什么贵 → 延迟误区」重排，补足了初学者需要的术语解释。

## 本讲要解决的核心问题（SCQA）

**背景**：大家挑 GPU 时习惯先看核心数、算力（TFLOPS）。训练和推理大模型时，算力确实是最显眼的指标。

**冲突**：可是把数据喂给这些核心的通道——显存带宽——一旦跟不上，核心再多也只能空转。而带宽最高的那种显存（HBM）又贵得离谱，直接推高了整卡价格。

**疑问**：HBM 到底靠什么把带宽做到数 TB 每秒？它和普通显卡上的 GDDR 差在哪里？为什么它这么贵、又为什么消费级显卡不用它？

**回答（中心思想）**：HBM 用「DRAM 裸片垂直堆叠 + 硅通孔垂直连线 + 与 GPU 同封装」三招，把位宽从几百位拉到 1024 位，从而把带宽做到数 TB 每秒；它同时带来更大容量和更低每比特能耗，代价是良率、产能和供应商都稀缺，所以贵。要记住的关键区分是：**HBM 强在吞吐量（带宽），不等于延迟低**。

## 一、AI 芯片的命脉是显存带宽，不是核心数

视频开篇就把结论摆出来：AI 芯片的命脉其实不是核心数，是显存带宽。核心再多，数据喂不上全是白费（[【跳转到 00:00】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=0)）。

为什么偏偏是 AI 负载对带宽这么敏感？视频给了一个非常具体的推理场景：

- 大模型推理时，**每生成一个 token，都要把全部参数从显存里读一遍**；
- 权重是几百 GB 量级，一个 token 读一遍；
- 而服务端每秒要生成几十个 token。

把这三件事串起来，带宽压力就很直观了。可以粗略估一下单个 token 的最短耗时：

$$
t_{\text{token}} \gtrsim \frac{\text{权重字节数}}{\text{显存带宽}}
$$

也就是说，权重越大、带宽越小，每吐一个字就越慢。这正是视频那句「大模型推理的瓶颈往往不是算力，是带宽」的算术来源（[【跳转到 00:50】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=50)）。

![显存的任务有多重：生成一个 token 要读一遍几百 GB 权重，每秒几十个 token，把带宽压力拉满](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00050.webp)

## 二、HBM 靠三招把带宽做上去

视频的答案是「三招」（[【跳转到 00:25】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=25)），而且每一招都在解决同一个问题：**让数据走更宽的路、走更短的距离**。

![结论先行：HBM 的三招——DRAM 裸片盖楼 8-12 层、TSV 垂直连线、与 GPU 毫米级同住](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00025.webp)

1. **堆叠（像盖楼）**：把 DRAM 裸片一层一层堆起来，8~12 层。
2. **硅通孔（TSV）**：在堆叠体上打垂直的通孔，让电流垂直穿过每一层。因为不是从芯片边缘绕出去，接触面积暴增。
3. **近封装**：直接和 GPU 封装在一起，距离以毫米计。

三层加持的结果就是：带宽是 GDDR 的好几倍。

### 2.1 和 GDDR 的根本差别：一个靠频率，一个靠宽度

要理解「为什么堆叠能换来带宽」，得先看两条路线的结构差异（[【跳转到 01:15】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=75)）：

![GDDR7 与 HBM 的结构对比：独立颗粒 512-bit 总线靠频率和通道数，HBM 垂直堆叠 1024 位靠堆叠出宽度](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00075.webp)

| 对比项 | GDDR7（消费卡路线） | HBM（数据中心路线） |
| --- | --- | --- |
| 形态 | 独立颗粒焊在显卡正面 | DRAM 裸片垂直堆叠 8~12 层 |
| 走线 | 又长又窄 | 与 GPU 同封装，毫米级 |
| 位宽 | 512-bit 总线 | 1024 位 |
| 提速手段 | 靠频率和通道数 | 靠堆叠出宽度 |

一个靠把频率和通道数往上顶，一个靠把位宽堆出来——「路线从根上就不一样」。

### 2.2 HBM 是怎么造出来的：四步

![HBM 制造四步：堆叠超薄裸片、TSV 硅通孔、逻辑基底调度、CoWoS 与 GPU 同封装](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00100.webp)

1. 把超薄的 DRAM 裸片一层层堆起来；
2. 打硅通孔（TSV），让电流垂直穿过每层；
3. 垫上逻辑基底，负责读取调度；
4. 用 CoWoS 先进封装和 GPU 装进同一个封装体——「撕不下来」，显存就长在了芯片旁边。

第 4 步是理解 HBM 的关键：显存不再是插在板子上的独立器件，而是和计算芯片共处一个封装。距离以毫米计，才有了后面要讲的能效优势。

## 三、带宽演进：从 H100 到 B200 的实测数字

视频给了一组可以直接记住的带宽数字（[【跳转到 01:40】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=100)）：

![实测带宽对比：H100 HBM3 3.35 TB/s、H200 HBM3E 4.8 TB/s、B200 8 TB/s、RTX 5090 GDDR7 1.792 TB/s](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00125.webp)

| 芯片 | 显存类型 | 带宽 |
| --- | --- | --- |
| H100 | HBM3 | 3.35 TB/s |
| H200 | HBM3E | 4.8 TB/s |
| B200 | HBM3E | 8 TB/s |
| RTX 5090（消费卡） | GDDR7 | 1.792 TB/s |

这张表就是「数据中心卡和消费卡的显存差距」（[【跳转到 02:05】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=125)）：一代 HBM 的升级，往往先把带宽往上抬一档（H100 → H200 是 HBM3 → HBM3E，3.35 → 4.8 TB/s），再往上就是 B200 的 8 TB/s。而消费卡 RTX 5090 用 GDDR7，是 1.792 TB/s。

## 四、容量：显存越大，能装的模型越大

带宽之外，HBM 的第二个卖点是容量。视频用一条清晰的升级线说明（[【跳转到 02:41】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=161)）：

![容量军备竞赛：H100 80GB → H200 141GB → B200 192GB](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00161.webp)

- H100：80GB
- H200：141GB（直接翻上去）
- B200：192GB

「显存容量越大，能装的模型越大，这是数据中心军备竞赛的核心参数。」对初学者来说，这句话的含义是：容量决定了**模型能不能放得下**（放不下就得切分到多卡），带宽决定了**放得下之后跑得多快**。两者是不同的约束，不能互相替代。

## 五、容易被忽略的优点：能效

HBM 的第三个好处不是性能，而是电费（[【跳转到 03:06】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=186)）：

![隐藏优点：距离短（毫米级）、位宽宽（并行搬运）、每比特能耗远低于长走线](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00186.webp)

- **距离短**：毫米级传输；
- **位宽宽**：并行搬运；
- 因此**每比特能耗低**，远低于长距离走线的 GDDR。

视频的落点是：「对数据中心来说，电费是真金白银，能效就是成本。」这解释了为什么数据中心愿意为 HBM 付溢价——省下来的电费是长期的。

## 六、为什么消费卡不用 HBM：一笔算不过来的账

既然 HBM 又快又省电，为什么游戏卡不用？视频的回答只有两个字：成本（[【跳转到 03:31】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=211)）。

「取舍的艺术，产品线就是这么分的。」

那到底谁最渴求 HBM？视频列了三类场景：大模型训练（参数和中间结果都要带宽）、推理服务（每生成一个 token 都要读权重）、科学计算（仿真数据吞吐巨大）。「HBM 就是这些场景的硬通货。」

## 七、为什么这么贵：良率、产能、玩家少

回到标题的问题。视频给了三条原因：

1. **良率**：堆叠八层，坏一层整颗报废；
2. **产能**：CoWoS 先进封装是全行业瓶颈；
3. **玩家少**：全球只有三家供应商，物以稀为贵。

结论是「HBM 的成本大头不在材料，在制造难度」。供应格局上（[【跳转到 03:56】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=236)），全球能造 HBM 的只有 SK 海力士、三星、美光三家，其中海力士目前领跑，大客户排队抢产能是常态。

HBM 自己也在迭代（[【跳转到 04:21】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=261)）：

![HBM 迭代路线：HBM2E 普及 → HBM3 速率跃升 → HBM3E 当前主力 → HBM4 位宽再上探，并支持定制化基底](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00261.webp)

- HBM2E：普及代
- HBM3：速率跃升
- HBM3E：当前主力
- HBM4：位宽再上探，还支持定制化基底，为大客户量身定做

每一代的规律都是：堆叠更高、速率更快、容量更大。

## 八、必须澄清的误区：带宽高不等于延迟低

这是本小节最该记住的一条（[【跳转到 04:48】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=288)）：

![常见误区：HBM 带宽高，延迟也一定低。真相是两个维度——带宽是吞吐量，延迟是一次请求等多久](assets/HBM%20显存拆解：为什么%20GPU%20需要数%20TB%20每秒的带宽/00286.webp)

- **带宽 = 吞吐量**，同时能搬多少；
- **延迟 = 一次请求等多久**；
- **HBM 强在吞吐**；
- 别把两个性能维度混为一谈。

换句话说，HBM 把「同时搬海量数据」这件事做到了极致，但它并没有把「单次访问要等多久」压下来。延迟敏感和带宽敏感是两种不同的场景，需要分开对待——这也正是后面小节要讲 L2/L1 缓存与 Shared Memory 的原因。

## 小结

视频最后的总结（[【跳转到 05:11】](https://www.bilibili.com/video/BV1CmHi6aEWU/?t=311)）可以压成一句话：HBM 靠堆叠、硅通孔、先进封装把带宽做到数 TB 每秒；良率、产能、玩家稀少决定了它贵。

- AI 芯片的命脉是显存带宽：推理每生成一个 token 都要读一遍全部权重，带宽不够，核心再多也白费。
- HBM 靠三招把带宽做上去：DRAM 裸片堆叠 8~12 层、TSV 硅通孔垂直连线、与 GPU 同封装（毫米级距离）。
- 和 GDDR 的根本差别在路线：GDDR 靠频率和通道数（512-bit 总线），HBM 靠堆叠出宽度（1024 位）。
- 带宽演进：H100 3.35 TB/s（HBM3）→ H200 4.8 TB/s（HBM3E）→ B200 8 TB/s；同期消费卡 RTX 5090 是 1.792 TB/s（GDDR7）。
- 容量演进：H100 80GB → H200 141GB → B200 192GB；容量决定「放不放得下」，带宽决定「放得下后跑多快」。
- 第三个优点是能效：距离短、位宽宽，每比特能耗远低于长走线，对数据中心就是电费。
- 贵的原因不在材料，在制造难度：良率（坏一层整颗报废）、产能（CoWoS 瓶颈）、玩家少（全球三家）。
- HBM 带宽高不等于延迟低：带宽是吞吐量，延迟是一次请求等多久，是两个维度。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| HBM（High Bandwidth Memory） | 高带宽显存，把多层 DRAM 裸片垂直堆叠并与 GPU 同封装，用极宽位宽换带宽。 |
| GDDR | 消费级显卡常用的显存，独立颗粒焊在板上，靠频率和通道数提带宽。 |
| TSV（硅通孔） | 在堆叠的裸片上打垂直通孔，让电流直接穿过各层，缩短连线距离。 |
| CoWoS | 台积电的先进封装工艺，把显存和 GPU 装进同一个封装体。 |
| 带宽（Bandwidth） | 单位时间能搬运多少数据，衡量吞吐量，单位如 TB/s。 |
| 延迟（Latency） | 一次访存请求从发出到拿到数据要等多久，和带宽是两个维度。 |
| token | 大模型处理文本的基本单位；自回归推理每生成一个 token 都要读一遍全部权重。 |
| 位宽（Bus Width） | 一次能并行传输多少位数据；HBM 堆叠后可达 1024 位，GDDR7 常见 512-bit 总线。 |
