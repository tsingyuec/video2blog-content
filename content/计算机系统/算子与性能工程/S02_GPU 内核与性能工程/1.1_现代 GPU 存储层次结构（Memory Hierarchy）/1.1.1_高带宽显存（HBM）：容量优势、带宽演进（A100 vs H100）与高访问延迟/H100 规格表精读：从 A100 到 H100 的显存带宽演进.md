# H100 规格表精读：从 A100 到 H100 的显存带宽演进

> 视频来源：[NVIDIA H100 Specs Explained — SXM vs PCIe, VRAM & H100 vs A100](https://www.youtube.com/watch?v=C4Y7sg7XfEM)（YouTube · Luxor Technology）｜时长约 7 分钟
> 简要导读：一支「教你看规格表」的视频：哪些数字真重要、哪些只是营销。本文只挑与本小节相关的部分深挖——HBM3 与 HBM2e 的带宽差、L2 缓存为什么能减少往返 HBM、80GB 容量到底能装多大模型——同时保留原片对 SXM/PCIe、Transformer Engine、MIG 的完整交代。

## 本讲要解决的核心问题（SCQA）

**背景**：H100 的规格表上数字很多，大家最熟悉的是 TFLOPS。

**冲突**：但同一张表上，有些数字决定实际吞吐，有些数字只是营销；更麻烦的是，同一个「H100」名字下，SXM 和 PCIe 两个版本的显存带宽差了 68%，买错了等于买了另一张卡。

**疑问**：H100 相对 A100，显存这一层到底进步在哪里？这些进步怎么换算成「能跑多大的模型、跑多快」？

**回答（中心思想）**：H100 的显存进步是两条腿走路——**带宽从 A100 的 HBM2e 级抬到 HBM3 的 3.35 TB/s（+64%）**，**容量统一到 80GB 并靠 50MB 的 L2 减少往返 HBM 的次数**；对带宽敏感的负载（大多数 LLM 与规模化推理），SXM 版和 PCIe 版完全不在一个量级。

分工上，CUDA Core 负责通用计算，Tensor Core 负责 AI 负载的重活——混合精度的矩阵乘（[【跳转到 00:55】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=55)）。

## 二、被所有人忽略的数字：L2 缓存 50MB

视频说，这张表上「大家都忽略」的数字是 L2 缓存：**H100 是 50MB，A100 是 40MB**。

多出的 10MB 意味着什么？——更多的模型权重和激活值可以**留在片上，而不用往返 HBM**。视频特别强调，对推理来说这是实打实的吞吐提升，而它根本不会出现在 TFLOPS 那个头条数字里（[【跳转到 01:20】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=80)）。

这句话其实点出了存储层次的核心逻辑：HBM 容量大但离得远，L2 容量小但离得近。**能用缓存接住的访问，就不必付 HBM 的代价**。所以看显存不能只看 HBM 的带宽数字，还要看中间那层缓存有多大——这正是本小节之后要展开的 L2/L1 话题。

## 三、SXM 与 PCIe：同名不同命，带宽差 68%

这是全片对「带宽演进」最直接的一段（[【跳转到 01:25】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=85)）：

![H100 SXM 与 PCIe 的实物形态差异：一个是基板上的模块，一个是标准插卡](assets/H100%20规格表精读：从%20A100%20到%20H100%20的显存带宽演进/00085.webp)

两个版本的**容量完全一样，都是 80GB**，但带宽差一大截：

![规格表对照：SXM 用 HBM3 跑 3,350 GB/s，PCIe 用 HBM2e 约 2 TB/s，标注 68% 带宽差距](assets/H100%20规格表精读：从%20A100%20到%20H100%20的显存带宽演进/00120.webp)

| 项目 | H100 SXM | H100 PCIe |
| --- | --- | --- |
| 显存容量 | 80 GB | 80 GB |
| 显存类型 | HBM3 | HBM2e |
| 显存带宽 | 3,350 GB/s | 约 2 TB/s |
| 差距 | — | 带宽差 68% |

视频的结论很硬：「对任何带宽受限的负载——包括大多数大语言模型和大量规模化推理——SXM 完全不在一个级别。」

这段话值得初学者反复读：**同样是 80GB 显存，装得下同样的模型，但跑起来的速度可以差 68%**。容量决定「能不能装」，带宽决定「跑多快」，两者必须分开看。

### 3.1 互联也是带宽：NVLink 与 PCIe Gen5

除了显存带宽，卡间带宽也是「带宽」的一部分（[【跳转到 02:00】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=120)）：

- SXM：NVLink 4.0，GPU 到 GPU 900 GB/s；
- PCIe：PCIe Gen 5，128 GB/s；
- 差距 7 倍。

「在一个节点里做 8 卡分布式训练时，NVLink 是维持扩展效率的关键。没有它，GPU 花在互相等待上的时间比计算还多。」

代价是功耗和基础设施：SXM 最高 700W，需要 HGX 或 DGX 基板；PCIe 是 350W，能塞进标准服务器。如果不需要大规模多卡训练，PCIe 省很多钱和复杂度（[【跳转到 02:25】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=145)）。

## 四、Transformer Engine：换的是「数学」，不只是频率

视频认为，真正把 H100 和之前所有卡区分开的规格是 Transformer Engine（[【跳转到 03:06】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=186)）：

- Tensor Core 上有专门的电路，在训练时**逐层**动态切换 FP8 与 FP16 精度；
- 它逐层判断这一层能否用 8 位数学而不掉精度：能，就跑 FP8、吞吐翻倍；不能，就保持 FP16；
- 所以「比 A100 快 4 倍训练」不只是频率营销，而是在做根本不同的数学；
- A100 根本不能做 FP8，它只有 BF16 或 FP16。

![Transformer Engine 的动态精度切换：FP16 / BF16 / FP8 E4M3 / FP8 E5M2 的符号位、指数位、尾数位划分](assets/H100%20规格表精读：从%20A100%20到%20H100%20的显存带宽演进/00229.webp)

这里要留意一个「星号」：规格表上 3,958 TFLOPS 的 FP8 数字是**带稀疏性**的。生产环境的 Transformer 模型权重很少有 50% 稀疏度，所以现实中应该看稠密数字——大约是这个的一半——作为真实上限。

## 五、容量：80GB 到底能装多大模型

回到显存容量（[【跳转到 04:14】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=254)）：

![H100 的显存规格：VRAM（HBM）80 GB，没有 40GB 版本](assets/H100%20规格表精读：从%20A100%20到%20H100%20的显存带宽演进/00259.webp)

- H100 只有 80GB，没有 40GB 版本；而 A100 同时有 40GB 和 80GB 两种；
- FP16、不做量化：大约能装 300 亿参数模型；
- 4-bit / 8-bit 量化：能跑 700 亿参数模型，比如 Llama 2 70B；
- 想不量化还要更大：要么多卡（NVLink 变得关键），要么上 141GB HBM3 的 H200；
- 对今天大多数生产推理服务，80GB 够用。

这段是「容量优势」最落地的解释：**容量直接决定单卡能装多大的模型，装不下就得切到多卡**。而一旦切多卡，卡间带宽（NVLink）又成了新的瓶颈——于是容量和带宽在这里又交汇了。

### 5.1 MIG：把一张卡切成七份

如果做多租户推理，还有一个规格值得看：MIG（Multi-Instance GPU）（[【跳转到 05:04】](https://www.youtube.com/watch?v=C4Y7sg7XfEM&t=304)）。

- H100 可以被切成 7 个互相隔离的实例，每个实例有自己的显存、缓存和计算核心；
- 这是硬件级隔离，一个租户的负载不会干扰另一个；
- 一张 H100 可以同时服务 7 个轻量推理负载，且有 QoS 保证；
- 对 GPU 即服务（GPU-as-a-service）的生意，这就是把一张贵卡变成多租户营收机器的方式。

## 七、把这张表读成一句话

如果只记一条：**H100 在显存这一层的进步，是「带宽 +64%、容量统一 80GB、L2 从 40MB 涨到 50MB」三件事的组合**。

- 带宽 +64%（HBM2e 级 → HBM3 的 3.35 TB/s）解决「喂不饱」；
- 80GB 统一容量解决「装不下」；
- L2 多出的 10MB 解决「少跑几趟 HBM」。

而这三件事恰好对应本小节要讲的三个维度：带宽、容量、以及用缓存层级去缓解高访问延迟。

## 小结

- H100 规格表上的数字分三类：很重要、有点重要、基本是营销；显存相关的属于第一类。
- L2 缓存 50MB（A100 是 40MB）是被忽略的关键数字：更多权重和激活留在片上，不必往返 HBM。
- 同为 80GB，SXM 用 HBM3 跑 3,350 GB/s，PCIe 用 HBM2e 约 2 TB/s，带宽差 68%；带宽受限的负载（大多数 LLM）上两者不在一个级别。
- 卡间带宽同样重要：SXM 的 NVLink 4.0 是 900 GB/s，PCIe Gen5 是 128 GB/s，差 7 倍。
- 容量决定能装多大模型：FP16 约 300 亿参数，4/8-bit 量化可跑 700 亿参数（如 Llama 2 70B）；再大就上多卡或 H200 的 141GB。
- H100 相对 A100：显存带宽 +64%、NVLink +50%、FP16 Tensor 超过 3 倍；Transformer 负载实测训练 3~4 倍、推理 2~4 倍。
- MIG 可以把一张 H100 切成 7 个硬件隔离实例，适合多租户推理。

## 关键术语速查

| 术语 | 一句话解释 |
| --- | --- |
| HBM3 / HBM2e | 高带宽显存的两代标准；HBM3 速率更高，H100 SXM 用它跑到 3.35 TB/s。 |
| SXM / PCIe | 同一款 GPU 的两种形态：SXM 是基板模块（高功耗高带宽），PCIe 是标准插卡（通用但带宽低）。 |
| L2 缓存 | GPU 上所有 SM 共享的片上缓存，接住重复访问、减少往返 HBM。 |
| NVLink | Nvidia 的 GPU 间高速互联，SXM 版 H100 达 900 GB/s。 |
| Transformer Engine | H100 Tensor Core 上逐层动态切换 FP8/FP16 的电路，用更低精度换更高吞吐。 |
| 稀疏性（Sparsity） | 规格表上 TFLOPS 数字的「星号」：带 50% 稀疏才有那个峰值，稠密模型要打折。 |
| MIG | Multi-Instance GPU，把一张卡切成多个硬件隔离的实例。 |
| 量化 | 用 4-bit / 8-bit 等更低精度存权重，用精度换容量，让 70B 模型塞进 80GB。 |
