# S07 存储引擎与快照

编号：S07 · 类型：系统专题 · 目录规模：37 个小节（三级叶子节点）。

> 本文件是 `content-new` 的完整目录草案。状态统一为 `[WAITING]`，待 Phase 2 映射 video2blog 博客后更新。

## 脉络章程

**知识主线**：从文件系统的数据布局出发，先学 reflink 与 `FICLONE` 这套“extent 级共享”的快照原语，再把它与 OverlayFS 的“文件级 copy-up”放在一起对照，理解两种 CoW 的性能模型差异；然后转向存储后端——对象存储的 S3 语义、分布式文件系统的元数据/数据分离与 FUSE 路径；最后落到“快照怎么持久化、怎么跨机传、后端怎么插件化”。

**一句话范围**：只讲**存储实现层**——数据在磁盘/对象存储上怎么布局、怎么共享、怎么复制。**接口契约归 S04**（PV/PVC/StorageClass/CSI/Volume 语义），**容器卷的使用语义归 S03 第 4 章**（匿名卷/命名卷/绑定挂载/传播），**VM 内存侧的脏页追踪与快照组成归 S06 第 5 章**，本系列只讲落盘与传输那一半。

**学习入口 → 学习出口**：文件系统与 inode 基础（可复用 S03 1.2）、OverlayFS 与镜像分层（可复用 S03 3.3）、PV/PVC/CSI 抽象（可复用 S04 第 6 章） → 能解释 `FICLONE` 为什么是 O(1)、能说清 reflink 与 copy-up 在什么场景下性能差几个数量级、能读懂一个卷插件在本地 reflink / 对象存储 / 分布式文件系统三种后端上的实现差异，能拆解一次跨机快照恢复的时延构成。

**完整问题链**：
1. 文件系统与快照原语：为什么有些文件系统能做到“零拷贝快照”，有些不能？
2. 写时复制的两种实现：文件级 copy-up 和 extent 级 reflink，差在哪、什么时候该用哪个？
3. 对象存储与 S3 语义：把块设备搬到对象存储上，会丢掉哪些语义？
4. 分布式文件系统：数据存对象存储、元数据存数据库，这种拆分带来什么、代价是什么？
5. 快照的持久化与跨机传输：一次跨节点恢复，时间花在哪几段？

**与相邻脉络的关系**：上游是 S03 1.2（文件系统与挂载）与 S03 3.3（联合文件系统、存储驱动），本系列把 3.3 里“CoW”这一条线单独抽出来做深；与 S04 第 6 章是**抽象层与实现层**的关系（S04 讲 CSI 契约，本系列讲 CSI 后端怎么写）；与 S06 是**内存侧与磁盘侧**的分工（S06 5.1 讲快照由哪几部分组成，本系列 5.1 讲这些部分怎么落盘）。
