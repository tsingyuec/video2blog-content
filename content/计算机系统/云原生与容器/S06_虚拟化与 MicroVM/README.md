# S06 虚拟化与 MicroVM

编号：S06 · 类型：系统专题 · 目录规模：66 个小节（三级叶子节点）。

> 本文件是 `content-new` 的完整目录草案。状态统一为 `[WAITING]`，待 Phase 2 映射 video2blog 博客后更新。

## 脉络章程

**知识主线**：从“内核共享 vs 内核独立”这条隔离边界出发，先学 KVM 暴露给用户态的接口模型与 vCPU 运行循环，再学内存虚拟化（EPT、内存区域、页级 CoW）与设备模型（virtio、virtqueue、vhost），接着学宿主与沙箱之间的通信通道（vsock、virtio-fs），然后学 VM 状态管理（快照、恢复、迁移）——这是“毫秒级启动”的实现处，最后横向对比 Firecracker / Cloud Hypervisor / Kata / gVisor 的取舍，并落到嵌套虚拟化与硬件隔离边界。

**一句话范围**：只讲“独立内核”这条隔离路径的机制与实现；进程级隔离（namespace/cgroup/capability/seccomp）归 S03，容器运行时契约（OCI/runc/CRI/shim v2 接口）归 S03，reflink 与对象存储归 S07，L7 代理归 S05。**shim v2 的接口定义在 S03，用 shim v2 启动 MicroVM 的实现在本系列。**

**学习入口 → 学习出口**：Linux 进程/内存/文件系统基础（可复用 S03 第 1 章）、容器运行时链路（可复用 S03 第 5 章） → 能解释一台 MicroVM 从 `create_vm` 到 `restore_vm` 走了哪些内核接口，能读懂 virtio 设备的队列与中断路径，能说清 VM 快照由哪几部分组成、为什么恢复能在百毫秒内完成，能判断 Firecracker / Cloud Hypervisor / Kata / gVisor 各自的适用场景。

**完整问题链**：
1. 虚拟化基础与 KVM：用户态怎么通过 `/dev/kvm` 驱动一颗 vCPU？
2. 内存虚拟化与 CoW：客户机物理地址怎么变成宿主物理地址？内存为什么能不复制就共享？
3. 设备模型与 virtio：一台只有最小设备的虚拟机，磁盘和网卡怎么工作？
4. 宿主与沙箱通信：没有共享网络栈时，宿主怎么在沙箱里执行命令、读写文件？
5. VM 状态管理与快照：怎样把“正在运行的整台机器”冻结成一个可复制的文件？
6. MicroVM 运行时对比：为什么 Firecracker 能 100ms 起机，而 QEMU 要几秒？
7. 嵌套虚拟化与 PVM：在云服务器里再跑 KVM，代价与边界在哪？

**与相邻脉络的关系**：与 S03 是**并列的两种隔离后端**（S03 内核共享、本系列内核独立），无学习先后依赖，但共享 S03 第 1 章的 Linux 基础；`3.3.3 写时复制机制`（内存 CoW）从 S03 迁入本系列 2.3；VM 快照的持久化格式与跨机传输归 S07；VM 的 L7 出网代理归 S05。
