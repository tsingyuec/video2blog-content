知识脉络设计准则
================

管三件事：一条脉络该不该拆、一个知识点该放节还是小节、别处的博客能不能复用。
不涉及写作规范（在 video2blog skill）与调度规则（在 AGENTS.md）。


一、五条判据
------------

判据的作用是在争议时给出唯一答案，不是描述性分类。

J1 依赖链      学 A 是不是学 B 的前提？        是→同系列；并列→不同系列
J2 问题域      这个节回答哪一个问题？          一个节只回答一个；两个问题硬拼=该拆
J3 抽象vs实现  讲接口契约还是后端实现？        契约归抽象层系列，实现归实现层系列
J4 契约vs实现  同一名词讲的是接口还是落地？    接口留原系列，落地归实现系列
J5 转发vs代理  只看五元组改地址，还是看 L7？   前者归数据面，后者归代理层

J1 最硬。它同时决定"该不该开新系列"和"该不该合并"。
  namespace → netns → veth 有硬依赖，必须同系列。
  namespace → KVM 没有依赖（学完 namespace 不会让你更懂 vCPU 循环），必须不同系列。
  把并列关系塞进同一系列，等于向读者暗示一条不存在的进阶路径。

J4 允许一个组件被切成两半，这不是重复：
  containerd shim：shim v2 接口定义归运行时系列，用 shim v2 启动 MicroVM 归虚拟化系列。
  CRI PodSandbox：接口与语义归运行时系列，Kata 的 VM sandbox 落地归虚拟化系列。
  判据：读者不需要跨系列就能理解接口，需要跨系列才能理解落地。


二、粒度：节还是小节
--------------------

节 = 一个问题域。读完这一节应能回答一个完整问题（"包怎么走""内存怎么翻译地址"）。
小节 = 该问题域下一个可独立成篇、可独立验收的知识点，通常 1–3 篇博客。

该升格为「节」的信号（任一成立）：
  1. 能自然拆出 ≥3 个互不重叠的子问题。
     反例：TPROXY 和 TLS MITM 各列一个小节——它们是同一机制的部件，合起来
     （透明拦截链路/中间人/策略匹配/凭证注入/审计）才是一个完整问题域。
  2. 和同级其他小节不在同一个问题域里。
     反例：Helm 与 DaemonSet 交付形态塞进「服务发现与入口」。
  3. 单独成小节时学习目标写不出"能做什么"。
     反例：vsock 单独一节只能写"说明 vsock 是什么"；放进「宿主与沙箱通信」节
     才能写"说明宿主如何通过 vsock 在沙箱内执行命令"。

该降格为「小节」的信号：
  1. 和同节其他小节共享同一套前置，单独讲会重复铺垫。
  2. 学习目标能被同节另一个小节完整覆盖。

节内小节数：3–5 健康；2 偏薄，查是否该合并；6–8 偏胖，查是否藏着两个问题域；>8 几乎
一定是两节被压成一节；1 不是节，是章。
实测：S03 105/24≈4.4，S04 67/18≈3.7，S06 66/22=3.0。

小节之间不许重叠。两个小节的学习目标若能互相覆盖就是重复，必须合并或划清边界。


三、边界：开新系列还是加新节
----------------------------

  和现有系列有硬依赖（不学 A 就不懂 B） → 加进 A 所在的系列
  并列（学不学 A 都不影响 B）             → 开新系列
  同一组件的接口/实现两个侧面             → 按 J4 切开，各归其位

「并列」必须开新系列，不能加新节。理由不是篇幅，是语义：加新节等于宣称"这是本系列的
下一步"，而并列关系没有下一步。

实测（计算机系统/云原生与容器）：
  虚拟化/MicroVM        与 namespace/cgroup 并列的另一种隔离后端（内核独立 vs 内核共享）
                        → 开 S06，不做 S03 第 7 章
  reflink/对象存储      与 OverlayFS 并列的另一种 CoW 实现（extent 级 vs 文件级）
                        → 开 S07，不做 S03 3.3 的子节
  L7 代理与出网控制     与数据面转发同属"包怎么走"，且依赖 6.2/6.3
                        → 可做 S05 的一个节，不必新系列

编号：一旦分配不再复用。允许留空号，但必须在分组 README 里写明"规划中 + 迁移范围"，
否则读者会以为漏了。

系列规模：<15 太薄，考虑并入相邻系列；15–90 健康；>100 该拆——通常是多个问题域被
"主题名"硬捆在一起（S03 的 6 个章分别回答 6 个不同问题，靠"容器"二字捆起来）。


四、复用（REUSE）
-----------------

状态机：WAITING → PROCESSING → DONE / REUSE / ABORT。

REUSE 是终态，与 DONE 并列，不是内容类型。含义是：该小节由另一脉络的已 DONE 小节
满足，本脉络不另建正文。它计入小节规模，不参与认领，不再流转；可在编排时直接标记，
不必经过 PROCESSING。

写法是行尾指向源小节 README 的锚点：

  - 1.1.1 抗原、表位与旁位 <a id="d07-1-1-1"></a> [REUSE](../../生命科学基础/B05_免疫与抗体生物学基础/README.md#b05-1-2-1)

并在 README 头部注明"自有 N 个 / 复用 M 个"。

可以复用的四个条件，全部满足才算：
  1. 知识点同一，不是"相似"或"相关"。
  2. 学习目标可以逐字复用，不需要为接收方改写。
  3. 源小节已 [DONE]，否则复用方指向空壳。
  4. 接收方不需要额外前置。

不能复用的情况（都是实测踩过的）：
  机制对、载体不对    企业防火墙的 NAT 回流 ↔ Docker 的 NAT 回流：机制一样，但全文是
                      eNSP + 华为防火墙，读者要先翻译一遍设备模型
  层次不同            netfilter 钩子 ↔ DMA/NAPI/ring buffer：都叫"包处理路径"，但一个
                      在 netfilter 层、一个在驱动与协议栈层。互补的该各自成篇
  已被覆盖            多篇 veth/端口映射博客：接收方已有更贴主题的版本
  只是顺带提及        表格里出现一次 "Kubernetes"/"Helm"
  排障/工具方法论     tcpdump、traceroute：接收方章程若排除排障，反向搬入会破坏边界
  子串误匹配          MIG↔migrate、FUSE↔diffused、TLS↔adults

检索规则：按接收方的缺口列关键词（不是按源方目录名）；全库 grep 后逐条打开确认，不许
只看命中数；实测 30 个关键词里绝大多数命中都是子串误匹配。找不到就写"没有"，不许为了
显得有产出而强行说合适。


五、覆盖度评估
--------------

判断"一条脉络够不够支撑某个项目"：

  1. 拆目标：按目标项目的架构文档与目录结构拆组件，不看 README 宣传语。
  2. 列前置：每个组件列出"读懂它需要什么"，粒度到机制名（FICLONE、virtqueue、TPROXY），
     不是到学科名。
  3. 逐项对表：现有脉络的节级标题能不能对上。对不上就是缺口，不用"相关"糊过去。
  4. 给比例并指认：明确说哪几块够、哪几块不够、不够的在哪。

反模式：按组件名对表（会漏掉"内存 CoW"这种藏在别处的必要前置）；用"概念可迁移"充数
（S04 的 apiserver 请求流水线不能算覆盖了 CubeAPI 的 Rust/Axum 实现）；只报缺口不报比例。

缺口三档：够（节级标题能直接对上且有博客）/ 概念够实现缺（有同名概念但缺工程细节，
在现有节内加小节）/ 缺口（节级都对不上，开新系列或新节）。


六、体检：四类错位
------------------

  重复    两个小节的学习目标互相覆盖
          S03 3.3.5 ↔ 4.3.1；S03 1.5.2/1.5.3 ↔ 2.2.8
  错位    内容与所在节的问题域不符
          S03 3.3.3 讲的是内存 CoW（fork/页表），却放在「文件系统与写时复制」节下
  硬拼    一个章的标题里有两个不相干的名词
          S04 第 6 章「存储抽象与准入策略」
  残留    目录或锚点残留
          S04 下多出一个「5_服务、入口与现代集群数据面」目录，与同级 5.1_/5.2_/5.3_ 重复；
          S03 的 README 混入 <a id="s04-3"></a>


七、一页速查
------------

  该拆成新系列吗？   和现有系列有硬依赖吗？没有 → 新系列
  该升格成节吗？     能拆出 ≥3 个独立子问题吗？能 → 是节
  该降格成小节吗？   学习目标被邻节覆盖了吗？是 → 降格
  能复用吗？         知识点同一 + 目标可逐字复用 + 源已 DONE + 不需额外前置
  找不到复用怎么办？ 写"没有"。不许强行凑
